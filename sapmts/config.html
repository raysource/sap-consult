配置前的准备

配置作业会在你的练习系统留下自建对象。开始前确认三件事：① 有可写入的カスタマイジング依頼（Customizing Request）； ② 用户能进入 SPRO（SPRO → 「カスタマイジング」→「IMG」）；③ 练习用的 販売組織/プラント/得意先/番号範囲 都可用。

效率技巧 SPRO 的菜单层级很深，直接用 T-code 跳转比对菜单 3 层点击快：VOV4・VOV5・VOV6・VOV7・OVZG・OVZI・OPPT・OPPS・OVZ9・OMDU 全部可以直呼。 本站每个 STEP 同时给出「T-code」与「IMGパス（日本語）」，照任一条走进同一个画面。

C1

部品品目（ZMTS-RM01 / ZMTS-RM02）

MM01 / MM02
目的
让完成品有可出库的部品（BOM コンポーネント）。本教程为了让流程聚焦在見込生産，部品用初期在庫应付需求（部品不跑采购），購買流程留作发展课题（练习⑤）。

目的

C3

BOM・作業区・作業手順（標準原価の入力でもある）

CS01 / CR01 / CA01 / C223
目的
① 让 MRP 能做 BOM 展開（部品的従属所要量）；② 让 CK11N 能算出标准成本（部品＋工数）；③ 让 CO11N 有可实绩的工序。
IMGパス（日本語）
マスタデータなので T-code 中心。作業区の標準値パラメータは IMG：生産 > 基本設定 > 作業区 > 一般データ（OPAL 系）。本练习用标准默认即可，不改。

C4

標準原価の計算・マーク・リリース（CK11N → CK40N → CK24）

CK11N・CK40N・CK24・OKKN・KP26
目的
给完成品一个標準価格（例 8,000 JPY）。MTS 是「先造后卖」，库存必须以标准价评价，否则月末无法算差异——这一步做不了，练习⑤ 就只能看个热闹。
IMGパス（日本語）
IMG：管理会計 > 製品原価管理 > 製品コストの計画 > 標準原価計算 > 原価計算バリアントの定義（OKKN）。 作業区のレートは IMG：管理会計 > 管理会計転送 > 活動タイプのレート割当（KP26 で年度レートを直接入力）。

输入值 / 手順の前提

価格管理  S（標準価格）      ← 品目 会計1
標準価格  8,000 JPY / PC     ← CK11N → CK24（リリース）後に見える値
原価計算バリアント  標準 PP 用（例 PP01 系）
原価計算ロットサイズ  EX（ロット単位）
計算の内訳（イメージ）  部品費 RM01 2×1,000 + RM02 4×500 = 4,000
                       ＋ 作業費 1 H × 3,000 = 3,000
                       ＋ 間接費/管理費など = 1,000  → 合計 8,000 JPY
  1. KP26（或 IMG のレート割当）→ 原価センタ / 活動タイプ（例 LAB01）/ 年度 → レート（例 3,000 JPY/H）を入れる。これが無いと CK11N の作業費が 0。
  2. CK11N → 品目 ZMTS-FG01 / プラント 1000 / 日付（当日）→ 原価計算バリアント（例 PP01 系）→ 実行。結果の項目明细（コストコンポーネント）を確認：部品費・作業費・間接費。
  3. 結果を保存（成本估算版本が作られる）。必要なら明細の警告（レート無し・工程無し）を潰して再実行。
  4. CK40N（一括）を使う場合：選択 → 実行（構造展開 → 原価計算 → マーク → リリース）の 4 段階を順に。「マーク」で来期、「リリース」で今期の標準価格になる。
  5. CK24 → 品目 ZMTS-FG01 / 会計期間 → マーク（Mark） → 続けてリリース（Release）。

表で見るなら SE16N: MBEW（キー MATNR/WERKS/BWTAR=標準価格）→ STPRS・PEINH・VPRSV（価格管理）。
つまずき ① リリースを忘れた（マークだけ）→ 品目会計1 に標準価格が出ず、指図の目標原価が「標準価格なし」になる。
② レート（KP26）が当期に無い → 作業費 0 の標準原価（例 5,000 JPY）が計算され、差異が全額「作業関連」に化ける。
③ 品目に原価計算バリアント/ロットサイズ未設定 → CK11N でエラー。F1 で必要項目を確認。
④ 期中のリリースは在库存评价会重估——练习系统里做，不要在实训外的系统试。

C13

在庫確認（ATP）の設定——MTS の「売れる量」を決める

OVZ9・CO09・MDVP・V_V2
目的
把「库存够不够」这件事做成受注时的自动判定：受注保存 → 納入日程行の在庫確認 ON → 品目 MRP3 のチェックルール → チェックグループ × チェックルール（スコープオブチェック）→ 使用可能数量。MTS 的关键是「检查对象要包含入庫予定与出庫予定」，否则只能看现有库存。
IMGパス（日本語）
IMG：販売管理 > 基本機能 > 在庫確認と所要量転送 > 在庫確認 > 在庫確認の定義（OVZ2：チェックグループ × チェックルール）/ 利用可能在庫確認制御（OVZ9：チェックルールごとのスコープオブチェック = 在庫/入庫予定/出庫予定/個別所要量/予約 の選択）。
T-code と画面名はバージョンで表記が異なるので、SPRO の検索窓で「在庫確認」を検索して自分の画面を確認する。

設定の 3 層（全部そろって初めて ATP が動く）

[1] 品目 MRP3 の「在庫確認」フィールド = チェックルール（例 02。値の意味は F1 で確認）
[2] 納入日程行カテゴリ（例 CP）の「在庫確認」ON + チェックグループ
[3] スコープオブチェック（OVZ9）：何を見るか
      在庫（自由在庫）      …… MTS は最低これ
      入庫予定（製造指図/計画手配/購買発注） …… 予測で作った分を「将来の可用量」に含める
      出庫予定（他の受注・出荷）               …… 先に受注した客が優先される根拠
      個別所要量（受注在庫）  …… MTO で必須。MTS では通常 OFF
  1. MM02 → ZMTS-FG01 → MRP3 → 「在庫確認」にチェックルール（例 02）を入れ、F1 で「何をチェックするか」の説明を読む。
  2. OVZ9 → そのチェックルール（02）→ スコープオブチェック（在庫 / 入庫予定 / 出庫予定 / 個別所要量 / 予約）の組合せを确认。見込生産では「在庫 + 入庫予定 + 出庫予定」が典型。
  3. （チェックグループ）OVZ2 → 得意先のチェックグループ（得意先マスタの一般データ/販売エリアに設定）とチェックルールの組合せに行がある事を确认。
  4. 入庫予定を ATP に含めるには、対象ドキュメント（製造指図・計画手配・購買発注）が入庫予定として認識されている必要がある——CO09 の要素一覧に計画手配/製造指図が並ぶかで判定する。
確認（自システムでの確認方法） CO09（品目 + プラント + 確認日）→ 「利用可能数量」と要素一覧（入庫/出庫の内訳）。
批量は MDVP（集団在庫確認）。納期再設定・バックオーダー処理は V_V2。
受注側の結果は VA03 → 明細 → 納入日程行 の「確認済数量」、表は VBEP（納入日程行）と VBBS（引当/所要）。
つまずき ① チェックルールの番号を暗記している：01/02/… の意味は環境で異なる。MM03 の F1 と OVZ9 のスコープで確認する。
② スコープに「入庫予定」が入っていない → MTS で先造りした完成品が受注時に見えず、「在庫があるのに欠品扱い」になる。
③ 品目 MRP3 の在庫確認が空 → ATP が動かず、受注は常に「未確定」または「即納 OK」のどちらかに偏る。
④ 得意先のチェックグループ不一致 → OVZ2 に組合せが無いとエラー。
練習課題CO09 で ZMTS-FG01 を開き、練習③ の入庫（101）前と後で「利用可能数量」がどう変わるかを記録する。さらに受注を入れた後で V_V2 を実行し、納期とバックオーダーの動きを見る（练习④）。

MRP 側の設定と実行（MD01N・OMDU・PP01・CO40/CO41）

目的
把「预测 → 补货」接起来：明确 MRP Live 的参数、指图类型的默认值、以及计划手配到制造指图的转换路径。
IMGパス（日本語）
