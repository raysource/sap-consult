讲师版：解答・採点ポイント・進め方

このページの扱い 受講者には配布しない（或は「解答編」として最後に配布）。学员版（worksheet.html）は記入用、こちらは答えと進行の説明です。 研修の成否は「受講者に自分で T-code を打たせたか」でほぼ決まります——講師が画面を写して説明するだけの研修は、差分（版本・業界ソリューション）で必ず破綻します。

2. 事前準備チェック（講師・前日までに）

#準備項目確認方法
1受講者用のユーザと権限（SPRO 表示・MM01/02・MD61・MD01N・CO01/02/11N/40/41・MIGO・VA01・VL01N/02N・VF01・CK11N/KKS1/KO88）各ユーザで 1 回ずつログインして実行
2練習用の品目（ZMTS-FG01/RM01/RM02）が作成済みで、MRP ビュー・標準価格（8,000 JPY）がリリース済みMM03 会計1・MRP1〜4 で確認
3戦略グループ 40 と消費モード 2 が品目に入っているMM03 MRP3（MARC-STRGR）
4BOM・作業区・工程が有効（有効日が当日を含む）CS03・CA03
5部品の初期在庫（RM01 1,000 / RM02 2,000 PC）MMBE
6得意先 1000 の販売エリア + 出荷先、条件レコード PR00BP/XD03・VK13
7会計期間が開いている（差異計算と決済ができないと練習⑤ が止まる）OB52・KKS2 のテスト実行
8カスタマイジング依頼（受講者が VOV4/VOV5 に自建行を入れる場合）練習用システムの登録権限
9当日の「基準値」を書いた紙：標準価格・安全在庫・PIR 数量・消費モード受講者全員に配布（自システムの値で上書きさせる）

4. 配置の解答と採点ポイント（C0〜C16）

採点の原則：「自システムで確認できたか」を評価する。「教科书の值を暗記したか」は評価しない。値が違う場合は「なぜ違うか」を説明できれば満点。

STEP解答の要点（期待値）採点ポイント
C0販売エリア 1000/10/00・プラント 1000・得意先 1000（出荷先あり）・番号範囲に空き前提の確認漏れを「練習中の事故」として記録できているか
C1部品 RM01（ROH）/RM02（HAWA）、MRPタイプ PD・手配タイプ F、初期在庫 1,000 / 2,000 PC部品に戦略グループを付けない理由を言えるか
C2MRP1 PD/EX/手配タイプ E、MRP2 安全在庫 100、MRP3 戦略 40/消費モード 2、MRP4 個別・包括所要量 空、販売組織2 品目カテゴリグループ 0001MRP4 が空である理由（自由在庫の維持＝MTS の成立条件）を説明できるか。ここが本研修の最重要採点項目
C3BOM RM01×2 / RM02×4、作業区 ZMTS_WC01、工程 0010・1 H/PC、有効日BOM と工程が標準原価の入力でもあることを結びつけられるか
C4CK11N → CK24 で標準価格 8,000 JPY、価格管理 S、レート（KP26）設定済みマークとリリースの違い、レート未設定時に何が起きるかを言えるか
C5条件レコード PR00 = 8,000 JPY、品目カテゴリグループ 0001（NORM）「見込生産専用の標準グループは無い」ことを理解しているか
C6TAN の特別在庫欄が空、納入日程行許可 ONMTO の ZTAK（特在 E）との対比で説明できるか
C7VOV4：OR + 0001 + 空 + 空 → TAN（4 键）「空値もキー」だと理解しているか（不要な値を入れない）
C8CP：所要量転送 ON・在庫確認 ON・移動タイプ 601OFF にしたときに何が壊れるか（MD04 に出ない / 引当不能）を言えるか
C9VOV5：TAN + PD → CP（2 键）品目に MRP ビューが無い場合との差を説明できるか
C10OVZG：100/030/050 に個別在庫なし、040（MTO）にあり「個別在庫フラグが形态を分ける」ことを理解しているか
C11戦略 40：独立 VSF / 得意先 KSV（→ クラス 050）。決定順は戦略グループ優先環境差を許容できるか（自分の値で読み替えられるか）
C12OPPT：40 = 最終組立ありの計画、10 = 見込生産（消費なし）、11 = 総所要量計画、70 = 組立レベルネットの誤情報（40 と 30 の取り違え）に引っかからず、自システムの記述を根拠にできるか
C13品目 MRP3 の在庫確認、OVZ9 のスコープ（在庫＋入庫予定＋出庫予定）、CO09 で検証「見込生産は入庫予定も可用量に入れる」ことを説明できるか
C14MD01N で計画手配、OMDU のパラメータ、OPJH/OPL8 で PP01、CO40/CO41 変換MRP リストが無い理由（MRP Live）を言えるか
C15LF/F2、PGI 601、OBYC の BSX/GBB、棚卸 MI01/04/07在庫金額が標準価格ベースで計上されることを説明できるか
C16Cloud：明細カテゴリ・販売伝票タイプの新規作成不可、スコープアイテム BJ5、SSCUI 105120断言できないものは「要確認」と書けるか（＝根拠意識があるか）
採点の配分（100 点満点の例） C2（品目主数据）20 点 / C6〜C9（SD 側 3 決定）20 点 / C10〜C12（所要量クラス・タイプ・戦略）20 点 / C13〜C15（ATP・MRP・出荷請求）20 点 / C0・C1・C3・C4・C16（前提・原価・Cloud）20 点。
減点ポイント：値の丸暗記（根拠が言えない）・確認手顺を飛ばした・エラーを「なんとなく直した」。

5. 練習の解答（期待値の要点）

練習期待値（システムの状態）よくある誤答・指導ポイント
① 需要予測と PIR版 00 に 3 か月分 × 500 PC。MD04 に「計画独立所要量（受注番号なし）」が並ぶ。利用可能数量はマイナス「PIR は受注が出たら減る」と思い込む → 消費と消減を分けて説明（PBED は変わらない）
② MRP と計画手配MD01N 後、計画手配（例 600 PC = 500 + 安全在庫 100）。部品に従属所要量 1,000 / 2,000 PC。CO40/CO41 で PP01 の指図に変換純所要量の検算をしない → 必ず手計算させる。「MRP リストが無い」で詰まる → MD04 に誘導
③ 製造と入庫CO02 解放 → 261（RM01 1,000 / RM02 2,000）→ CO11N 歩留 500 → 101 で自由在庫 +500・特在空、状態 DLV、会計伝票は標準価格ベース入庫が受注在庫に入る（MTO 化）→ MRP4 と AFPO-KDAUF を見せる。「特在区分が空」が MTS の証拠と強調
④ 受注・引当・出荷・請求受注 200 PC（TAN/CP）、CO09 で 500 → 300、MD04 で PIR 消費済 200（PBED は 500 のまま）、PGI 601 で自由在庫 300、請求 1,600,000 JPY、伝票フロー闭合「PIR が減っていない＝消費されていない」誤解 → MD04 の消費済数量を見せる。在庫の取り合い（引当順）を事例で説明
⑤ 月末と発展KKS2/KKS1 で差異（カテゴリ別）、KO88/CO88 で決済 → FB03。棚卸 1 回。故障対照表の 3 項以上を説明差異を「異常」と捉える → 差異は正常、額と原因が問題と伝える。差異カテゴリの番号を暗記させない

6. 必出質問 Q&A（模範回答つき）

#質問模範回答（要点）
1MTS と MTO の違いを一言で需給の起点が予測か受注か、在庫が誰のものか。MTS＝予測（PIR）起点で自由在庫、MTO＝受注起点で受注在庫（特在 E）。（概念 1）
2なぜ MTS の MRP4「個別/包括所要量」は空なのか空＝受注に紐づけない＝入库が自由在庫に入る。ここを「個別所要量のみ」にすると受注在庫 E に変わり、形態が MTO になる。
3戦略 40 と 10 はどちらが「受注で予測が減る」か40 が減る（消費）。10 は消費しない（受注は情報表示のみ、入库時に古い PIR から消減）。11 も消費しない上に在庫を見ない（総所要量計画）。
4戦略 30 と 40 の違いは？標準の説明では 30 = ロット生産（Production by lot size）、40 = 最終組立ありの計画（Planning with final assembly）。40 は独立 VSF／得意先 KSV、30 は独立 LSF／得意先 KL。必ず OPPT の自分の記述で確認。
5消費と消減の違いは？消費＝MD04 上で PIR が食べられる（PBED は不変）。消減＝PBED の数量自体が減る（入库・発注の完結時など）。確認は MD04 と PBED の比較。
6PIR を入れたのに MRP が動かない確認 3 点：① 版が 00 か（T459U）② MRP タイプが ND でないか ③ 手配タイプが入っているか。→ 故障対照表 #2
7受注したのに MD04 に需要が出ない納入日程行カテゴリの所要量転送（VBEP-BEDSD）と、品目 MRP ビューの有無。VOV5/VOV6 と VA03 で確認。
8在庫があるのに出荷できない① 在庫タイプ（品質検査/ブロック）② 保管場所違い ③ 先行受注が引当済み ④ ピッキング未入力。確認は MMBE → CO09 → VL03N の順。
9差異は誰の責任か差異は原因が複数（部品価格・用量・工時・スクラップ・設定）。差異カテゴリを見て初めて「購買/生産/原価設定」に割り振れる。差異計算→決済は CO だが、原因は SD/PP/MM/購買に散っている。
10MRP リスト（MD05/MD06）はどこ？MRP Live（MD01N）は MRP リストを作らない。MD04 を見る（SAP KBA 2640393）。古典 MRP との差異の代表例。
11Public Cloud でも同じ手顺が使える？使えない部分がある。明細カテゴリ・販売伝票タイプの新規作成は不可、設定は SSCUI、操作は Fiori。スコープアイテム（BJ5 など）の提供範囲を先に確認する（C16）。
12安全在庫を守るために出荷を止めるべき？いいえ。安全在庫はMRP の補貨トリガであり、出荷可否を決めるルールではない。出荷可否は受注の引当と納期で判断する（欠品は「見せる」が原則）。
13標準価格が無いと何が起きる？入库が評価できず（金額 0/エラー）、差異計算もできない（目標原価が無い）。CK11N→CK24 が前提（C4）。
14見込生産で一番お金がかかる失敗は？予測過多による滞留在庫（維持費＋評価減）と、予測不足による欠品（売上逸失＋緊急対応コスト）。どちらも「予測＋計画パラメータ（安全在庫・ロットサイズ）」の設計問題。

7. 故障の教え方（切り分けの物語）

3 層モデル（これを板書してから故障表を配る） 第 1 層：品目マスタ（MRP1〜4。特に戦略グループ・個別/包括所要量）
第 2 層：SD 側の 3 つの決定（VOV4 明細カテゴリ → VOV5 納入日程行カテゴリ → VOV6 所要量転送/在庫確認）
第 3 層：実行結果（MD04 に何が出るか / CO09 の可用量 / MMBE の在庫区分）
教え方：症状を読み上げ → 受講者に「第 1 層か第 2 層か第 3 層か」を当てさせる → 当たった層の中で T-code を挙げさせる。
やってはいけない：講師が先に答えの T-code を言う（受講者は手顺を覚えるだけで、切り分けを覚えない）。
練習問題（受講者用）正解の層根拠
MD04 に受注が出ない第 2 層所要量転送（VBEP-BEDSD / VOV6）。品目は正しいことが前提
101 の入庫が得意先別に入った第 1 層MRP4 の個別/包括所要量（+ 指図の受注参照）
PIR は出ているのに計画手配が無い第 1 層MRP タイプ / 手配タイプ / ロットサイズ、或は純所要量 0
受注できるが確認済数量 0第 2 層 + 第 3 層在庫確認 OFF 或はスコープ（OVZ9）と CO09 の可用量
差異が大きい第 3 層（データ）KKS2 のカテゴリ → 実績（AFRU）・単価（MATDOC）へ遡る

9. 発展の導線（研修後）

  • 形態の対比：姉妹站 sapmto（MTO）・sapeto（ETO）と並べ、「同じ受注でも 3 形態でどう変わるか」を比べる。
  • PP/DS と aATP：より高度な見込生産（能力制約・複数プラント・優先度付き ATP）へ進む。
  • 需要計画（IBP / S&OP）：PIR の上流（予測の作り方）を学ぶ。练习① 1-5 が入口。
  • 原価・差異の深掘り：Material Ledger（Actual Costing）と差異の配賦・期末評価。
  • Cloud 実装：スコープアイテム（BJ5）と SSCUI の実習（C16）。
講師の心得（最後に 1 つだけ） 受講者が「自分のシステムでは値が違う」と言ったら、それは最高の瞬間です。標準値の暗記より、自分の環境で確認する方法を持ち帰らせるのが研修の目的です。
