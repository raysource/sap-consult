配置前的准备

配置作业会在你的练习系统留下自定义对象。请先确认三件事：① 有可写入的カスタマイジング依頼；② 你的用户能进入 SPRO（SPRO → 「カスタマイジング」→「IMG」）； ③ 练习用的販売組織/プラント/得意先/品目番号範囲可用。

VC 特有の前提（これを最初に確認する） ① 品目タイプ KMAT の番号範囲が空いているか（MMNR）。KMAT が使えない環境では VC の練習が始まりません。 ② AVC か LO-VC か：S/4HANA では PMEVC（AVC）が現行ですが、CU41 系の画面も併存します。どちらで作るかを最初に決めて、全手順をそれに合わせる（途中で混ぜると設定プロファイルの二重管理になる）。 ③ 分類システム（Classification）の権限：CT04（特徴）・CL02（クラス）は「カスタマイジング」扱いで、MM01 の分類ビュー（CL20N 系アプリでも可）とは別権限になっていることがあります。
C0

前提与环境确认（権限・AVC/PMEVC の利用可否）

目的
避免「练习跑到一半才发现 KMAT の番号範囲がない／CU50 が使えない」という手戻り。VC は 5 つの専用 T-code が揃わないと练习①〜③ が成立しません。

つまずき ① CT04 は「変更モード」で開かないと新規登録できない（照会モードのまま入力して「変更できません」と言われるのが定番）→ 初期画面の「変更」を押すか、CT04 のメニュー「特徴 → 登録」。 ② KMAT が品目タイプの F4 に出ない → 品目タイプの品目カテゴリ（OMS2 系）か、番号範囲未設定。 ③ PMEVC が無い環境（ライセンス／スコープアイテム）→ 無理をせず LO-VC 手順へ。**判断を全員で共有**する（個人判断で混ぜると後で破綻）。
練習課題C0 の 5 項目を一覧にして、自分の環境の実測値（使える／使えない、KMAT の採番方式、AVC 可否）を書いてください。この一覧は練習⑤の故障切り分けで最初に見る資料になります。
C1

特徴（Characteristics）の設計と登録

CT04
目的
「選べる仕様」を 4 つ定義する。特徴は VC の入力インターフェースなので、値の粒度・必須・複数選択・追加データをここで設計しきる。
IMG パス
SPRO → クロスアプリケーションコンポーネント → 分類システム → クラス → 特徴（CT04）。※実作業は CT04 を直接起動するのが実務的（SPRO のメニューからも同じ画面が開く）。
T-code
CT04（登録/変更/照会）。照会専用の CT03、値一覧の CT04 → 「許可値」タブ。
入力値
特徴（技術名称）名称（表示）値の型許可値設計上のポイント
ZVC_CAPACITY容量 (m3/h)NUM（数値）50 / 80 / 120数値型にすると大小比較の依存関係（> <）が書ける
ZVC_MATERIAL材質CHARFC200 / SUS304 / SUS316価格のキーに使う（加算差が最も出る特徴）
ZVC_COATING塗装CHARNONE / EPOXY / URETHANE工程の取捨（選択条件）に使う
ZVC_ACCESSORY付属品CHARNONE / PG / FG / PG_FG複数選択（複数値）を許可して練習する。※複数値を使うと単純な = 判定では拾えないため、「組合せ値（PG_FG）」を用意する設計と併用
  1. CT04 → 変更モード → 特徴 ZVC_CAPACITY を入力 → 「登録」。
  2. 基本データ：名称「容量 (m3/h)」、データタイプ NUM、長さ・小数点（例 3.0）、単位（必要な場合）、値チェックは「許可値による」。
  3. 「許可値」タブ → 値 50 / 80 / 120 を登録（値ごとに説明文を入れると設定画面で読みやすい）。
  4. 同様に ZVC_MATERIAL / ZVC_COATING を CHAR で登録（値は上表）。
  5. ZVC_ACCESSORY：基本データの「複数値（複数選択可）」を ON。値は NONE/PG/FG/PG_FG。
  6. 必須の設計：必須にするかはクラス側（CL02 の特徴行）で決めるのが基本（同じ特徴を別クラスでは任意にしたいことがあるため）。ここでは CT04 では必須にしない。
  7. 追加データ（変種価格用・発展）：価格のキーに使う特徴は「追加データ」タブで テーブル／項目（SDCOM/MMCOM の VKOND という記載）を指定する。→ 詳細は C13。
  8. 4 つ登録できたら CT04 → 照会で 4 特徴の名称・データタイプ・許可値を一覧で確認。
確認（自システム） ① CT04（照会）で ZVC_MATERIAL を開き、データタイプ CHAR・許可値 3 件・「複数値」の状態を確認。 ② SE16N で CABN を特徴の技術名称（ATNAM という項目という記載が一般的）で絞り、1 件見つかれば登録は有効。値は CAWN／テキストは CAWNT という記載（必ず SE11 で項目名を確認してから使う）。
つまずき ① データタイプを後から変えられない（NUM ⇔ CHAR）→ 変えたいなら別名で作り直す。最初に決める。 ② 値の先頭に空白・全角文字が混入すると依存関係の = 判定が一致しない（最も多い作業ミス）。CU50 で選んだ後に「値が一致しない」症状が出たら、値の前後の空白を疑う。 ③ 複数値（複数選択可）の特徴を、単純な前提条件 $SELF.ZVC_ACCESSORY = 'PG' で判定しようとして「選んだのに反応しない」→ 複数値では「すべての値が条件を満たすか」で判定されるため、組合せ値（PG_FG）を別途用意するか、手続きで単一値に正規化する設計にする。
練習課題① ZVC_CAPACITY を「数値」ではなく「文字」で作った場合、どんな依存関係が書けなくなるか？ ② なぜ必須フラグをクラス側で持つ設計が良いのか、理由を 2 つ挙げよ（ヒント：クラスの再利用、特徴の再利用）。
C2

クラス（型 300）の登録と特徴の割当

CL02（CL01/CL03）
目的
4 特徴を 1 つの「質問票」にまとめる。クラス型 300（品目変種）を使うことが VC の必須条件（他の型と混ざると品目の分類ビューにクラスが出ない）。
IMG パス
SPRO → クロスアプリケーションコンポーネント → 分類システム → クラス → クラス（CL02）。クラス型の定義は IMG の「クラス型」で確認。
T-code
CL02（登録/変更）・CL01（登録）・CL03（照会）
入力値
クラス型   300（品目変種 / Variant class）
クラス名   ZVC_PUMP_CL
名称       ポンプ バリアントクラス
特徴の割当 ZVC_CAPACITY（必須=ON） / ZVC_MATERIAL（必須=ON）
           ZVC_COATING（必須=ON）  / ZVC_ACCESSORY（必須=OFF = 任意）
  1. CL02 → クラス型 300 を選ぶ（F4 で型一覧が確認できる）。
  2. クラス ZVC_PUMP_CL を入力 → 登録 → 名称「ポンプ バリアントクラス」。
  3. 「特徴」タブ → 行を追加 → 特徴 ZVC_CAPACITY を入力。表示される特徴名・データタイプを確認。
  4. 同じ行の「必須（必須特徴）」列を ON（ZVC_CAPACITY / ZVC_MATERIAL / ZVC_COATING）。ZVC_ACCESSORY は OFF（任意）にしておく（後で「必須にすると何が起きるか」を練習する余地を残す）。
  5. 4 行そろったら保存。保存時にカスタマイジング依頼を聞かれるので、練習用の依頼を指定。
  6. CL03 でクラス ZVC_PUMP_CL を照会し、4 特徴と必須状態を確認。
確認（自システム） ① CL03 → クラス ZVC_PUMP_CL：特徴タブに 4 行、必須列の状態が意図どおり。 ② SE16N → KLAH（クラスマスタ）で CLASS = ZVC_PUMP_CL・クラス型の項目 KLART = 300（という記載が一般的）を確認。クラスに割り当てた特徴は KSML という記載。 ③ 品目への割当は C3 で行う（クラス単体では受注に効かない）。
つまずき ① クラス型を間違える（001 品目一般など）→ 品目の分類ビューでクラスが見えない。症状が出たら CL03 のクラス型を最優先で確認。 ② 特徴の「必須」を全部 ON にすると、CU50 で未入力のまま抜けられなくなる（それ自体は正しい動作）。「必須にして止める」のか「任意にして運用でカバーする」かは業務判断（第 3 節の設計判断②と同じ論点）。 ③ 既に受注が流れているクラスに特徴を追加すると、既存受注の再構成が必要になることがある（変更統制の論点 → 练习⑤）。
練習課題クラス ZVC_PUMP_CL の ZVC_ACCESSORY を必須に変えて CU50 を実行すると、何が起きるか？実際に試して元に戻してください（元に戻せることが「変更統制を理解した」証拠）。

練習課題①「受注できる 5 条件」を暗記せずに書けるようになること（KMAT／設定可能 ON／0002／戦略 25／MRP4 個別所要量）。 ② ZVC-PUMP01 を MM03 で開き、どのビューにどの値が入っているかをワークシート シート A に転記せよ（自分の環境の証跡を残す）。

目的
