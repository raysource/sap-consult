バリアント設定付き受注生産（VC / AVC）实战训练站

一条完整可跑的 バリアント設定付き受注生産（Variant Configuration / VC、S/4HANA では AVC） 场景： 特徴設計 → クラス → 設定可能品目（KMAT）→ 設定プロファイル → 依存関係 → スーパー BOM → 受注（VA01）で構成 → MRP → 製造指図 → 入庫 → 出荷 → 請求（変種価格の加算つき）。 本站分两层：练习配置（CT04 / CL02 / MM01 / CU41・PMEVC / CU01〜CU03 / CS01 / VOV7 / VOV4 / OPPS / OVZG / V/06 / V/08 / VK11 的逐项手顺，给出输入值与「在自系统中的确认方法」）与 练习流程（练习①〜⑤，每个练习都有输入值表、操作手顺、期待结果、故障对策、验收清单）。 主口径为 S/4HANA On-Premise，同步给出 Public Cloud（SSCUI / スコープアイテム） 的差异对照。

1. 这个场景教什么

VC 不是生产形态，而是「构成引擎」——这是本站所有内容的出发点。它解决的是「用 1 个品目表达无数种规格组合」的问题： 特征（特性）定义「能选什么」，依存关系定义「选了 A 就不能选 B、选了 B 就要加零件 C 和工序 D、还要加价 E」， 系统在受注输入的瞬间把这个逻辑跑一遍，算出这台泵的构成品目、工序、价格。

所以 VC 从来不单独存在。它一定和某种生产形态组合：本站主场景是 VC × 受注生産（戦略グループ 25 → 所要量タイプ KEK → 所要量クラス 046 系、受注在庫 E）， 练习⑤ 再把它换成 VC × 受注組立（82 → KMFA → 201 → 指図タイプ PP04、受注と指図 1:1） 做对照。 读者要能回答的问题是：① 这个规格组合是怎么被「翻译」成 BOM 和工序的？② 加价是从哪里来的？③ 换一种生产形态，哪几个配置项要动？

① 练习配置手顺（详细 SPRO）

C0〜C16 共 17 个 STEP：前提确认 → 特徴 CT04 → クラス CL02（クラス型 300）→ 設定可能品目 MM01（KMAT/0002/戦略 25/MRP4 個別所要量）→ 設定プロファイル CU41・PMEVC → 依存関係 CU01〜CU03（前提条件・選択条件・手続き・アクション）→ スーパー BOM CS01 → 作業手順 → 明細カテゴリ（VOV7/VOV4）→ 戦略/所要量クラス（OPPS/OPPJ/OVZG）→ ATP → 変種価格（V/06・V/08・VK11）→ 出荷・請求 → 自動転記 OBYC → Public Cloud 差异，每步给出 IMG 路径、事务码、输入值、在自系统中的确认方法。

2. 训练场景设定

场景取自典型的「産業用ポンプのバリアント設定付き受注生産」：客户按自己的用途选容量・材質・塗装・付属品，工厂按这张受注单独制造（不做库存）。 选泵的理由是它天然具备 VC 的三要素：连续的容量等级（50/80/120 m³/h）、可选材质（影响价格与交期）、可选附属装置（决定 BOM 里多不多那几个零件）。

#前提确认方法
1販売組織/販売チャネル/部門/プラント 已建并互相分配SPRO 组织构造 + OX10・OVX5 系确认；VA01 能选到销售区域
2得意先 1000 已建（一般/会社/販売エリア/出荷先）BP / XD03，需有出荷先（船積先）
3品目タイプ KMAT の品目番号範囲可用（KMAT 是 VC 的前提）MMNR；OMS2 系で品目タイプの属性も確認可
4CT04・CL02・CU01・CU41・CU50 が使える権限（AVC は PMEVC）实机直接起動。使えない場合は講師に連絡（この 5 つが無いと练习①〜③ は実施不可）
5スーパー BOM／作業手順を作れる PP 権限（CS01/CA01）既存 BOM の照会（CS03）→ 変更できるかで判断
6カスタマイジング依頼（Customizing Request）に書ける権限配置作业时会要求输入请求；CT04/CL02 は「カスタマイジング」扱い

7. 关于标准值的立场（请务必读）

本教程的做法 VC 是设计判断（モデリング）决定成败的领域，标准值本身的可变性也大： ① VC 用の明細カテゴリは「KMAT＋品目カテゴリグループ 0002 なら通常 TAN」という記載（varconf）がある一方、ACE/TA 系の専用カテゴリ（TAC＝Configurable material item 等）を使う設計もある —— 必ず VOV4/VOV7 と受注明細で確認。 ② 変種価格の追加データは LO-VC は SDCOM-VKOND、AVC は MMCOM-VKOND という記載がある —— CT04 の追加データ画面と SE11 で自分の環境の構造を確認。 ③ AVC では CU50 相当の画面が Fiori の特徴グループ（Characteristic Groups）ベースに置き換わる —— PMEVC の有無と Fiori アプリの導入状況を確認。 ④ 所要量クラス（046 系）・評価の有無は環境差が大きい —— OVZG で自分の環境の 046 の属性を確認。
因此本站原则是：把「标准值的通常情况」写清，但每个值都配一条「在你自己的系统里怎么确认」的手顺， 并让所有练习都建自己的 Z 对象（ZVC_*），这样即使标准值与本站不同，练习依然成立。教学以「机制正确」为优先，不以背标准值为目标。
