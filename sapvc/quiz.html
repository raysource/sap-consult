能力测试（28 題 ＋ 実機验收清单）

用法 每题点击一个选项即判分并显示解说，页面顶部显示累计成绩。合格判定：正确率 ≥75%（21/28）＋ 実機验收清单全部勾上 ＋ ワークシート記入。 60〜74% 请回对应页面重读；<60% 请从 概念与设计 重来一遍。
解说里的标准值同样是「通常情况」——考试式的死记没有意义，要能说出「怎么在系统里验证」。

一、概念（1〜10）

概念VC の本質

1. SAP のバリアント設定（VC）を最も正しく説明しているものは？

受注生産（MTO）の別名であり、生産形態のひとつ
1 つの品目（KMAT）で無数の仕様組合せを表現する「構成エンジン」であり、生産形態は戦略グループで別に決める
在庫品を組み立てる生産方式（組立処理）そのもの
品目マスタを減らすための分類機能で、価格や BOM には影響しない
VC は構成エンジンです。生産形態（受注生産 25 / 受注組立 82 / ETO）は戦略グループ・WBS 側の設計で決まり、VC はそのどれにも乗ります。→ 概念 2 節
概念戦略と所要量

2. VC の受注生産で一般に使われる戦略グループ 25 の組み合わせは？

25 → 所要量タイプ KMFA → 所要量クラス 201・指図タイプ PP04
25 → 所要量タイプ KE → 所要量クラス 040 系・在庫は自由在庫
25 → 所要量タイプ KEK → 所要量クラス 046 系・受注在庫（E）
25 → 所要量タイプ E21 → プロジェクト在庫（Q）
25（Make-to-Order Production w/ Configuration）は KEK → 046 系で、受注在庫（E）です。KMFA/201/PP04 は戦略 82（受注組立）。確認は OPPS/OPPJ/OVZG。→ 概念 7 節
概念クラス

3. VC でクラスを作るときに選ぶクラス型は？

300（品目変種 / Variant class）
001（品目一般）
023（品目バッチ）
クラス型に決まりはなく、どれでも同じように動く
VC（設定可能品目）はクラス型 300。間違えると品目の分類ビューにクラスが出ず、受注で構成画面が出ないなどの症状になります。→ C2
概念依存関係

4. 「この構成のとき、この BOM 明細を採用するか」を判定する依存関係は？

前提条件（Precondition）
手続き（Procedure）
アクション（Action）
選択条件（Selection condition）
BOM 明細や工程の採用可否は選択条件。前提条件は特徴値の成立条件（$SELF）、手続きは値の計算・上書きです。→ 概念 3 節
概念KMAT

5. 設定可能品目（KMAT）の在庫の扱いとして正しいものは？

自由在庫として通常どおり在庫管理され、MMBE で見える
原則として在庫管理されない（構成された実体・構成品目・受注在庫の単位で管理する）
品目タイプ KMAT にすると自動的に受注在庫（E）になる
材料バリアントを作ると在庫が二重計上される
KMAT 自体は在庫を持ちません。「在庫が見えない」は仕様です。在庫の持ち方（受注在庫 E・材料バリアント・別品目）は設計判断になります。→ 概念 12 節 #2
概念依存関係の適用先

6. 「塗装 EPOXY は材質 SUS316 のときだけ選べる」ようにする前提条件は、どこに貼る？

クラス ZVC_PUMP_CL に貼る
特徴 ZVC_COATING（特徴そのもの）に貼る
特徴値 ZVC_COATING = EPOXY（当該の値）に貼る
スーパー BOM の明細に貼る
「この値のときだけ成立する」は特徴値に貼ります。特徴（全体）に貼ると塗装という特徴自体が使えなくなり、症状が全く変わります。→ C5
概念処理形式

7. 設定プロファイルの処理形式のうち、構成品目が子明細（個別の明細）として受注に並ぶものは？

伝票明細（SET 処理）。品目カテゴリグループ 0004 が前提という記載がある
明細 / 生産指図（BOM 展開なし）
受注 BOM（Order BOM）方式
多階層展開を選べば必ず子明細になる
SET 処理では構成品目が子明細になり、価格・所要量も子明細単位で転送されます（varconf の記載）。受注 BOM は「受注ごとの BOM を作る」方式で子明細とは別です。→ 概念 5 節
概念変種価格

8. 変種価格（条件タイプ VA00）で「どのオプションにいくら加算するか」を引くためのキーは、何が決める？

品目マスタの標準価格（会計ビュー）
受注明細の数量
クラス型 300 の定義
特徴の「追加データ」で指定したテーブル/項目（VKOND）に、設定値が入ること
SAP KBA 1934081 も、標準ではVKOND を参照する特徴の値が変種条件行を決めると説明しています。LO-VC は SDCOM-VKOND、AVC は MMCOM-VKOND という記載があります（自システムで SE11 確認）。→ 概念 8 節
概念AVC

9. S/4HANA の AVC（Advanced Variant Configuration）について正しいものは？

AVC では従来の特徴・クラス・依存関係は使えなくなる
統合モデリング環境 PMEVC が入り口で、従来の CU41 系画面も併存する。環境を片方に統一するのが原則
AVC を入れれば依存関係の設計ミスは自動的に解消される
AVC は Public Cloud では使えない
PMEVC（AVC）と CU41 系（LO-VC）は併存します。AVC では特徴グループ＋Fiori の設定 UI、MMCOM-VKOND、制約（Constraints）などが特徴。Cloud は AVC 前提です。→ 概念 9 節
概念品目カテゴリグループ

10. 設定可能品目の「品目カテゴリグループ 0002」の役割は？

MRP のロットサイズを決める
在庫評価クラスを決める
受注明細の明細カテゴリ決定のキーになる（VC の標準。VOV4）
作業手順の工程を決める
品目カテゴリグループは VOV4 による明細カテゴリ決定のキーです（SET 処理は 0004 という記載）。標準で決まる明細カテゴリの値は環境差があるためVOV4＋VA03 の実測を正とします。→ C10

二、配置（11〜19）

配置品目マスタ

11. 品目カテゴリグループは、品目マスタのどのビューで設定する？

販売組織 2（Sales Org 2）
MRP 1
会計 1
分類（Classification）
販売組織 2 です（販売エリア単位で持ちます）。分類ビューにはクラスを割り当てます。→ C3
配置MRP4

12. 品目マスタ MRP4 の「個別/包括所要量 = 1（個別所要量のみ）」を設定する目的は？

MRP の実行を速くするため
受注在庫（特別在庫 E）を成立させるため（受注単位で所要量と在庫を分ける）
ロットサイズを自動化するため
バックフラッシュを有効にするため
受注在庫・プロジェクト在庫を使う品目は個別所要量が前提です。未設定だと「受注在庫に割当できません」系のエラーになります。→ C3
配置特徴

13. CT04 で特徴を登録するとき、後から変えられないため最初に決めるべきものは？

名称（説明文）
許可値の件数
データタイプ（CHAR か NUM か）と桁・小数点の構成
使用するクラス
CHAR ⇔ NUM は後から変更できず、作り直しになります。NUM でないと大小比較（>=）の依存関係が書けません。→ C1
配置クラス

14. 特徴を「必須（未入力では設定を終われない）」にする設定は、どこで行うのが基本か？

CT04 の基本データ
品目マスタの MRP3
設定プロファイルの名称
CL02（クラス）の特徴行の「必須」列
必須はクラス側で持ちます。同じ特徴を別クラスでは任意にできるためです（特徴の再利用性）。設定プロファイル側にも必須・完全性チェックがあります。→ C2
配置設定プロファイル

15. 設定プロファイルと品目のひもづけは、どこで指定する？

品目マスタの基本データ 1 の「設定可能」インジケータだけ
CU41/CU42（または PMEVC）のプロファイル側で「割当品目」を入力する
VOV4 の明細カテゴリ決定
BOM ヘッダの項目
割当はプロファイル側で品目を指定します。忘れると CU50 は開くのに VA01 で構成画面が出ないという症状になります。→ C4
配置依存関係の照会

16. 「この依存関係がどの適用先に貼られているか」を確認する画面は？

CU03（照会 → 適用先／使用箇所一覧）
CU50 の構成結果
CS03 の BOM 明細だけ
MM03 の MRP4
CU03 の「適用先／使用箇所一覧」に出ない依存関係は発火しません。無反応時の第一チェックです。→ 练习⑤ 5-3
配置スーパー BOM

17. スーパー BOM の作り方として正しいものは？

最も売れる構成の部品だけを入れて、後から追加する
組合せごとに別々の BOM を作る（使用箇所を分ける）
受注のたびに BOM を手で作る
全バリエーション分の構成品目を 1 つの BOM に入れ、選択条件で今回必要な行だけを採用する
「全部入れて、選択条件で絞る」が VC の原則。材質別ケーシングのように行を分けて条件を書き分けるのが保守しやすい設計です。→ 练习③ 3-2
配置変種価格

18. 変種価格で使う条件タイプはどれ？

PR00
VA00
K007
MWST
PR00 は基本価格、変種（加算）は VA00 です。条件タイプは V/06、計算手続は V/08、条件レコードは VK11。→ C13
配置Public Cloud

19. Public Cloud（SSCUI）で一般的にできないとされるものは？

設定可能品目の品目マスタを登録すること
特徴（CT04 相当）を作ること
標準にない明細カテゴリ等の伝票カテゴリを新規作成すること
AVC（PMEVC）でモデリングすること
Cloud は AVC 前提でモデリングは可能ですが、SSCUI の範囲外＝実現できない領域があります（明細カテゴリの新規作成など）。スコープアイテム IYT/7DM の活性も必要です。→ C16

三、流程（20〜25）

流程受注

20. VA01 で設定可能品目の構成（設定値）を入力する操作は？

初期画面で「構成」を押す
明細を選択した状態で「構成」ボタンを押し、設定画面で特徴値を選ぶ
納入日程行の明細で値を入力する
受注を保存した後に CU50 で値を入れる
明細レベルの「構成」です。開かない場合は C3 の 5 条件・プロファイル・明細カテゴリを確認します。→ 练习④ 4-1
流程受注 BOM

21. 受注で選んだ構成に対応する構成品目（受注 BOM）を確認する場所は？

VA03 → 明細 → 「構成品目（受注 BOM）」ボタン
CS03 のスーパー BOM
MM03 の MRP1
CU03 の依存関係一覧
受注明細の構成品目です（CS03 はスーパー BOM＝設計側の全量）。設定プロファイルの処理形式が「展開なし」の場合はここに出ません。→ 练习④ 4-1
流程指図への伝搬

22. 製造指図に受注の設定値を引き継がせるために、正しい作り方は？

CO01 で品目だけを入力して指図を新規作成する
指図を作った後に明細の構成値を人が入力する
計画手配（MD04）からの変換、または CO40/CO08 で受注明細を参照して指図を作る
受注を VA01 で作り直す
指図は「受注明細参照」で作ると構成（設定値）を引き継ぎます。品目だけの新規作成では構成が空になります。→ 练习④ 4-4
流程出荷

23. VC × 受注生産（戦略 25）の出荷で正しいものは？

自由在庫から出庫する（在庫区分は空）
プロジェクト在庫（Q）から出庫する
構成品目を明細に並べて出荷し、在庫区分は E
受注在庫（特別在庫 E／受注番号つき）から出庫し、出庫確認 601 で在庫が消える
受注在庫（E）からの出庫で、PGI は移動タイプ 601。通常は親品目を出荷し、構成品目は製造で消費します（子明細は SET 処理の設計）。→ 练习④ 4-6
流程変種価格

24. 受注の条件画面に VA00 の加算が出ないときの第一嫌疑として適切なものは？

特徴の「追加データ」（テーブル/項目＝VKOND）が未設定、または計算手続に VA00 のステップが無い
受注数量が多すぎる
クラス型が 300 でない
MRP4 の個別所要量が未設定
切り分け順は ① 追加データ（CT04）② 条件タイプ（V/06）③ 計算手続（V/08）④ 条件レコード（VK13）。行はあるのに金額 0 ならキー不一致です。→ C13
流程戦略 82

25. 戦略グループを 82（受注組立）にしたときの、戦略 25 との決定的な違いは？

受注在庫ではなくプロジェクト在庫（Q）になる
受注と製造指図が 1:1 で、受注保存と同時に指図が作られる（所要量タイプ KMFA／所要量クラス 201／指図タイプ PP04）
構成が使えなくなる
BOM が不要になる
戦略 82 は受注と指図が 1:1 で、BOM が必須という記載があります（SAP Help 組立処理）。変更は新規受注にだけ効きます。→ 练习⑤ 5-2

四、故障（26〜28）

故障症状から引く

26. 受注で「構成」ボタンがグレーで構成画面が出ない。第一に確認する組み合わせは？

MRP タイプとロットサイズ
出荷タイプと請求タイプ
設定可能（Configurable）インジケータ／品目タイプ KMAT／品目カテゴリグループ 0002／設定プロファイルの品目割当
OBYC の自動転記設定
「構成が出ない」は品目マスタの 5 条件とプロファイル割当に集約されます（MM03 → CU43 → VOV4 の順）。→ 故障対照表 #1
故障症状から引く

27. CU50 で材質を変えてもケーシング（構成品目）が入れ替わらない。第一嫌疑は？

品目の評価クラスが未設定
条件レコードのキーが違う
作業手順の標準値項目名が違う
選択条件の適用先（BOM 明細に貼っていない）／$ROOT と特徴名の不一致／BOM の有効日
CU03 で使用箇所を確認 → CS03 の選択条件文字列 → BOM 有効日、の順が最短です（CU50 で再現できる＝設計側の問題）。→ 故障対照表 #2
故障変更統制

28. 受注後に構成（材質）を変更した。製造指図はどうなる？

自動的に新しい構成に更新される
自動では変わらない。指図（または明細）の再展開が必要で、運用ルール（変更可否・承認）を決めておかないと事故になる
指図は自動的に削除される
在庫が自動的に引き当て直される
受注 BOM・指図・価格は自動追従しません（価格も再価格決定が必要）。本站は「リリース前は変更可／リリース後は禁止＋例外は作り直し」を推奨案として提示しています。→ 练习⑤ 5-1

五、実機验收清单（これを全部 ✓ にできないと「修了」ではありません）

  • 特徴 4 つ（ZVC_CAPACITY は数値型）とクラス ZVC_PUMP_CL（クラス型 300）を提示できる
  • 品目 ZVC-PUMP01 の「受注できる 5 条件」を MM03 で提示できる（KMAT／設定可能 ON／0002／戦略 25／MRP4 個別所要量）
  • 設定プロファイル ZVC_PROFILE01 の割当品目・処理形式を CU43 で提示できる
  • 依存関係の適用先を CU03 の使用箇所一覧で提示できる（前提条件・選択条件・手続き）
  • CU50 で材質・付属品・塗装を変え、構成品目と工程の取捨が変わることを実演できる
  • CS03 のスーパー BOM に行を分けた材質別ケーシングと選択条件を提示できる
  • 受注（VA01）で構成を入力し、受注明細の「構成品目（受注 BOM）」が構成どおりであることを提示できる
  • 条件画面で VA00 の加算行とキー（設定値）を提示できる
  • MD04 に得意先所要量が出て、計画手配の在庫区分が受注在庫（E）であることを提示できる
  • 製造指図の「構成」に設定値が伝搬していることを CO03 で提示できる
  • MMBE で受注在庫（E）10 PC を提示し、601 後に 0 になるところまで実演できる
  • 請求に PR00＋VA00 の金額が乗り、伝票フローが受注→出荷→請求→会計で完結していることを提示できる
  • 戦略グループを 82 に切り替え、受注と指図が 1:1 になることを実演し、25 に戻した
  • 故障対照表の 5 項以上を、確認手顺を見ずに切り分けの型（CU50 で再現 → 設計側／伝票側）で説明できる
  • ワークシートのシート A〜F を記入し、伝票番号（受注・指図・出荷・請求）を提示できる
合格判定 28 題で 21 問以上（≥75%）＋ 上記验收清单の全項目 ✓ ＋ ワークシート記入＝「VC の受注生産を 1 周できる」レベルです。
