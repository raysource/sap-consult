講師用 — 授業設計、デモスクリプトと採点の提案

この教材を使って講習を担当する講師向けのページです。当サイトの素材は教材ドキュメント S4.docx に基づいています： 222 タスク／1369 枚の実機画面。すべての画面は原作者が実際のシステムでキャプチャした中国語インターフェースです。

当サイトの立場（講義の際は同じ説明をしてください） ① 画面は原教材ドキュメントの実機スクリーンショットであり、模式図ではありません。② ドキュメント内の組織構造とマスタデータの番号（C999 / F999 / R999-100 / K001 …）は原作者の教材環境に属します。操作の順序はそのまま行い、設定値は受講者ご自身のシステムのものに置き換えてください。 ③ 当サイトは原教材ドキュメントにない標準値、項目一覧、SAP Note を補足しません。

1. 授業時間割の提案（5 日 / 30 時間）

タスク数も画面数も非常に多く、講義しきれないのは当然です。そこで「設定は主要な流れだけ、業務はすべて実演」をお勧めします： 各モジュールの IMG 設定から重要なタスクを 1〜2 件選んでデモし、業務処理のタスク（伝票の登録、入庫、請求）はすべて一通り実施します。

3. 必ず出る質問（12 問、標準回答付き）

#受講者が必ず聞くことこのように答えるとよい
1この教材の設定作業はどこから始めますか？「準備作業」の SPRO から IMG 設定に入り、その後は FI → CO → MM → PP → SD の順に進めます。FI のタスク 01〜05（会社コード / 勘定科目表 / 会計年度バリアント / 与信管理領域 / グローバルパラメータ）は全モジュール共通の前提なので、必ず最初に実施してください。
2FI の最初のタスクが「勘定の登録」ではなく「会社コードの登録」なのはなぜですか？会社コードは「1 つの完全な会計実体」です（原教材ドキュメントの表現）。以降のすべての勘定、伝票、期間、レポートはこの会社コードに紐づきます。教材で登録するのは C999「頤寧機械有限公司」です。
3勘定を登録したのに、伝票である項目が見えない（または項目がグレーになる）のはなぜですか？「勘定グループ + 項目ステータスバリアント」で決まります：タスク 06 で勘定グループと入力制御を定義し、タスク 07 で項目ステータスバリアントを定義し、タスク 08 でバリアントを会社コードに割り当てます。そのため、勘定を説明する前に、まずこの 2 つを説明する必要があります。
4「材料購買勘定」は何のためにあるのですか？なぜ GR/IR とも呼ばれるのですか？原教材ドキュメントの説明：入庫時は「在庫」を借方・「材料購買」を貸方に記帳し、請求書受領時は「材料購買」を借方・「買掛金」を貸方に記帳し、勘定は「1 件ずつ消し込む」必要があり、入庫と請求書受領の間をつなぐ中間勘定（GR/IR）です。貸方残高は WRX トランザクションキーに計上されます。
5MM で最も間違いやすい接点はどこですか？品目マスタの「評価クラス」と自動記帳 OBYC：評価クラスが勘定決定を左右し、評価クラスを誤って入力するとエラーになります「明細 A999 BSX CN01 に対して勘定を決定できません」。原教材ドキュメントでの対応は、作成済みの購買発注を削除し、品目の会計ビュー 1 の評価クラスを変更するというものです（当期／前期／前年度のすべてを変更する必要があります）。品目を登録する時点で正しく設定しておくことをおすすめします。
6税コードのエラー FS217 はどう対処しますか？FS00 でその総勘定元帳勘定を開き、「制御データ」で税分類を緩めます：- は仕入税のみ許可、+ は売上税のみ許可、* はすべて許可。変更後は MIRO を終了して入り直します。
7PP の標準原価見積は、どの T-code をどの順で使いますか？CK11N で見積 → CK24 でマーク → CK24 でリリース。作業価格が欠落している場合（例：「内部作業 LAB 1001 の価格を確定できません」）は、まず KP26 で作業の出力価格をメンテナンスし、再び CK11N に戻ります——原教材ドキュメントが特に注意を促しているのは、メンテナンス後にCK11N を終了して CK24 を再実行するという点です。
8製造指図を指図発行から決済まで実演するとき、正しい順序はどれですか？指図発行 CO02 → 出庫（製造指図への出庫）→ 確認 CO11N → 入庫 MIGO → 原価照会 CO03 → 技術的完了 CO02 → 差異決済 KO88 → 原価レポート。（PP のタスク 42〜49 に対応）
9SD の「販売エリア」とは何ですか？なぜ受注伝票の最初に必ず入力するのですか？販売エリア = 販売組織 + 流通チャネル + 製品部門 で、SD の業務区分です（タスク 01〜07）。受注伝票の価格決定手順、納入、税の決定、供給可能量はいずれもこれで特定するため、販売エリアを入力しないと何もできません。
10得意先マスタのパートナはなぜ 4 つあるのですか？原教材ドキュメントに記載されているのは：SP 受注先、BP 請求先、PY 支払先、SH 納入先。同じ得意先でも、役割ごとに別の相手を設定できます（例えば受領先 K002 を納入先にするなど）。受注伝票ではこれらの役割が自動的に反映されます。
111 件の取引が見積から会計伝票に至るまで、どの T-code を実演しますか？見積 VA21 → 受注伝票（見積を参照して登録）→ 納入 VL01N → 請求書 VF01 → 転記 VF02 → 会計伝票（元伝票をクリック）→ 伝票一覧 VA05 / 販売分析 MCTA。
12受講者のシステムで出るエラーが教材と違うときはどうしますか？まず「トラブルシューティングと注意点」ページの 6 つの前提チェック（期間のオープン／クローズ、組織構造の割当、評価クラスと OBYC、価格のマークとリリース、在庫、マスタデータ）を行い、教材に出てくるエラーのほとんどは、この 6 つの分類に当てはまります。それでも解決しない場合は、F1/F4 と SPRO のドキュメントボタンで項目を確認してください —— 他人の標準値をそのまま写さないでください。

4. 採点と受入確認の提案

項目配点判定基準
自習テスト（quiz.html 30 題）30%75% 以上で合格（23 題以上）。誤答した問題は該当のタスクに戻って復習してください。
手順の完成度（受講者用の記入表）40%FI 01〜21 + MM 21〜28 + PP 22〜25 + SD 34〜44 の「重要チェーンのタスク」はすべてチェックが必要です。
トラブルシューティング問題（トラブルシューティングページ の 10 現象）20%「現象 → 原因 → 対処 T-code」の 3 要素を言えること。5 題を抽出し、全問正解で満点です。
口頭で流れを復唱10%購買チェーン（ME51N→ME21N→MIGO→MIRO→MRBR）と販売チェーン（VA21→受注伝票→VL01N→VF01→VF02）の 2 つの T-code の流れを自力で言えること。
1 回の授業の最後の 20 分はこう締めくくります① 受講者に受講者用の記入表で「遭遇した問題」欄を記入してもらう；② トラブルシューティングページの現象表を一緒に確認する；③ 自習テストページを一通り解き、その場で間違いを確認する。④「自分のシステムに戻って、会社コード／プラント／販売エリアを自分の値に置き換える」という課題を出す。
