受注形態の横断比較（MTS / MTO / ETO / ATO / VC）

「どの生産形態を選ぶか」で、後工程の库存区分・所要量タイプ・成本对象・请求方式・収益認識がすべて連鎖して決まります。 本站把 5 种形态放在一张表上横向比，再用 「同一业务分别用 E（受注在庫）和 Q（プロジェクト在庫）跑一遍」 的对照实习把差异钉死，最后给出 VC（バリアント設定） 的概观与选型判断。 配置与操作手顺不重复写——那部分在 ../sapmto/（MTO）与 ../sapeto/（ETO）两站。

1. 五种形态的地图 2. 选型判断（用什么问题问业务） 3. 与两个实训站的关系 4. 授课方案 5. 关于标准值的立场

1. 五种形态的地图（先在脑子里画这张图）

形态一句话计划起点库存区分典型的な品目マスタ設定
見込生産（MTS）先做后卖，按预测备库存計画独立所要量（PIR, MD61）自由在庫戦略グループ 10 / 11 / 30 / 40 等、MRP4 は空
受注生産（MTO）按订单造，做完就发受注E ＝ 受注在庫（受注明細）戦略グループ 20、MRP4 個別所要量
受注設計生産（ETO）按项目设计、制造、核算受注＋プロジェクト（WBS）Q ＝ プロジェクト在庫（WBS）戦略グループ（Cloud E2）、MRP4 個別所要量、評価付プロジェクト在庫
受注組立（ATO）部件备库，受注瞬间建指图受注（保存と同時に指図）E（または自由在庫＋指図）戦略グループ 82（組立処理）、所要量クラス 201、指図タイプ PP04
バリアント設定（VC）一个 KMAT ＋ 客户选择值 → 无限变体受注（設定値つき）E 或 Q（VC 単体では形态を決めない）品目タイプ KMAT、品目カテゴリグループ 0002（/ 0004）、戦略グループ 25（MTO+VC）
三句话总结 ① 计划起点决定「需求从哪来」（PIR / 受注 / 受注＋プロジェクト）。
② 库存区分决定「东西归谁」（自由 / E / Q）——这是后续所有差异的根源（数量表 MSKA・MSPR、出荷の引当、评价の有無）。
③ 成本与请求决定「钱怎么算、怎么收」（指図 / WBS；出荷ベース / 請求計画・出来高）。VC 与 ATO 是「怎么造」的维度，可以和上面任一种组合（VC+E、VC+Q、VC+ATO）。

2. 选型判断：拿这 6 个问题问业务（现场最有用的部分）

  1. 是先造还是先卖？——先造 → MTS；接了单才动 → 继续问。
  2. 这张单要按项目核算成本/收入吗？（有设计费、据付、验收、分期收款）——要 → ETO（WBS；将来可能要用 PS/EPPM）。
  3. 库存只能给一张受注明细，还是只能给一个项目？——受注明細 → E；WBS → Q。
  4. 客户在受注时选规格（颜色/容量/口径…）吗？——选 → VC（KMAT ＋ 特徴/クラス/設定プロファイル）。选完还要立刻建指图 → VC＋ATO（組立処理）。
  5. 制造多久？要提前备料/提前组装吗？——受注即组装 → 戦略 82（ATO）；按 MRP 排产 → 戦略 20/25。
  6. 收入什么时候确认？——交货时 → 出荷ベース請求；按进度/里程碑 → 請求計画・出来高＋結果分析（ETO で多い）。
現場で最も誤解される 3 点 ① 「受注生産 = 受注在庫（E）」→ 不一定，按项目核算就是 Q。
② 「VC は生産形態」→ VC 只是「怎么描述与选配产品」的机制，库存区分与计划战略另配（戦略 25 + 品目カテゴリグループ 0002 が一般的）。
③ 「戦略グループ 82 は VC 用」→ 82 是组立处理（1:1 建指图），与 VC 无关的项目也能用。

5. 关于标准值的立场

本站の前提 比较表里写的是「標準の通常情況」（S/4HANA On-Premise 2020〜2024 基準）。ETO/VC の標準値は環境差が特に大きいため、具体値（戦略グループ、WBS を割り当てられる明細カテゴリ、VC の設定プロファイルの作り方）は 各实训站の「自システムでの確認手顺」で実測してください。本站の目的は「選型と説明」であり、「値を暗記する」ことではありません。

  • SAP Help（S/4HANA On-Premise）Special Settings for Production Orders：戦略 82 ＝ 組立処理（所要量タイプ KMFA / 所要量クラス 201 / 指図タイプ PP04、1:1）。
