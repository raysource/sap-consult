2. 板書用：3 つの問い（この順で問いかける）

問い 1：この商流は「受注の前にモノを作るか？」
        → 作る＝MTS（PIR・自由在庫）／作らない＝受注起点（次へ）

問い 2：この案件は「プロジェクト（案件）単位で原価・収益・進捗を管理するか？」
        → する＝ETO（Q・WBS・請求計画・結果分析）／しない＝MTO（E・指図）

問い 3：この製品は「得意先が仕様を選ぶタイプか？ そして受注後すぐ組むか？」
        → 選ぶ＝VC（KMAT・特徴/クラス・設定プロファイル）
        → すぐ組む＝ATO（戦略 82・受注と同時に指図）

※ モノの流れ（261 / 101 / 601）と請求伝票（VF01）はどの形態でも同じ。
   違うのは「帰属先」「成本の対象」「月末の処理」。この 3 点だけを板書に残す。
講義で必ず言う 3 点 ① 库存区分が全てを決める：自由 / E（受注明細）/ Q（WBS）——表は MARD / MSKA / MSPR。
② 受注在庫 E の 4 点セット：MRP4 個別所要量／所要量クラスの個別在庫／明細カテゴリの特別在庫 E／（＋戦略グループ）。
③ プロジェクト在庫 Q の 4 点セット：評価付プロジェクト在庫／MRP4 個別所要量／戦略グループ（評価区分 M）／受注明細への WBS 割当。

3. 演習解答：形態の振り分け（横断比较 の演習）

#ケース形態库存区分成本の対象請求方式
①標準的な工作機械の受注生産（納期 2 か月・分割請求なし）MTOE（受注在庫）製造指図出荷ベース（F2）
②得意先工場に据え付ける特注ライン（設計・据付・検収・着手金あり）ETOQ（プロジェクト在庫）WBS（＋指図）請求計画/出来高＋結果分析
③自社ブランドの切削工具（見込みで在庫し出荷）MTS自由在庫品目/指図（標準原価）出荷ベース
④得意先が容量・色・材質を選ぶ産業用ポンプ（受注後すぐ組立）VC ＋ ATOE（または自由在庫＋指図）製造指図出荷ベース（変種価格の加算あり）
⑤得意先ごとにソフトウェアをカスタマイズして納める案件ETO（サービス明細の併用も）Q（または在庫なし＋費用）WBS（プロジェクト）請求計画/出来高。役務は納入不要の明細（DIEN 系）も検討

採点の見方：形態名だけでなく库存区分・成本の対象・請求方式が揃って正解。特に ④ で「VC は形態ではなく構成エンジン」と説明できるかが理解の分かれ目です。

4. 演習解答：E vs Q 判別（E vs Q 对照 の 8 問）

#問い解答解説（採点のポイント）
1受注 10 台・納期 2 か月・分割請求なし・設計は流用MTO（E）設計も据付もなく、受注後に造って納めるだけ → WBS を作る理由がない。原価は指図で足りる
2工場据付の特注ライン・着手金 30%・検収後 70%ETO（Q）据付・検収・分割請求＝案件としての原価/収益管理が必要 → WBS ＋ 請求計画（30/70）
3MMBE に「特別在庫 E、受注 0000001234/000010」MTO特別在庫 E は受注明細に帰属。数を確認する表は MSKA
4計画手配の勘定設定が空・在庫区分も空。最初に疑う設定は？4 点セットの不成立（ETO なら特に ① 評価付プロジェクト在庫 と ④ 受注明細の WBS、MTO なら ③ 明細カテゴリの特別在庫 E）「空」＝個別需要として成立していない。まず受注明細（WBS / 特別在庫）→ 次に品目 MRP4 → 戦略グループの順で見る
5CJI3 に収益が出ない受注明細が指す WBS が請求要素でない（または受注明細に WBS が無い）収益は請求要素、原価は勘定設定要素。CJ20N の WBS フラグと VA03 の WBS を突き合わせる
6請求計画なしで出荷ベースだけの請求は可能か？可能請求計画は「分割して請求する」仕組み。出荷ベースなら出荷（PGI）後に VF01。明細カテゴリの請求関連とコピー制御（VTFL）を確認
7同じ品目を MTO と ETO の両方で使えるか？技術的には可能（受注明細の WBS / 特別在庫で分岐）ただし運用は分けるのが安全。同じ品目に E と Q が混在すると、入庫先・評価・決済が読みにくくなる。品目を分けるか、得意先/チャネルで運用を分けるのが実務的
8得意先が色と容量を選ぶ。MTO のままで対応できるか？不可（VC が必要）選択値を BOM・工程・価格に反映するには KMAT・特徴/クラス・設定プロファイルと依存関係が必要。品目カテゴリグループ 0002＋戦略 25（または 82）

5. 討論テーマ（15 分ずつ、現場感覚を養う）

  1. 「E と Q のどちらで設計すべきか」——同じ製品でも、得意先が「据付・検収・分割払い」を求めるかどうかで変わる。要件定義でどの質問を得意先にするか。（答えの型：原価/収益の管理単位＝受注か案件か、請求の仕方＝出荷か請求計画か）
  2. 「VC を入れるべきか、品目を増やすべきか」——品目が 50 → 5,000 に増える見込みがあるなら VC。ただし依存関係の設計・保守コストを直視する。
  3. 「予算管理は必要か」——ETO で案件ごとに予算統制するか、計画＋実績の比較で足りるか。可用性管理（CJBV）の警告/エラー設計は業務と合意が必要。
  4. 「収益認識はどの方式か」——出荷ベース / 出来高 / POC（進捗比例）/ イベントベース。会計方針×契約×システム対応（結果分析 or イベントベース）の掛け算で決める。
  5. 「月末に何を見るか」——MTO は指図の差異、ETO は WBS の予実と WIP。経営層に見せる帳票はどれか。

6. 採点・評価

観点配点合格ライン見方
知識（選択問題）40能力测试 20 題で 75% 以上（15 問）誤答分野（形態判別 / 主数据 / T-code / 故障 / VC）で戻るページを指示
説明力（対比）40「需要の帰属・在庫の表・成本の対象・請求の仕方・月末処理」の 5 点を、資料を見ずに 5 分で説明できるE vs Q 对照 の 5 点。ここが本講義の主評価
実機（任意）20MTO と ETO の両方で、受注→入庫→出荷→請求を 1 回ずつ通した証跡（伝票番号・MSKA/MSPR の行）詳細は各站のチェックリストで採点
フィードバック文例 「比較表は読めています。次は判断です。『この商流なら Q、理由は◯◯』を自分の言葉で言えるようにしましょう。特に『なぜ E では足りないのか』を説明できると、要件定義の場で信頼されます。」

7. 必出質問 Q&A

#質問模範回答
1E と Q を同じ受注で同時に使えますか？明細単位では混在可能ですが、運用は分けるのが安全です。理由は、入庫先・評価・決済・帳票がすべて変わるためです。設計上は「案件＝Q」「単発＝E」のように切り分けるのが定石です
2ETO で必ずネットワークを使いますか？不要です。WBS ＋ 製造指図で回せます。ネットワークは設計・据付・外注の工程管理と工数集計（CN25）に価値があります
3VC を入れたら ETO にできますか？できます（VC × Q）。Cloud では「完成品受注で BOM を展開したい」場合に E2 を使わない選択もあるため、スコープ要件の確認が必要です
4戦略グループ 82 は VC 専用ですか？違います。82 は組立処理（受注と同時に指図、1:1、BOM 必須）で、VC の有無に関係なく使えます
5MTS の在庫と MTO の受注在庫を同じ品目で持ちますか？持ち得ますが、実務では分ける（品目を分ける・プラントを分ける）ことが多いです。MRP4 の個別/包括所要量は品目単位の設定なので、混在させると在庫と需要の見え方が複雑になります
6請求計画と出来高請求の違いは？請求計画は「いつ・いくら請求するか」の一覧（日付ベースも出来高ベースもある）。出来高請求はマイルストーン達成をトリガにする方式で、請求計画タイプの一つとして扱います
7どの形態でも 261/101/601 は同じですか？移動タイプは同じです。違うのは「入庫先（自由 / E / Q）」と「勘定設定（受注明細 / WBS）」です
