4. 配置の解答と採点ポイント（C0〜C16）

STEP本練習の解答（設定値）採点ポイント／よくある間違い
C0販売エリア 1000/10/00、得意先 1000（販売エリア＋出荷先）、各番号範囲に空き前提を飛ばして VA01 から始め、保存時エラーで 30 分溶かす。冒頭で「保存せずに画面まで入る」確認を必ず実施させる
C1RM01：ROH / PD / EX / F / 初期在庫 100 ・RM02：HAWA / PD / EX / F / 初期在庫 500（MRP4 は空）部品にも受注生産設定（MRP4 個別所要量）を入れてしまう → 部品は見込で持つ、と明確に区別させる
C2FERT / PD / EX / 手配タイプ E / MRP3 戦略グループ 20・在庫確認 02 / MRP4 個別所要量のみ / 販売組織2 品目カテゴリグループ 0001この 3 フィールド（販売組織2・MRP3・MRP4）を口頭で言わせる。手配タイプ空／MRP タイプ ND は計画手配が出ないので必ず指摘
C3BOM RM01×2・RM02×8（用途 1）／作業区 ZMTO_WC01／工程 0010 組立 1HBOM 無しで練習② に進むと 261 で詰まる。CS03 の表示確認までやらせる
C4PR00 = 12,000 JPY/PC（得意先 1000 × ZMTO-FG01）「請求は後で直せる」と思って飛ばす → 練習④で金額 0 になり詰まる
C5Z001「受注生産品（練習用）」を追加（標準キーの一覧を記録させる）「受注生産という標準キーがある」と思い込む。標準キーの実物を画面で見せて納得させる
C6ZTAK：価格設定 X・納入日程行許可 ON・請求関連 ON・特別在庫 = E納入日程行許可 OFF／特別在庫 E の入れ忘れ。SE16N: TVAP-SOBKZ でも見せる（表で確認する癖）
C7OR + Z001 + （空）+ （空） → ZTAK（代替に TAN）用途・上位明細に何か入れてしまい決定されない。空値もキーであることを強調
C8ZCP：所要量転送 ON・在庫確認 OFF・納入関連 ON・所要量タイプは空所要量転送 OFF → MD04 が空（故障 #1）。所要量タイプに値を入れて自動決定を殺してしまう
C9ZTAK + MRPタイプ PD → ZCPMRP タイプを変えたのに VOV5 に追加しない（将来の落とし穴）

C11KE → 040 の連鎖。OVZI の起点（origin）で戦略グループ優先を確認決定順序を逆に覚える。MD04 で最終確認までやらせる
C12OPPS で 20（KE）／82（KMFA・201・PP04）を確認「20 と 82 の使い分け」を必ず質問される（Q&A #3）
C13品目 MRP3 在庫確認 02、CO09 で要素確認練習用 ZCP は在庫確認 OFF なので、ATP を期待すると混乱する（説明しておく）
C14PD / EX / PP01（発展で PP04）計画手配の在庫区分が受注在庫（E）になっているかを MD04 で確認させる
C15LF / F2 / 出荷ポイント自動決定 / VTFL のコピー制御「出荷ポイントが決まらないと保存できない」を実機で体感させる

練習期待値（解答の要点）採点のポイント
① 受注受注番号採番・明細カテゴリ TAN（または ZTAK）・納期行あり・所要量タイプ KE 系・MD04 に得意先所要量 −10（受注番号付き）・MMBE に受注在庫（E）0 PC の行「MD04 に出たか」が唯一の合格判定。出なければ SD 側（VOV6 の所要量転送 / VOV5 の決定 / VOV7 の納入日程行許可）へ戻す
② MRP・指図計画手配 10 PC（在庫区分＝受注在庫 E・受注番号付き）→ 製造指図 10 PC（受注明細参照・部品予約 20/80・入庫予定が受注在庫）「自由在庫の計画手配」になっていたら MRP4 と所要量クラス。「受注参照の無い指図」は CO08 で作り直させる
③ 出庫・入庫261 で部品 80/420、CO11N で CNF、101 で受注在庫 E = 10 PC・自由在庫は 0、MSKA に SOBKZ=E自由在庫 0 を必ず確認させる。ここが MTO の分水嶺。バックフラッシュとの二重出庫にも注意
④ 出荷・請求出荷明細の在庫区分 E・引当 10 → PGI 601 で受注在庫 0 → 請求 120,000 JPY → 伝票フローで全闭合伝票フローを受講者自身の言葉で読み上げさせる（受注→指図→入庫→出荷→PGI→請求）。FB03 で借貸の方向も確認
⑤ 発展戦略 82 で受注保存と同時に指図生成／ZTAK 切替の決定／KKS1→KO88 の差異と決済／部品の購買連携／取消の逆順2 つ以上実施。「なぜそうなるのか」を説明できたら満点。操作だけでは評価しない

6. 必出質問 Q&A（模範回答つき）

#質問模範回答
1テキストの TAK を使わないのですか？TAK は SAP 標準に存在しません（SAP Note 2708455 が明記）。網上教材の TAK は自建か旧版のものです。本教材は自建 ZTAK（特別在庫 E）で同じことを実現します
2所要量クラスは 040 と 046 のどちらを使うべき？「受注在庫を評価するか」で選びます。評価付なら評価区分 M を持つクラス（S/4HANA Cloud の MTO は 046）。実際に使われるのは品目戦略グループ経由で決まるので、OVZG と MM03 で確認するのが正解
3戦略 20 と 82 の使い分けは？「指図をいつ作るか」です。20＝MRP 実行後に計画手配から変換（一般的な受注生産）、82＝受注保存と同時に指図を自動生成（1:1、組立型・BOM 必須、所要量クラス 201・指図タイプ PP04）
4品目カテゴリグループ 0002 を使うのでは？標準の 0002 は LUMF 系（BOM／設定可能品の構成品目側）で、受注生産専用のキーではありません。普通の MTO は 0001/NORM のままでも成立します。まず IMG の「明細カテゴリグループ定義」で実物を見てください
5MRP タイプ ND にすれば MRP が走らず受注生産になる？逆です。ND は計画なしなので計画手配が生まれず、在庫も作れません。MTO は MRP 対象（PD 等）が前提です
6受注在庫に入れず、自由在庫で運用してはだめ？だめです。自由在庫に入れた時点で他の受注が引当でき、按单生产（MTO）の意味が失われます。按单入库是 MTO 的最小要求
7明細カテゴリだけ／MRP4 だけでも受注在庫になりますか？環境差があります。だから本教材は 3 点セットで確認し、自分のシステムでの実測結果を要件定義に書く、という進め方を取ります（断言せず、実測を優先）
8MRP リストどこですか（MD05）？MRP Live（MD01N）は MRP リストを作りません。MD04（在庫/所要量リスト）または Fiori アプリで見ます（KBA 2640393 参照）
9受注在庫は金額（評価）を持ちますか？設定次第です。所要量クラスの評価区分と品目会計ビューで決まります。Cloud の MTO は評価付が前提。MMBE の金額欄で必ず実測してください
10差異は誰の仕事ですか？差異は製造指図に発生し、KKS1（差異計算）と KO88（決済）で処理されます。SD も「受注在庫が出荷時に売上原価になる」最后一公里を知っておく必要があります
11Public Cloud でも同じ練習ができますか？できません。Cloud では明細カテゴリ・販売伝票タイプの新規作成ができず、SSCUI とスコープアイテム（BJE/IYT/1BM/7DM）の Test Script に従います。本教材は机制理解と差異の把握に使い、実施は Test Script で行ってください

7. 故障の教え方（切り分けの物語）

故障演習は「設定を直す」ことが目的ではありません。症状から層を特定できるようになることが目的です。次の 4 層で必ず声に出して確認させてください。

層問いかけ見る画面 / T-codeここで終わらせる結論
① SD 側需要が MD04 に出ているか？VA03（納期行カテゴリ・所要量タイプ）→ MD04出ていない＝所要量転送／納期行／明細カテゴリの問題（PP を触らない）
② PP 側補貨（計画手配）が出ているか？MM03 MRP1 → MD01N/MD02 → MD04出ていない＝MRP タイプ・手配タイプ・批量・計画対象の問題
③ 在庫区分その補貨は受注在庫（E）か？MM03 MRP4 → OVZG → VA03 の特別在庫自由在庫なら個別所要量の 3 点セットを見直す
④ MM/FI 側在庫は動いたか？ 引当はできたか？ 勘定は出たか？MMBE / MATDOC / VL03N / FB03在庫・引当・転記の問題（指図の受注参照、OBYC 等）
証跡として必ず控えさせる T-code VA03・MD04・MMBE・SE16N（VBAP/VBEP/MSKA/AFPO/MATDOC）・CO03・VL03N・VF03・FB03。 「根因 + 証跡（T-code + 画面/表の行）」の 2 点セットで書かせると、障害票の書き方が身につきます。

8. 評価基準（3 観点）

観点配点合格ライン見方
知識（選択問題）4028 題で 75% 以上（21 問）能力测试。誤答はどの分野（概念/配置/流程/故障）かを見て、戻るページを指示する
実技（証跡）40学员版チェックリストの全項目が証跡つき伝票番号・表の行・画面の要点が記録されているか。「できた」だけの申告は不可
言語化（説明力）20決定链と故障 1 件を、資料を見ずに 3 分で説明できる用語が正確か（所要量転送／所要量クラス／個別所要量／特在 E）
フィードバック文例（そのまま使える） 「受注〜請求は通っています（証跡 OK）。次のステップは説明力です。『この受注の需要は MD04 にどう出て、なぜ受注在庫に入るのか』を、設定画面を開かずに 3 分で話してみてください。 そのあと、故障 #3（自由在庫に入る）を自分で人に説明できるようになれば、このシナリオは卒業です。」
