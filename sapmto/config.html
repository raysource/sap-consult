练习配置手顺（C0〜C17）

关于本页的「画面イメージ」：这些图是按 SAP GUI 标准布局重绘的示意图，不是实机截图。字段名、字段顺序、按钮位置会因版本与自定义而不同，请以自系统的画面为准（各 STEP 的「自系统での確認方法」里写了确认用的 T-code 与表）。若是想换成实机截图，把同名 .png 放进 assets/gui/ 后执行 python3 tools/swap_gui_images.py <site> --apply 即可一键替换。
本页怎么用 每个 STEP 都是「目的 → IMG 路径 / 事务码 → 输入值 → 操作手顺 → 自系统中的确认 → 注意事项 → 练习课题」的固定结构。
① 先确认再新增：和本教程一样的配置通常已经存在，先学会「怎么看到它、怎么读它」，再动手建练习用的 Z 对象；
② 练习用对象命名约定：Z001（明細カテゴリグループ）ZTAK（明細カテゴリ）ZCP（納入日程行カテゴリ）Z040（所要量クラス，仅在需要时）；
③ 所有配置改动都记入你的 カスタマイジング依頼，便于练习后回滚；
④ 标准值随环境不同 —— 每个 STEP 的「确认」栏就是让你在自系统里核对它的方法。 先读完 概念页的决定链 再动手，效率会高很多。

配置前的准备

配置作业会在你的练习系统留下自定义对象。请先确认三件事：① 有可写入的カスタマイジング依頼；② 你的用户能进入 SPRO（SPRO → 「カスタマイジング」→「IMG」）； ③ 练习用的贩卖组织/工厂/得意先/品目编号范围可用。以下每步都会用到 SPRO 的搜索框——直接用事务码跳转比逐层点菜单快，两者都写在手顺里。

C5

明細カテゴリグループの確認と追加

SPRO（IMG）
IMG 路径（日本語）
販売管理 > 販売伝票 > 販売伝票明細 > 定義: 明細カテゴリグループ
目的
明細カテゴリ決定 4 键中的 1 键（来自品目マスタ 販売組織2 的字段）。这里定义的是「组」，本身的字段只有 キー + 説明。
  1. 进入上述 IMG 节点（或 SPRO 搜索框输入「明細カテゴリグループ」）。
  2. 先看现状：记录标准里已有的键（通常可见 0001 标准、0002、0004，以及 NORM/DIEN/LEIS/ERLA/LUMF 这类的文字键）。你系统里到底有哪些，以这一屏为准。
  3. 新增一行：キー Z001、説明「受注生産品（練習用）」。保存到你的カスタマイジング依頼。
背景知识（避免踩坑） 标准里常见的组：NORM（标准品）、DIEN（サービス）、LEIS（納入関連サービス）、ERLA（設定可能製品ヘッダ）、LUMF（設定可能製品の構成品目）。 SAP 并没有一个专门叫「受注生産」的标准组；普通 MTO 用 0001/NORM 也能实现（受注在庫 E 由 MRP3/MRP4 与所要量クラス决定）。 要靠明細カテゴリ来区分受注生産明细时，通常就是像我们这样自建一个组。
C6

明細カテゴリ的确认与新增 ZTAK

VOV7
IMG 路径
販売管理 > 販売伝票 > 販売伝票明細 > 定義: 明細カテゴリ（事务码 VOV7）
目的
决定「这一行明细」的行为：是否定价、是否允许纳期行、是否请求相关、特別在庫区分（E） 等。
  1. VOV7 → 输入 TAN → 「詳細」：先读标准。确认以下项目（字段名可能因版本不同，用 F1 看帮助）：
    ・品目タイプ = 標準品目　・価格設定 = X（標準）　・納入日程行許可 = ON　・請求関連 = ON　・特別在庫 = 空（标准 TAN 不带特在区分）。
  2. 回退到一览 → 光标放在 TAN → 「コピー（Copy as…）」→ 新キー ZTAK、说明「受注生産明細（練習用）」。
  3. 在 ZTAK 中按下列值修改并保存：
品目タイプ            : 標準品目（Material と同じ）
価格設定              : X（標準の価格設定を実施）
納入日程行許可        : ✓（必须。OFF にすると納期行が作られず MRP に需要が届かない）
請求関連              : ✓
特別在庫（SOBKZ）     : E  ← 本练习的核心：明細が受注在庫に紐づく
購買関連 / 構造範囲   : 空 / 空（BOM 参照は使わない）
明細テキスト決定手続  : 任意（例 0001）
完了ルール            : 空
确认（自系统） ① VOV7 → ZTAK → 詳細 を再表示：特別在庫 = E になっている；
② SE16N 里可以核对底层表 TVAP（明細カテゴリ）的 SOBKZ 字段是否为 E（TVAP 确实有 SOBKZ「Special Stock Indicator」字段）；
③ 标准 TAK 是否在你系统里存在？——很多系统没有。SAP Note 2708455 明确说「TAK 不是 SAP 标准定义」，所以本文用自建 ZTAK，避免依赖不存在的标准对象。
术语提醒 日文「特別在庫」/ 中文「特殊库存」在明細カテゴリ画面里控制的是 VBAP-SOBKZ（受注明細的特别库存区分）。 受注在庫的「数量」本身落在 MSKA（特别库存数量表），「需求」落在 VBBE。
C7

明細カテゴリの割当（4 键决定）

VOV4
IMG 路径
販売管理 > 販売伝票 > 販売伝票明細 > 明細カテゴリの割当（VOV4）
决定キー（4 键）
① 販売伝票タイプ（OR）② 品目カテゴリグループ（品目マスタ 販売組織2 = Z001）③ 用途（明細用途，本例 空）④ 上位明細の明細カテゴリ（本例 空）
  1. VOV4 → 进入后先读标准：你会看到类似 OR + NORM + （空）+（空） → TAN 这样的行。理解「4 个字段都是键，空值也参与匹配」。
  2. 「新規エントリ（New Entries）」→ 输入：
    ・販売伝票タイプ OR　② 品目カテゴリグループ Z001　③ 用途 空　④ 上位明細 空 → 明細カテゴリ 自动提案 = ZTAK。
  3. 同一行的「手動選択可能な明細カテゴリ（代替明細カテゴリ）」栏里，把 TAN 也加上（练习时便于手动切换比较）。
  4. 保存。
确认（自系统） ① VOV4 中能看到新行；② 实测才是硬道理：把品目 ZMTO-FG01 的品目カテゴリグループ在 MM02 改成 Z001 → 新建一张受注，明细的明細カテゴリ应自动变成 ZTAK（见 练习⑤ 课题）； ③ 若要退回标准做法，把品目改回 0001 即可（标准 OR + NORM → TAN 仍有效）。
C8

納入日程行カテゴリ的确认与新增 ZCP

VOV6
IMG 路径
販売管理 > 販売伝票 > 販売伝票明細 > 定義: 納入日程行カテゴリ（VOV6）
目的
纳期行是「受注需求进入 MRP 的入口」：所要量転送 决定 MRP 是否看得到；在庫確認（ATP） 决定纳期确认；移动タイプ/購買発注 相关则决定后续物料动作。
  1. VOV6 → 逐一打开 CN、CP，比较这两个标准纳期行类别的项目。把差别记下来（例：CN 偏标准受注（含在庫確認），CP 常被用于「MRP 関連あり・在庫確認なし」的受注纳期）。实际字段值以你系统为准，用 F1 看每个字段的帮助。
  2. 复制 CP → 新键 ZCP、说明「受注生産用納入日程行（練習用）」，按下列要点确认/设置：
所要量転送（BEDSD）      : ON  ← 受注の需要を MRP に渡す（OFF だと MD04 に何も出ない）
                          ※ 選択肢に「同時に組立指図を開始」がある場合、戦略 82（組立処理）ではそれを選ぶ
在庫確認（ATPPR）        : OFF（本练习首要目标是 MRP 需求传递）／想同时练 ATP 则 ON
納入関連（LFREL）        : ✓（出荷対象）
購買発注関連（EBANF 等） : 空（内製のため。外注/第三社処理の練習時のみ ON）
移動タイプ（BWART）      : 空（受注在庫の入出庫は指図側で制御）
所要量タイプ（BDART）    : 空  ← 空にすると「戦略グループ／OVZI」による自動決定が効く
确认（自系统） ① SE16N → TVEP（納入日程行カテゴリの表）→ 输入 ZCP，看 BEDSD / ATPPR / BDART 的值；
② 用 VOV6 的 F1 逐一确认字段含义——这比背值更有用（考试与现场都靠它）。
最容易出错的一步 「所要量転送」被关掉 → 受注保存成功、纳期行也有，但 MD04 里只有受注行、没有需求行、MRP 不动。这是 MTO 练习中最常见的第一个故障，排障流程见 故障对照表。
C9

納入日程行カテゴリの割当（2 键决定）

VOV5
IMG 路径
販売管理 > 販売伝票 > 販売伝票明細 > 納入日程行カテゴリの割当（VOV5）
决定キー
① 明細カテゴリ（ZTAK）② MRPタイプ（品目マスタ MRP1 = PD）
  1. VOV5 → 先读标准：找到 TAN 的行，看它指向哪个纳期行类别（常见的默认组合会涉及 CN/CP，具体以你系统为准）。
  2. 新增：明細カテゴリ ZTAK + MRPタイプ PD → 納入日程行カテゴリ ZCP。保存。
  3. 顺便记录：若同一品目将来改用别的 MRP タイプ（如 VB），需要在 VOV5 里补对应行，否则纳期行会取到默认或空白类别。
确认（自系统） 受注明细保存后，在 VA03 → 明細 → 納入日程行 里确认用到的是 ZCP（而不是标准 CN）——这就是 C6/C7/C8/C9 四步配置的成果。
C10

所要量クラス的确认（MTO 的开关面板）

OVZG
IMG 路径
販売管理 > 基本機能 > 在庫確認と所要量転送 > 所要量転送 > 所要量クラスの定義（OVZG）
目的
所要量クラス才是真正装开关的地方：所要タイプ（独立/得意先所要量）、個別在庫（E）、MRP への転送、在庫確認、評価区分、原価計算の要否。
  1. OVZG → 显示（或経由 SPRO 进入「所要量クラス」节点）→ 用 F4 或直接输入编号查看 040（受注生産の代表）与 046（評価付販売伝票在庫、S/4HANA Cloud の MTO シナリオで使われる）。
  2. 逐项读并记录：
    ・所要タイプ / 計画タイプ（得意先所要量か、独立所要量か）
    ・個別在庫（特別在庫 E を使うか）
    ・MRP への転送（所要量が MRP に見えるか）
    ・在庫確認（ATP を起動するか）
    ・評価区分（評価付 or 評価なし。評価付なら M＝販売伝票参照の個別評価）
    ・原価計算（B＝自動原価計算/マーキング 等）
  3. （可选练习）复制 040 → Z040，说明「受注生産（練習用）」，把「個別在庫」与「評価」按你想验证的方向调整后保存；之后在 C11 里让所要量タイプ指向它。
确认（自系统） ① 打开 040 时能否看到「個別在庫」相关项目？这就是受注在庫是否成立的根因之一；
② 若你的目标是「受注在庫要带金额」，请优先选择带評価区分 M 的所要量クラス（S/4HANA Cloud 的 MTO 用 046）；
③ 找不到 046？在 OVZG 的列表里用 F4 浏览全部条目——不同版本/激活的解决方案会不一样。
版本差异（重要） 本教程无法替你断言「你的系统里受注生産用的一定是 040」。标准值会随版本与已激活业务功能变化；能确认的方法、以及确认后该怎么用（例如让品目戦略グループ指向带個別在庫的所要量タイプ）才是要掌握的东西。
C11

所要量タイプ与它的决定顺序

OVZG・OVZI
IMG 路径
販売管理 > 基本機能 > 在庫確認と所要量転送 > 所要量転送 > 所要量タイプの定義（OVZG 同一区域）／ 明細カテゴリと MRP タイプを使用した所要量タイプの決定（OVZI）
决定顺序（务必记住）
① 优先看品目マスタの戦略グループ（MTO は 20 → 所要量タイプ KE）； ② 若没有戦略グループ，才用 OVZI 的 明細カテゴリ + MRP タイプ 组合决定。
  1. 打开 KE（受注生産の所要量タイプ）→ 确认它指向的所要量クラス（通常 040）与说明。记录「KE → 040（→ 個別在庫 / 評価の設定）」这一条链。
  2. 打开 OVZI → 观察标准的决定表：行键是「明細カテゴリ + MRPタイプ」，列里有所要量タイプ与「起点（origin）」类项目（值常见 0/1/2，控制「用这里的所要量タイプ」还是「交给戦略グループ决定」）。
  3. 找到与 TAN 相关的行，读它指向的所要量タイプ与起点；再找与我们练习相关的行（若 ZTAK 尚未出现在此表中，说明标准路径下它仍会先看戦略グループ——这正是我们要的）。
  4. （可选）为 ZTAK 追加一行：明細カテゴリ ZTAK + MRPタイプ PD → 所要量タイプ KE、起点 = 「戦略グループから決定」类。保存。这一行保证即使将来品目没有戦略グループ，也能拿到受注生産用の所要量タイプ。
确认（自系统） 受注保存后，在 VA03 明細詳細 → 納入日程行 的項目里能看到所要量タイプ；再对照 MM03 MRP3 の戦略グループ 20。两者能串起来（20 → KE）就说明你理解了这一层。
最直观的验证仍是 MD04：出现「得意先所要量」＝所要量転送成功；其数值与受注数量一致＝所要量タイプ/クラス的传递正确。
C12

計画方針グループ／計画方針（20 与 82）

OPPJ・OPPS
IMG 路径
生産 > 資材所要量計画 > 計画 > 需要管理 > 計画方針 > 計画方針の定義（OPPS）／計画方針グループの定義（OPPJ）
目的
品目マスタ MRP3 上填的是戦略グループ（可包含多个計画方針），系统据此选出所要量タイプ。MTO 主线用 20；组立处理用 82（练习⑤）。
  1. OPPS → 输入 20 → 确认它分配的所要量タイプ（通常 KE）与说明「受注生産（組立指図なし）」。同时确认该方針不使用計画独立所要量（PIR 不参与）。
  2. OPPJ → 输入 20 → 确认它包含的方針（通常就是 20 本身）。
  3. 查看 OPPS 的 82（組立処理）：标准设定为 所要量タイプ KMFA / 所要量クラス 201 / 指図タイプ PP04（SAP Help「Special Settings for Production Orders」明确列出）。练习⑤ 会用它做「受注保存 → 指図自动作成」。
确认（自系统） 在 OPPS 用 F4 一览看到 20/25/82 等方針与它们的所要量タイプ对应关系，截图/记录即可（现场要件定义时常被问到「你们用哪个戦略」）。
C13

在庫確認（ATP）

品目マスタ MRP3 + 所要量クラス
目的
让受注保存时（或手动）能给出「能否在希望纳期交货」的答复。MTO 的 ATP 基础是個別所要量（自己这张受注的需求 vs 自己这张受注的入库）。
  1. 品目 ZMTO-FG01 的 MRP3「在庫確認」设为 02 一类（個別所要量ベース。具体值用 F4 看帮助文本，选择描述里含「個別所要量」的项）。
  2. 确认所要量クラス（C10）里在庫確認是激活的（若关闭，纳期行不会做 ATP）。
  3. 确认检查范围/检查规则（在庫確認グループ/チェックルール的设定），决定「哪些要素参与检查」（例：是否把受注在庫 E 的入库预定、计划手配算作可用量）。
  4. 实战确认：CO09（在庫確認概要 / ATP 一覧）输入品目 ZMTO-FG01 / プラント 1000，看可用量与要素明细。
确认（自系统） 受注保存后，纳期行应有「確認済納入日付」。若纳期行为空或提示「在庫確認なし」，回到 MRP3 的在庫確認字段与所要量クラス两处检查。
注意：本教程的 ZCP 默认关掉了在庫確認（先聚焦 MRP 需求传递）；要练 ATP 时把它打开再测一次，体会两者差别。
C14

MRP タイプ・ロットサイズ・指図タイプ（PP 側の確認）

品目マスタ MRP1/MRP2
MRPタイプ      : PD（MRP 対象。ND は「計画なし」で受注生産には不適）
ロットサイズ   : EX（ロット単位＝受注数量単位で手配）
手配タイプ     : E（内製）  ※ F＝外部調達、X＝両方
指図タイプ     : PP01（標準の製造指図タイプ）※ 受注明細参照の指図は CO08 / 計画手配の変換で作成

确认（自系统） MRP 実行後に MD04 を見て、計画手配が生成され、その「在庫区分」が受注在庫（E）になっているかを確認（指定した受注番号・明細が付いている）。 ここで自由在庫（プラント在庫）用の計画手配になっていたら、C2 の MRP4 個別/包括所要量 と C10 の所要量クラス（個別在庫）を疑います。
C15

出荷・請求の前提（确认即可）

VL01N・VF01・VTFL
  1. 出荷：VL01N 能选择出荷タイプ LF；品目/得意先/プラントから出荷ポイントが決定されること（決定されないと出荷伝票が保存できない）。
  2. 出荷の制御：VL02N 里能完成「ピッキング数量入力 → 出庫確認（PGI）」；PGI 的移動タイプは标准为 601（受注在庫 E からの出庫）。
  3. 請求：VF01 的請求タイプ F2 可用；コピー制御（VTFL，出荷伝票 → 請求伝票）已激活，且请求类型为「伝票（伝票関連請求）」。
确认（自系统） 最省事的做法：先在练习① 建出受注，练习②③ 完成入庫，练习④ 做 VL01N → VL02N（PGI）→ VF01，全程不报错即说明这些「确认」都通过。请按顺序做，不要跳步——出荷前没有受注在庫，PGI 一定会失败。
C16

自動転記（OBYC）与受注在庫的会计

OBYC・FB03
受注在庫への入庫（101）  : 在庫勘定（BSX）が借方 → 受注在庫が評価される場合、金額が在庫に載る
出庫確認（601/PGI）      : 売上原価（消費）→ 勘定は OBYC の GBB（汎用変更）系で決定
差異（標準 vs 実績）      : 指図決済（KO88/CO88）と差異計算（KKS1 系）で処理
確認の仕方               : 练习④ で PGI 後の伝票番号から FB03 で会計伝票を開き、勘定/金額を見る
  1. OBYC → 查看 BSX（在庫勘定）与 GBB（消費・差異）的现有设定（一般已由项目配好）。看不懂没关系，先确认「有设定」。
  2. 练习④ 里把 FB03 打开，确认受注在庫的入库/出库都有会计传票，且金额能连上（受注在庫入庫金额 → 出库时的销售成本）。
范围声明 本教程主目标是打通 SD×PP×MM 的流程，会计侧只做「看得懂、验证得到」的深度。若你的目标是「受注在庫の評価・差異分析」深化，请在 练习⑤ 之后追加 CO 模块的专题练习。

C17 Public Cloud（S/4HANA Cloud Public Edition）差异对照

Public Cloud 的核心差别是「你不能做自定义，但 SAP 已经按 スコープアイテム 交付了 MTO 场景」。对照下表落到具体做法：

本教程的 STEPOn-Premise（本站主线）Public Cloud 的做法 / 限制
整体配置手段SPRO / IMG（传输请求）Configure Your Solution の SSCUI（自助配置）＋ スコープアイテム 激活。伝票タイプ・明細カテゴリ・所要量クラス などの新規作成はできない（提供された範囲のみ）
场景交付自己配为主スコープアイテム で交付：BJE（受注生産：完成品販売と最終組立）、IYT（受注生産 + バリアント設定）、1BM（受注生産：半製品計画と組立）、7DM（アドバンスド社内販売 + MTO + VC）。先读 Test Script，它是手上要照做的「手顺」
C6〜C9（明細カテゴリ・纳期行类别）VOV7/VOV4/VOV6/VOV5 自由新增新規作成は不可（What you see is what you get）。可用的 SSCUI（例：SSCUI 105120「明細カテゴリ別の所要量タイプ決定」）只允许在既有明細カテゴリ上调整映射；SAP 不会为单个租户改动 TAN 的标准映射
