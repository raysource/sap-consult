能力测试（28 题 + 实机验收）

用法 每题点击一个选项即判分并显示解说，页面顶部显示累计成绩。合格判定：正确率 ≥75%（21/28）+ 实机验收清单全部勾上。 60〜74% 请回对应页面重读；<60% 请从 概念与设计 重来一遍。
解说里的标准值同样是「通常情况」——考试式的死记没有意义，要能说出「怎么在系统里验证」。

一、概念（1〜10）

概念MTO 的本质

1. SAP 的「受注生産（MTO）」与見込生産（MTS）最本质的差别是？

A. 受注生産不需要跑 MRP
B. 受注生産不能按标准价格评价
C. 需求与库存按「受注明細」切分（得意先個別在庫・特別在庫区分 E）
D. 受注生産只能用戦略グループ 82
MTO 的核心是「按单切分」：需求（得意先所要量）与库存（受注在庫 E）都挂在受注明細上，别的受注不能占用。MRP 照跑（战略 20），评价与否取决于所要量クラス（战略 82 只是「何时建指图」的另一选项）。
概念特別在庫

2. 特别库存区分 E 指的是？

A. 外注先預託在庫（下請在庫）
B. 得意先個別在庫（受注在庫・sales order stock）
C. プロジェクト在庫
D. 返品在庫
E = 得意先（受注）ごとの個別在庫で、受注番号 + 明細番号に紐づきます。数量は MSKA、集計は VBBS、所要は VBBE で確認できます（Q = プロジェクト在庫、K = 預託在庫）。
概念戦略グループ

3. 戦略グループ 20（受注生産）について正しいのは？

A. 受注を起点に計画し、計画独立所要量（PIR）は使わない
B. PIR を登録しないと計画手配が生まれない
C. 受注保存と同時に製造指図が自動作成される
D. 自由在庫で運用するので個別在庫は不要
战略 20 = 受注を起点，不使用 PIR（这就是 MTO 与 MTS 的计划起点差异）。「受注保存と同時に指図」是战略 82（組立処理）的特征。
概念E 特在の成立条件

4. 受注在庫（E）を成立させるために必要なのは、次のうちどれ？

A. 品目マスタの MRP タイプを ND（計画なし）にする
B. 明細カテゴリの「納入日程行許可」を OFF にする
C. 納入日程行カテゴリの在庫確認を必ず ON にする
D. 品目マスタ MRP4 の「個別/包括所要量」を個別所要量にし、所要量クラスに個別在庫の設定があり、明細カテゴリで特別在庫 E を持つ
三方都要到齐：① MRP4 個別所要量（数量的区分）② 所要量クラス（個別在庫・評価・MRP 転送的规则）③ 明細カテゴリの特別在庫 E（VBAP-SOBKZ）。ND は計画手配を生まないので論外，納入日程行許可 OFF は需要が MRP に届かなくなります。
概念決定の順序

5. 所要量タイプ（requirement type）の決定順序として正しいのは？

A. 必ず明細カテゴリ + MRP タイプで決まる（戦略グループは使われない）
B. まず品目マスタの戦略グループから決定し、戦略グループが無い場合に明細カテゴリ + MRPタイプ（OVZI）で決定する
C. 販売伝票タイプだけで決まる
D. 出荷タイプと請求タイプで決まる
SAP Help「Determination of the Requirements Type」：まず品目マスタの戦略グループから所要量タイプを決定。フォールバックとして OVZI（明細カテゴリ + MRPタイプ）があり、「起点（origin）」列の値でどちらを使うかを制御します。
概念明細カテゴリの決定

6. 明細カテゴリを決定する 4 つのキーとは？

A. 販売組織 + 販売チャネル + 部門 + 得意先
B. 明細カテゴリ + MRP タイプ
C. 販売伝票タイプ + 品目カテゴリグループ + 用途 + 上位明細の明細カテゴリ
D. 品目タイプ + プラント + 保管場所 + 品目グループ
4 键来自 VOV4 的设置：販売伝票タイプ + 品目カテゴリグループ（品目マスタ 販売組織2）+ 用途 + 上位明細の明細カテゴリ。空字段也参与匹配。B 是納入日程行カテゴリ的决定键（VOV5）。
概念納入日程行カテゴリ

7. 受注の需要が MRP（MD04）に伝わるかどうかを決めるのは？

A. 納入日程行カテゴリの「所要量転送」
B. 明細カテゴリの「価格設定」
C. 販売伝票タイプの番号範囲
D. 品目マスタの品目グループ
需求传递的开关落在納入日程行カテゴリ（VOV6）：所要量転送（TVEP-BEDSD）。在庫確認（ATPPR）与移動タイプ也在同一个对象上控制。
概念所要量クラス

8. 所要量クラス（requirements class）がコントロールしないものは？

A. 個別在庫（特別在庫 E）を使うか
B. MRP への所要量転送
C. 在庫確認の要否・評価区分
D. 明細の単価（価格条件 PR00 の金額）
金额来自价格条件（V/06/V/08/VK11），与所要量クラス无关。所要量クラス控制的是需求种类、个别库存、MRP 连携、ATP、评价、原价计算等「需求的下游行为」。
概念S/4HANA

9. SAP S/4HANA Cloud Public Edition の MTO シナリオで前提とされる受注在庫の扱いは？

A. 非評価の受注在庫（金額を持たない）
B. 評価付の販売伝票在庫（所要量クラス 046・評価区分 M など）
C. 受注在庫は使わず、自由在庫で代替する
D. プロジェクト在庫（Q）に置き換える
SAP Help（Cloud・Production Accounting）的 MTO 场景以「評価付販売伝票在庫」为前提：MRP4 を個別所要量にし、所要量クラスで評価区分 M・原価計算 B（例 046）を使い、製造指図で原価を集めて分析します。
概念組立処理

10. 戦略グループ 82（組立処理）の標準的な組み合わせは？

A. 所要量タイプ KE / 所要量クラス 040 / 指図タイプ PP01
B. 所要量タイプ KEK / 所要量クラス 046 / 指図タイプ PP01
C. 所要量タイプ KMFA / 所要量クラス 201 / 指図タイプ PP04
D. 所要量タイプ LSF / 所要量クラス 010 / 指図タイプ PP01
SAP Help「Special Settings for Production Orders」明确列出：戦略グループ 82 → 所要量タイプ KMFA、所要量クラス 201、指図タイプ PP04（静的手法＝指図と受注 1:1）。KEK/046 是 VC 的受注生産（战略 25）方向。

二、配置（11〜20）

配置品目マスタ

11. 品目カテゴリグループ（明細カテゴリ決定のキー）はどのビューにある？

A. 販売組織ビュー2
B. MRP1
C. 会計ビュー1
D. 基本データ1
在 販売組織ビュー2（它是按销售区域维护的，所以同一品目在不同销售组织可以表现不同）。MM01/MM02/MM03 的 販売組織2 画面可以查看。
配置品目マスタ

12. 「個別/包括所要量」を設定するのはどのビュー？

A. 販売組織1
B. MRP1
C. MRP3
D. MRP4
MRP4 的「個別/包括所要量」＝ 個別所要量のみ にすると、その品目的需求与库存按受注区分（＝E 特在的前提）。MRP3 上是 戦略グループ、在庫確認。
配置T-code

13. 明細カテゴリの定義を行うトランザクションは？

A. VOV4
B. VOV7
C. VOV5
D. VOV6
VOV7 = 明細カテゴリの定義、VOV4 = 明細カテゴリの割当（4 键）、VOV6 = 納入日程行カテゴリの定義、VOV5 = 納入日程行カテゴリの割当（2 键）。
配置T-code

14. 明細カテゴリと MRP タイプから所要量タイプを決定する設定は？

A. OPPS
B. OVZG
C. OVZI
D. OPJH
OVZI 的 IMG 路径是 販売管理 > 基本機能 > 在庫確認と所要量転送 > 所要量転送 > 明細カテゴリと MRP タイプを使用した所要量タイプの決定。 OVZG 是所要量タイプ/クラス的定義、OPPS 是計画方針の定義。若 OVZI 里要加新行却报错，注意 SAP KBA 2197844 的说明。
配置標準の状況

15. 明細カテゴリ TAK について正しい記述は？

A. SAP 标准系统并没有定义 TAK（SAP Note 2708455），很多项目自己建同名对象
B. TAK 是受注生産の標準明細カテゴリで、必ず存在する
C. TAK は在庫管理不可能なサービス用の明細カテゴリ
D. TAK は販売伝票タイプの標準値で、明細カテゴリではない
SAP Note 2708455 的标题就是「Item category TAK (make-to-order) is not defined in the standard SAP system」。所以本教程用自建的 ZTAK（带 特別在庫 E）来做配置练习，不依赖不存在的标准对象。
配置明細カテゴリの項目

16. 明細カテゴリの定義（VOV7）で、受注在庫に直結する項目は？

A. 価格設定
B. 完了ルール
C. 請求関連
D. 特別在庫（SOBKZ）
明細カテゴリ表 TVAP 里有 SOBKZ（Special Stock Indicator）字段，设成 E 就表示这条明细走受注在庫（受注明細 VBAP-SOBKZ）。所要量転送/在庫確認则落在納入日程行カテゴリ（TVEP-BEDSD/ATPPR）。
配置品目カテゴリグループ

17. 明細カテゴリグループについて正しいのは？

A. 標準には「受注生産」という専用キーがあり、MTO では必ずそれを使う
B. 標準値（NORM、DIEN、LEIS、ERLA、LUMF など）には MTO 専用のものが無く、必要なら自建する。普通の MTO は 0001/NORM のままでも実現できる
C. 品目カテゴリグループは SAP が固定しており、追加できない
D. 品目カテゴリグループは伝票タイプの一種である
它是 VOV4 的一个决定键（来自品目マスタ 販売組織2），本身只有 キー + 説明 两个字段，可以自建。受注在庫の成否主要由 MRP4 個別所要量 与 所要量クラス 决定，所以 NORM ままでも MTO は成立します。其标准值的实际内容请在自己系统里用 IMG「定義: 明細カテゴリグループ」确认。
配置計画方針

18. 計画方針／計画方針グループを定義・確認するトランザクションは？

A. OPPS（計画方針の定義）/ OPPJ（計画方針グループの定義）
B. OVZG / OVZI
C. VOV4 / VOV5
D. OBYC / OMS2
戦略グループ → 計画方針 → 所要量タイプ 的链条在 PP 侧用 OPPS（方針）与 OPPJ（方針グループ）维护；OVZG/OVZI 是 SD 侧的所要量タイプ／クラス一侧。
配置Public Cloud

19. SAP S/4HANA Cloud Public Edition でできないことは？

A. 所要量タイプの決定（明細カテゴリ別）を SSCUI で調整する
B. スコープアイテム BJE / IYT を有効化して MTO プロセスを使う
C. 新しい明細カテゴリや販売伝票タイプを自由に作成する
D. MRP Live ベースのアプリで資材所要量計画を実行する
Public Cloud 的基本规则是「What you see is what you get」：新規の明細カテゴリ／販売伝票タイプは作成できず、SSCUI で調整できる范围内の操作になります（例：SSCUI 105120「明細カテゴリ別の所要量タイプ決定」）。MTO 场景通过 scope item（BJE/IYT/1BM/7DM）交付。
配置納入日程行カテゴリ

20. 納入日程行カテゴリの標準的な設定項目に含まれないものは？

A. 所要量転送（BEDSD）
B. 在庫確認（ATPPR）
C. 移動タイプ（BWART）・購買発注タイプ
D. 品目カテゴリグループ
品目カテゴリグループは品目マスタ（販売組織2）侧的字段，用于明細カテゴリの決定，不在納入日程行カテゴリ上。納入日程行カテゴリ（表 TVEP）控制的是所要量転送・在庫確認・移動タイプ・購買関連・所要量タイプ等。

三、流程（21〜26）

流程受注直後

21. 受注を保存した直後に、最初に確認すべきことは？

A. 製造指図ができているか
B. 明細カテゴリ／納入日程行カテゴリ／所要量タイプ、そして MD04 に得意先所要量が出ているか
C. 請求伝票ができているか
D. 受注在庫が入庫されているか
顺序上：受注保存 → 明细属性与所需量传递（MD04 得意先所要量）→ MRP → 指图 → 入库 → 出荷 → 请求。受注直後に指図や在庫を期待するのは、战略 82（組立処理）か、手動で作った場合だけです。
流程指図と受注の紐づけ

22. 完成品が受注在庫（E）へ入庫されるために必須なのは？

A. 出荷伝票を先に作っておくこと
B. MRP を 2 回以上実行すること
C. 製造指図が受注明細を参照していること（CO08 または計画手配からの変換）
D. 受注在庫を評価なしに設定すること
入庫先（受注在庫）は指図側が持つ情報です。CO01 など受注参照のない指図は自由在庫に入庫されます（表层面是 AFPO-KDAUF/KDPOS 为空）。
流程MRP

23. S/4HANA の MRP Live（MD01N）について正しいのは？

A. MRP リストは作成されないので、結果は MD04 などで確認する
B. 結果は MD05 の MRP リストで確認する
C. MRP Live では受注在庫が使えない
D. MRP Live は単品目 MRP であり、プラント全体は処理できない
MRP Live 不生成 MRP 列表（MD05/MD06 系），要看 MD04（或 Fiori 的库存/需求清单应用）。它也能处理计划范围/工厂级别的计划，并非只能单品目（MD02 才是单品目 MRP 的入口）。
流程移動タイプ

24. MTO の主要な移動タイプの組み合わせとして正しいのは？

A. 261＝完成品入庫 / 101＝部品出庫 / 601＝在庫転送
B. 261＝指図への部品出庫 / 101＝指図への完成品入庫 / 601＝出荷の出庫確認
C. 101＝部品出庫 / 601＝完成品入庫 / 261＝返品
D. 301＝部品出庫 / 101＝入庫 / 601＝請求
261 = 指図（製造）への出庫、101 = 指図/購買発注への入庫、601 = 出荷（PGI）の出庫。受注在庫（E）は 101 で増え、601 で減ります。
流程出荷引当

25. 出荷伝票で「引当数量 0」になる典型的な原因は？

A. 請求伝票がまだ作られていない
B. 受注明細の数量が大きすぎる
C. 出荷タイプが LF である
D. 受注在庫（E）に在庫が無い（入庫漏れ・保管場所違い・既に他で消費）
出荷引当的候选是「该受注明細的受注在庫」。MMBE で受注在庫の数量と保管場所を确认 → 無ければ指図の入庫（101）をやり直します。
流程取消

26. 請求まで完了した伝票を巻き戻すときの正しい順序は？

A. PGI 取消 → 請求取消 → 入庫取消
B. 入庫取消 → 実績取消 → PGI 取消 → 請求取消
C. 請求取消（VF11）→ PGI 取消（VL09）→ 入庫取消（MIGO/MBST）→ 実績取消（CO13）
D. 指図を削除すれば後続伝票は自動で消える
取消必须「逆順」：先在请求侧取消（VF11），再取消 PGI（VL09），再取消入库（MIGO取消/MBST），再取消报工（CO13），最后处理指图。顺序反过来会因后続伝票存在而报错。

四、故障（27〜28）

故障MD04

27. MD04 に受注の需要が出ているが、計画手配が生成されない。次に疑うのは？

A. 出荷タイプや請求タイプの設定
B. 品目マスタの MRP タイプ／手配タイプ／批量（＝MRP の対象になっているか）
C. 得意先マスタの与信管理
D. 価格条件レコードの有効期間
需求到了 MD04（＝SD 侧成立），但补货元素出不来，问题在 PP 侧的品目设置：MRPタイプ（PD 等）、手配タイプ（E）、ロットサイズ、MRP 対象プラント/エリア。用 MD02 单品目跑一次看结果日志最快。
故障受注在庫にならない

28. 計画手配・製造指図はできたが、入庫が自由在庫に入ってしまう。第一嫌疑は？

A. 品目マスタ MRP4 の「個別/包括所要量」が個別所要量になっていない（または所要量クラスに個別在庫の設定がない／明細の特別在庫が空）
B. 出荷ポイントが決定されていない
C. 請求タイプが F2 でない
D. 保管場所が 0001 でない
「自由在庫に入った」＝ 系統认为这个需求不是个别需求。检查顺序：MM03 MRP4 → OVZG 所要量クラス（個別在庫）→ VA03 明細の特別在庫 E（C2/C10/C6）。修正后新建受注重跑流程最干净。

实机验收清单（合格必须全勾）

✓ 総合验收（把系统里的证据按顺序摘出来，交作业即可）
  • 配置：VOV7 の ZTAK（特別在庫 E）・VOV4 の OR + Z001 → ZTAK・VOV6 の ZCP（所要量転送 ON）・VOV5 の ZTAK + PD → ZCP の 4 点の画面（または SE16N の表証跡）。
  • 主数据：MM03 の 販売組織2 品目カテゴリグループ / MRP3 戦略グループ 20 と在庫確認 / MRP4 個別・包括所要量 の画面。
  • 受注：受注番号 + VA03 の 明細カテゴリ/納入日程行カテゴリ/所要量タイプ + MD04 の「得意先所要量 −N PC（受注番号付き）」。
  • MRP/指図：MD04 の計画手配（在庫区分＝受注在庫）または CO03 の受注明細参照 + 構成品目（数量）。
  • 製造：261 出庫と 101 入庫の物料传票番号 + MMBE の受注在庫（E）数量。
  • 販売：出荷伝票（在庫区分 E）+ PGI 後の受注在庫 0 + 請求伝票の金額。
  • 伝票フロー：VA03 → 環境 → 伝票フロー で 受注 → 指図 → 入庫 → 出荷 → 請求 が全部つながった画面。
  • 故障：この実習中に発生した問題を 1 つ以上、症状 / 根因 / 证据 T-code の 3 点で記述した。
合格判定 選択問題 ≥75%（21/28）＋ 上記実機验收清单 全項目が証跡つきで説明できること。 両方満たしたら、この「SD 受注生産（MTO）」场景已经是可以讲给别人听的水平了——下一步建议把它扩到受注設計生産（ETO/PS）或バリアント設定付き受注生産（VC），那两条路可以复用本站在这里打下的全部基础。
