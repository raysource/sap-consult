概念与设计：MTO 到底改了什么

本页要带走的三句话 ① MTO 的本质 = 需求与库存按「受注明细」切分（＝特別在庫区分 E、受注在庫）； ② 切分是靠一条配置链实现的：品目マスタ（戦略グループ 20）→ 所要量タイプ KE → 所要量クラス 040/046 → 個別在庫 E， 　明細カテゴリ（VOV7 の 特別在庫 E）と納入日程行カテゴリ（VOV6 の 所要量転送）是把 SD 的传票接进这条链的两个入口； ③ 只要链上任一环缺失，症状一定出现在 MD04 / MMBE / 出荷の引当 / 受注在庫の評価 这四处。
（本页出现的标准值都以「通常情况」表述，请用各页给出的手顺在你自己的系统里确认。见 关于标准值的立场。）

2. 得意先個別在庫（特別在庫区分 E）

「特別在庫（special stock）」是 SAP 库存的一层附加区分。受注生産用的是 E：得意先個別在庫（sales order stock / 受注在庫）—— 库存数量不属于工厂自由库存，而是挂在受注番号 + 明細番号上。具体差别：

视角自由在庫（MTS）受注在庫 E（MTO）
数量归属性工厂/保管場所単位受注番号 + 受注明細単位（他の受注には使えない）
需求来源PIR（MD61）+ 受注受注の得意先所要量のみ（PIR は使わない）
库存一览MMBE / MB52 のプラント在庫MMBE / MB52 の「受注在庫／特別在庫」欄、MSKA（後述の表参照）
入出库101 / 261 / 601（自由在庫）101 入受注在庫（指図の受注明細参照が必要）、601 出荷時に E 在庫から引き落とし
評価（＝会计金额）通常の評価（標準価格/移動平均）受注在庫として評価するかどうかは設定次第。S/4HANA Cloud の MTO シナリオは評価付（所要量クラス 046、評価区分 M）が前提
会計影響在庫勘定（BSX）受注在庫勘定／仕掛（WIP）→ 出荷時に売上原価へ、差異は指図決済で処理
名称の揺れ（日本語現場で混ざる） E 特在 ＝受注在庫＝得意先個別在庫＝販売伝票在庫＝個別在庫。英語では sales order stock / individual customer stock。 要項クラスの項目名では「個別在庫」「特別在庫」と訳されることがあります。同じものを指しているので、画面では区分 E と受注番号が付いているかで判断してください。

4. SD 侧三个对象的分工（配错了症状各不相同）

对象层级决定方式它控制什么（与受注生産有关的部分）配错的典型症状
販売伝票タイプ（VOV8）传票头用户选择 / 参照传票种类（受注 OR / 見積 / 契約）、番号範囲、全体动作明細无法输入、无法参照出货

5. 所要量タイプ／所要量クラス（MTO 的心脏）

项目作用MTO 的典型值在哪里看／改
所要量タイプ（requirement type）把受注需求「翻译」成 MRP 看得懂的需求种类KE（受注生産・組立指図なし）／KMFA（組立処理）／KEK（VC）OVZG（定義）、OVZI（明細カテゴリ+MRPタイプによる決定）、品目マスタ戦略グループ経由
所要量クラス（requirement class）真正装开关的地方：所要タイプ（得意先所要量）、個別在庫、MRP 転送、在庫確認、評価、原価計算040（受注生産）／046（評価付販売伝票在庫。S/4HANA Cloud の MTO）／201（組立処理）OVZG（IMG：販売管理 > 基本機能 > 在庫確認と所要量転送 > 所要量転送）
計画方針グループ（strategy group）品目マスタから「どの戦略（＝どの所要量タイプ）を使うか」を引く鍵20（受注生産）／25（VC 受注生産）／82（組立処理）品目マスタ MRP3；定義は OPPJ / OPPS
所要量タイプの決定順位①まとめ品目マスタの戦略グループ → ②（戦略グループが無い場合）明細カテゴリ + MRPタイプ（OVZI）—OVZI（「所要量タイプの起点」列の値で制御）
実機での確認手順（覚えておくと便利） 受注明細を保存 → VA03 → 明細行 → ダブルクリックで明細詳細 → 「納入日程行」タブ → 右側の項目に所要量タイプと所要量クラスが表示されます（表示されない場合は項目の表示設定／ユーザパラメータを調整）。 さらに MD04 を見れば「その所要量が実際に MRP に届いたか」が一目で分かります＝所要量転送の最終確認は MD04。

8. 十个常见误解（也是测试题的重点）

  1. 「受注生産 就用 明細カテゴリグループ 0002」——不准确。0002（LUMF）在标准里属于 BOM／可配置品相关的组（ERLA 是头品、LUMF 是组件侧）。 平时的 MTO 做法是品目カテゴリグループ维持 0001（NORM），靠 戦略グループ 20 + 個別所要量 实现 MTO；要靠明細カテゴリ区分时再自建 Z001/ZTAK。
  2. 「TAK 是 SAP 标准明細カテゴリ」——不是。SAP Note 2708455 明确：Item category TAK (make-to-order) is not defined in the standard SAP system。很多教材里的 TAK 是项目自建或旧版遗留。
  3. 「只要品目マスタ MRP4 设成個別所要量就行」——不够还要（a）所要量クラス有個別在庫的设定、（b）明細カテゴリの特別在庫 E（或等价的决定路径）。三点齐全才是完整的 E 特在。
  4. 「加个 MRP タイプ ND 就不跑 MRP，正好做受注生産」——错。ND（計画なし）会让你的受注需求产生不了计划订单。MTO 需要 MRP 対象（如 PD）。
  5. 「受注在庫は必ず評価される」——取决于设定（所要量クラスの評価区分）。S/4HANA Cloud 的 MTO 场景是評価付前提（046 / 評価 M）；On-Premise 用 040 系时可能是非評価。
  6. 「在庫は自由在庫に入っても、出荷時に受注へ引き当てれば同じ」——不可。自由在庫に 101 入庫した時点で别的受注也能抢占，MTO 的「按单」就失效了。
  7. 「所要量転送（納入日程行カテゴリ）は既定で ON」——不一定。很多自建纳期行类别会关掉在庫確認或所要量転送；症状是 MD04 里什么都看不到。
  8. 「MRP 跑完就一定有计划订单」——还要看純所要量（在手库存、入库预定、批量）、手配タイプ（E/F/X）、ロットサイズ、以及その所要量が MRP 対象か。
  9. 「CO08 与 CO01 一样，只是多输个受注」——CO08 的意义正是与受注明細建立关联；用 CO01 建出来的指图不会自动落到受注在庫。
  10. 「差异只有财务关心」——MTO 的差异（標準原価 vs 実績）产生在指图上，KKS1/KO88 处理结果直接影响受注在庫出货时的销售成本。SD 顾问也要看得懂这最后一公里。
