# gui_spec.json の書き方（SAP GUI 画面イメージの仕様ファイル）

`tools/make_gui_mockups.py <site>` は `<site>/tools/gui_spec.json` を読み、SAP GUI 風の SVG を
`<site>/assets/gui/` に生成して、手顺ページの該当ステップへ `<figure class="gui">` を挿入します。

**生成物は実機のスクリーンショットではありません。**標準レイアウトに基づく再現イメージです。
実機で撮った画像に差し替えるときは、同じファイル名で `.png` を置き
`python3 tools/swap_gui_images.py <site> --apply` を実行してください（`src` の拡張子を一括で書き換えます）。

## トップレベル

```json
{
  "pages": {
    "config.html":     { "<ステップID>": [ 画面, 画面, … ] },
    "handson-1.html":  { "<h2 の見出し文字列>": [ 画面, … ] }
  }
}
```

- `config.html` のキーは `<div class="steph" id="…">` の **id**（例 `"c2"`, `"prep"`）。
- `handson-*.html` のキーは **h2 の見出し（タグを除いた文字列）**。前方一致でも可（例 `"1-1 受注登録（VA01）"`）。
  `期待結果`／`つまずき`／`验收`／`発展` の h2 はキーにしない（挿入位置が不自然になるため）。
- 1 ステップに複数の画面を配列で並べられる（初期画面 → 明細概況 → 保存後メッセージ、など）。
- 挿入位置は「そのステップの最後の `</ol>`（＝手順リスト）の直後」。手順 → 画面 → 確認ボックスの順になります。
- 実行は**冪等**：既存の `<figure class="gui">…</figure>` を全部消してから入れ直します。手で図を足さないこと。

## 1 画面のキー

| キー | 必須 | 内容 |
|---|---|---|
| `tx` | ○ | 取引コード（`VA01` など）。タイトルバー右とキャプションのバッジに出る |
| `title` | ○ | 画面タイトル（タイトルバーとキャプションに表示） |
| `kind` | ○ | `form` / `table` / `tree` / `split`（不明なら `form`） |
| `fields` | form のみ | `[[ラベル, 値], [ラベル, 値, 必須true], [ラベル, 値, 必須, 全幅true, 幅px]]` |
| `table` | table/split のみ | 下記 |
| `tree` | tree のみ | `{"title": …, "rows": [["⊟ プロジェクト定義 …", 深さ], …], "selected": 2}` |
| `tabs` / `active_tab` | 任意 | タブ見出しの配列と、選択中タブの index |
| `section` | 任意 | 本文の小見出し（例 `MRP 4（個別所要量＝本実習のスイッチ）`） |
| `note` | 任意 | 本文下の小さな注記（1 行） |
| `status` | ○ | `["success"｜"warning"｜"error"｜"info", "メッセージ"]`。実機で出るメッセージを書く |
| `status_right` | 任意 | 省略時 `S4H / 100 / TRAIN-01` |
| `toolbar` | 任意 | `[["↩","Enter"], ["▣","保存"], …]`（省略時は標準ツールバー） |
| `callouts` | 推奨 | `[["説明文", x, y, "吹き出しの短い文言"]]`。赤い番号バッジ＋吹き出し |
| `caption` | ○ | 画像下のキャプション（例 `品目マスタ（MM01）の初期画面`） |
| `tip` | 推奨 | キャプション下の補足（「自システムでの確認：〜」など） |
| `aria` | 推奨 | スクリーンリーダー用の説明（画像の内容を 1 文で） |
| `file` | 任意 | 出力ファイル名（省略時は `config_s01_2.svg` のように自動命名） |

### table オブジェクト

```json
"table": {
  "title": "明細概況",
  "columns": ["品目コード", "受注数量", "受注単位", "品目カテゴリ", "所要量タイプ"],
  "widths":  [1.5, 1.0, 0.9, 1.4, 1.2],
  "rows":    [["ZMTO-FG01", "10", "PC", "TAN", "KE"]],
  "selected": 0,
  "footer": "所要量タイプ KE = 受注生産。ここが空なら MRP4 を疑う"
}
```

## 座標について

- キャンバスは `1180 × 760`（viewBox）。タイトルバー 0-32 / メニュー 32-56 / ツールバー 56-84 / タブ 84 前後 / 本文 / ステータスバー下 34px。
- `callouts` の x,y は**その画面の座標**。`form` は 1 行目 y≈150 から 50px 刻み、2 列目 x≈600。
  `table` はヘッダー y≈150 付近、行は 26px 刻み。ずれても致命的ではないが、指したい欄の近くに置くこと。
- 生成時に `xml.etree` で SVG をパースし、壊れていればエラーで止まる。

## 内容を書くときのルール（品質基準）

1. **実機のメッセージを書く**：`status` は「伝票 0000001234 を保存しました」「品目 ZMTO-FG01 の MRP 4 ビューを更新しました」のように、実際に出る文言に寄せる。
2. **値を実習のシナリオに合わせる**：品目コード・数量・金額は同一サイト内で必ず一致させる（`index.html` のシナリオ表と突き合わせる）。
3. **推測でフィールド名を書かない**。不明な欄は省略するか、`note` に「項目名は環境により異なる」と書く。
4. `callouts` は「なぜそこを見るのか」を書く（単なる名称の写しではなく、つまずきポイントを指す）。
5. 1 ステップあたり 1〜2 画面を標準とする（初期画面 → 結果画面）。全ステップに最低 1 画面を付ける。
