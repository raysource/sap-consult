总览 / 能力测试

能力测试（28 题 + 实机验收）

用法 每题点击一个选项即判分并显示解说。合格判定：正确率 ≥75%（21/28）＋ 实机验收清单全部勾上。 60〜74% 请回对应页面重读；<60% 请从 概念与设计 重来。
解说里的标准值是「通常情况」——要能说出「怎么在系统里验证」，比背下来重要。

一、概念（1〜10）

概念E と Q

1. ETO（受注設計生産）で使う在庫の区分は？

A. E（受注在庫。受注番号＋明細に紐づく）
B. K（預託在庫）
C. Q（プロジェクト在庫。WBS 要素に紐づく）
D. W（得意先預託）
ETO は在庫・原価・収益をプロジェクト（WBS）単位で管理するため、特別在庫区分 Q＝プロジェクト在庫を使います。E は受注明細単位（MTO）、K＝預託、W＝得意先預託です。
概念テーブル

2. プロジェクト在庫（Q）の数量が入るテーブルは？

A. MSKA
B. MSPR
C. MSKU
D. MSSA
MSKA＝受注在庫(E)、MSPR＝プロジェクト在庫(Q)、MSKU＝得意先預託(V/W)。SAP Help「Stock Tables and Stock Types」に一覧があります。SE16N で SOBKZ を見れば一目で分かります。
概念Q の成立条件

3. プロジェクト在庫 Q を成立させる 4 点セットに含まれないものは？

A. プロジェクト定義の「評価付プロジェクト在庫」
B. 品目マスタ MRP4「個別/包括所要量」＝ 個別所要量のみ
C. 品目マスタ MRP3 の戦略グループ（評価区分 M を持つ所要量クラスを指す）
D. 品目マスタ MRP1 のロットサイズを「EX」にすること
4 点セットは ① 評価付プロジェクト在庫 ② MRP4 個別所要量 ③ MRP3 戦略グループ（→所要量クラス） ④ 受注明細への WBS 割当。 ロットサイズ（EX など）は手配の量を決めるだけなので、Q の成立条件ではありません（実務上は EX が便利なだけ）。
概念個別所要量品目

4. 「個別所要量品目（individual requirements material）」とは？

A. 品目マスタに品目カテゴリグループ 0002 を持つ品目
B. WBS 要素を参照して製造され、需要・在庫が個別に管理される品目（ETO の完成品）
C. 計画独立所要量（PIR）で計画する品目
D. ロットサイズが EX の品目
SAP Help（Cloud, 受注設計生産）は「ETO などのプロジェクト関連の生産環境では、品目は WBS 要素を参照して製造される。このような品目は個別所要量品目とも呼ばれる」と説明しています。PIR で計画するのは見込生産品です。
概念WBS の役割

5. 「請求要素（billing element）」として使う WBS の役割は？

A. 予算を持つだけの要素
B. 指図や発注の勘定設定に使う要素
C. 受注明細を割り当てて収益を計上する要素
D. 階層を表すだけの構造要素
請求要素は「収益を計画・計上できる」WBS。受注明細を請求要素に割り当て、請求（VF01）するとその WBS に収益が集まります。原価は勘定設定要素（.2 など）に集まります。
概念請求方式

6. ETO で長期案件の分割請求に使うのは？

A. 出荷ベースの請求だけ
B. 前受金しか使えない
C. 買掛金の計上
D. 請求計画（日付／出来高）や資源関連請求（RRB）
ETO は「金額×いつ請求するか」を契約で決めます。請求計画（日付ベース／出来高＝マイルストーン）、資源関連請求（DP90/DP91）などが選択肢。受注明細の明細カテゴリに請求計画の許可が必要です。
概念評価

7. プロジェクト在庫に金額（評価）を持たせるには？

A. プロジェクト定義の「評価付プロジェクト在庫」を設定し、所要量クラスに評価区分（M）を持たせ、品目会計ビューを整える
B. 品目マスタの価格管理を移動平均価格（V）にする
C. 明細カテゴリの特別在庫を E にする
D. 出荷タイプを LF にする
評価付プロジェクト在庫は、① プロジェクト定義の フラグ、② 品目 MRP4 個別所要量、③ 戦略グループ経由の所要量クラス（評価区分 M＝販売伝票/プロジェクト参照の別評価）、④ 会計ビューの評価クラスの組合せで成立します。
概念月末処理

8. ETO の月末処理の正しい順序は？

A. 決済 → 進捗 → 結果分析
B. 進捗 → 結果分析（WIP/収益の計算）→ 決済
C. 請求 → 決済 → 進捗
D. 予算入力 → 決済 → 進捗
進捗（CNE1/CNE2）→ 結果分析（KKA2/KKAJ）で WIP と認識収益を計算（KKAX で照会）→ 決済（指図 KO88 / 受注 VA88 / WBS CJ88）で FI へ、という順序です。
概念Cloud

9. SAP S/4HANA Cloud Public Edition の ETO スコープアイテムと戦略グループは？

A. スコープアイテム BJE / 戦略グループ 20
B. スコープアイテム IYT / 戦略グループ 25
C. スコープアイテム 6GD / 戦略グループ E2（所要量タイプ E21＝特別在庫 Q）
D. スコープアイテム 1BM / 戦略グループ 82
Cloud の ETO は 6GD（Engineer Products and Systems – Project with Production）で交付され、Master Data 手順に「Strategy Group: E2」と記載があります。E2 は 6GD 活性後に利用可能（SAP KBA 3623492）。BJE は MTO＋最終組立、IYT は MTO＋VC です。
概念決済対象

10. 決済トランザクションの組合せで正しいのは？

A. 製造指図 KO88 ／ 得意先受注 VA88 ／ WBS CJ88（一括 CJ8G）
B. 製造指図 CJ88 ／ 得意先受注 KO88 ／ WBS VA88
C. すべて KKA2 で行う
D. すべて VF01 で行う
SAP Help「S/4HANA information for Cost Object Controlling」に、指図の決済 CO88、受注の決済 VA88 などが整理されています。WBS は CJ88（個別）/CJ8G（一括）。KKA2 は結果分析、VF01 は請求です。

二、配置（11〜19）

配置PS プロファイル

11. プロジェクトプロファイルを作成/確認するトランザクションは？

A. OPPJ
B. OPSA
C. CJ20N
D. OVZG
プロジェクトプロファイルは OPSA（IMG：Project System > Structures > Operative Structures > Work Breakdown Structure > Create Project Profile）。 番号範囲・予算プロファイル・決済パラメータ・ステータスなど PS の制御がここに集まります。CJ20N はプロジェクトの登録画面です。
配置品目マスタ

12. 「個別/包括所要量」を設定するのはどのビュー？

A. MRP1
B. MRP2
C. MRP3
D. MRP4
MRP4 の「個別/包括所要量」＝個別所要量のみ が、個別所要量品目（＝プロジェクト在庫 Q の前提）を作ります。MRP3 は戦略グループと在庫確認、MRP1 は MRP タイプ・ロットサイズ・手配タイプです。
配置戦略グループ

13. 戦略グループを設定するビューと、その先を確認する手顺は？

A. MRP4 → OVZI で所要量タイプを確認
B. 販売組織2 → VOV4 で確認
C. MRP3 → OPPJ/OPPS で戦略の中身 → OVZG で所要量クラス（評価区分・個別在庫）を確認
D. 会計1 → OBYC で確認
戦略グループは品目マスタ MRP3。そこから 計画方針グループ（OPPJ）→ 計画方針（OPPS）→ 所要量タイプ → 所要量クラス（OVZG）と辿り、評価区分 M と個別在庫を確認するのが ETO の要点です。
配置予算

14. 予算関連のトランザクションの説明で正しいのは？

A. CJ30＝元予算の変更、CJ32＝予算の解放、CJ31＝元予算の照会、CJBV＝可用性管理の活性化
B. CJ30＝予算照会、CJ32＝予算振替、CJBV＝予算の取消
C. CJ30＝決済、CJ31＝結果分析
D. 予算は VF01 で投入する
CJ30（元予算の変更）/ CJ31（照会）/ CJ32（予算の解放）/ CJBV（可用性管理の活性化）/ CJ34（予算振替）/ CJ37（予算補足）です。予算は「統制と予実比較」のためのもので、計画（CJ40/CJ42）とは別物です。
配置ネットワーク

15. ネットワーク／活動の確認・進捗に関するトランザクションで正しいのは？

A. CN21＝活動確認、CN25＝ネットワーク登録
B. CN21＝ネットワーク登録、CN25＝活動確認（個別）、CN27＝一括確認、CN29＝確認の取消、CNE1/CNE2＝進捗の決定
C. 進捗は CO11N で入れる
D. CN21＝決済
CN21/CN22/CN23＝ネットワークの登録/変更/照会、CN25/CN27/CN28/CN29＝活動確認（個別/一括/照会/取消）、CNE1/CNE2＝進捗の決定（個別/一括）。製造指図の実績は CO11N です。
配置受注明細と WBS

16. 受注明細に WBS 要素を割り当てるために確認すべきことは？

A. 出荷タイプが LF であること
B. 請求タイプが F2 であること
C. 品目マスタのロットサイズが EX であること
D. その明細カテゴリが WBS の割当を許可していること（VOV7。Cloud は CBAO など交付済みの明細カテゴリのみ）
WBS を割り当てられる明細カテゴリは限定されています。SAP Help（Cloud）は例として CBAO（マイルストーン請求計画）を挙げています。On-Premise は VOV7 で確認し、必要ならコピーして作成します（実測が基本）。
配置プロジェクト定義

17. 「評価付プロジェクト在庫」を設定する場所は？

A. 品目マスタの会計ビュー
B. 明細カテゴリ（VOV7）
C. プロジェクト定義（CJ20N）の「プロジェクト在庫」セクション
D. 荷動きの転記画面（MIGO）
SAP Help「Valuated Project Stock: Scenario」が「プロジェクト作成時、プロジェクト定義の プロジェクト在庫 セクションで評価付プロジェクト在庫インジケータを設定する」と明記しています。品目側では MRP4 の個別所要量が必要です。
配置Public Cloud

18. Public Cloud の ETO（6GD）でできないことは？

A. WBS に受注明細を割り当てる
B. 明細カテゴリやプロジェクトプロファイルを自由に新規作成する
C. プロジェクト在庫から出荷する
D. マイルストーン請求計画を使う
Cloud は「What you see is what you get」。明細カテゴリの新規作成はできず、交付済みのもの（CBAO 等）から選びます。プロファイル類も SSCUI の範囲のみ。代わりに 6GD の Test Script が業務手顺として提供されます。
配置MRP 実行入口

19. 受注単位／プロジェクト単位の MRP 実行トランザクションは？

A. 受注 MRP＝MD50、プロジェクト MRP＝MD51、全体＝MD01N
B. 受注 MRP＝MD04、プロジェクト MRP＝MD05
C. すべて MD02 で行う
D. PS では MRP を実行できない
MD50＝受注単位の MRP、MD51＝プロジェクト単位の MRP。MD01N は MRP Live（プラント全体）で、MRP リストは作られず結果は MD04 で確認します。MD04 は在庫/所要量リスト（照会）です。

三、流程（20〜26）

流程練習①の順序

20. 練習① の正しい順序は？

A. 受注 → プロジェクト作成 → 予算 → 計画
B. プロジェクト（WBS・評価付在庫）→ ネットワーク → 計画（CJ40/CJ42）→ 予算（CJ30/CJ32）→ 受注（明細に WBS）→ 請求計画
C. 予算 → 受注 → プロジェクト作成
D. 受注 → 請求計画 → プロジェクト作成 → 予算
受注明細に WBS を入れる必要があるため、プロジェクトが先です。請求計画は受注後（VA02）に登録します。予算は計画の後に投入すると予実の流れが追いやすい、という順序です。
流程計画手配

21. MRP 後の計画手配で確認すべき最重要点は？

A. 数量だけ
B. 品目コードだけ
C. 勘定設定が WBS であることと、在庫区分がプロジェクト在庫 Q であること
D. 伝票タイプの番号範囲
計画手配の「勘定設定 = WBS」と「在庫区分 = Q」が ETO 成立の証拠です。ここが空/自由在庫なら、① 受注明細の WBS、② MRP4 個別所要量、③ 戦略グループ、④ 評価付フラグ の 4 点を疑います。
流程入庫

22. 完成品の 101 入庫先は？

A. プロジェクト在庫（特別在庫 Q）＋ WBS（指図の勘定設定）
B. 自由在庫（プラント在庫）
C. 受注在庫（E）＋受注番号
D. 預託在庫（K）
ETO では受注明細→WBS→指図の勘定設定という連鎖があるため、101 はプロジェクト在庫 Q に入ります。入庫画面で「特別在庫 Q」「WBS」が自動表示されているかを必ず確認します（自由在庫に入ったら MBST で取消して原因を直す）。
流程出荷

23. 出荷（VL01N）と出庫確認（PGI）について正しいのは？

A. 出荷明細の在庫区分は常に自由在庫
B. PGI の移動タイプは 261
C. PGI はプロジェクト在庫を増やす
D. 出荷明細の在庫区分は Q（＋WBS）で、PGI（601）によりプロジェクト在庫が減る
出荷明細は受注明細→WBS を通じてプロジェクト在庫 Q を向きます。PGI は移動タイプ 601 で Q から出庫し、在庫が減ります（261 は指図への部品出庫、101 は入庫）。
流程CJI3

24. 請求後、CJI3（実績）で期待される表示は？

A. 収益も原価も同じ WBS に出る
B. 収益は請求要素（.1 など）、原価は勘定設定要素（.2 など）に出る
C. 収益はネットワーク、原価は受注に出る
D. CJI3 には金額は出ない
請求は受注明細が指す請求要素に収益を、指図・発注の勘定設定である勘定設定要素に原価を集めます。CJI3 に出ないときは、この 2 つの役割の取り違えを最初に疑います。
流程決済前後

25. 決済（KO88 / CJ88）を実行すると何が変わる？

A. 受注金額が変わる
B. プロジェクト在庫の数量が変わる
C. 指図や WBS に集まっていた原価・収益が決済受信者（損益勘定など）へ流れ、CJI3 の表示が変わる
D. 請求伝票が自動で作られる
決済は「集めた金額をどこへ渡すか」を実行します（決済ルール CJB1/CJB2 が必要）。数量は変わりません。決済前後で CJI3 と CJIC（決済明細）を見比べるのが一番の理解の近道です。
流程取り消し

26. 請求まで完了した案件を巻き戻す順序は？

A. 請求 VF11 → PGI VL09 → 入庫取消（MIGO/MBST）→ 確認取消（CO13/CN29）
B. 指図を削除すれば後続は自動で消える
C. PGI 取消 → 請求取消 → 入庫取消
D. プロジェクトを削除するだけでよい
取消は逆順：請求（VF11）→ PGI（VL09）→ 入庫取消 → 実績取消（CO13、ネットワークなら CN29）。指図やプロジェクトを削除しても後続伝票は消えません。

四、故障（27〜28）

故障WBS が入らない

27. 受注明細に WBS 要素を入力できない。第一嫌疑は？

A. 得意先マスタの与信限度
B. その明細カテゴリが WBS の割当を許可していない（VOV7／Cloud は交付済みの明細カテゴリのみ）
C. 出荷ポイントが決まっていない
D. 品目のロットサイズが EX でない
WBS 割当の可否は明細カテゴリ側の設定です。VOV7 で確認し、必要ならコピーして ZETO 明細カテゴリを作成（VOV4 に決定キー追加）。Cloud では新規作成できないため、CBAO などの交付済み明細カテゴリを選びます。
故障自由在庫に入る

28. 101 入庫が自由在庫に入ってしまった。確認すべき 4 点は？

A. 出荷タイプ・請求タイプ・与信・税区分
B. ロットサイズ・MRP コントローラ・購買グループ・品目グループ
C. 予算プロファイル・決済ルール・結果分析キー
D. ① 指図の勘定設定（WBS）② プロジェクト定義の評価付プロジェクト在庫 ③ 品目 MRP4 個別所要量 ④ 戦略グループ（Q 系の所要量タイプ）
「自由在庫に入った」＝システムが個別需要として扱っていない、ということ。Q の 4 点セット（評価付フラグ・MRP4・戦略グループ・WBS 割当）を順に確認します。MBST で取消 → 修正 → 再入庫の順で直します。

实机验收清单（合格必须全勾）

✓ 総合验收（証跡つきで説明できること）
  • PS 主数据：CJ20N のプロジェクト定義（評価付プロジェクト在庫 ON）・WBS 3 件（.1 請求要素 / .2 勘定設定要素）・ネットワーク activity（CN23）。
  • 計画と予算：CJ40/CJ42 の計画値（CJI4）と CJ30→CJ32→CJ31 の予算。
  • SD×PS 接続：VA03 明細の WBS 要素・所要量タイプ（Q 系）・請求計画（30%/70%）。
  • MRP と指図：MD04 の計画手配（勘定設定 = WBS・在庫区分 = Q）、CO03 の勘定設定と部品予約。
  • 在庫：261/101 の伝票番号 ＋ MMBE のプロジェクト在庫 1 式（自由在庫 0）＋ SE16N: MSPR（SOBKZ = Q）。
  • 販売：出荷伝票（在庫区分 Q）＋ PGI 後の Q 在庫 0 ＋ 請求伝票（請求計画のどの行かも）。
  • CO：CJI3 で WBS .1 に収益・.2 に原価が出ている画面、決済前後の変化。
  • 故障：この実習中に発生した問題を 1 件以上、症状／根因／証跡 T-code で記述した。
