练习配置手顺（C0〜C16）

关于本页的「画面イメージ」：这些图是按 SAP GUI 标准布局重绘的示意图，不是实机截图。字段名、字段顺序、按钮位置会因版本与自定义而不同，请以自系统的画面为准（各 STEP 的「自系统での確認方法」里写了确认用的 T-code 与表）。若是想换成实机截图，把同名 .png 放进 assets/gui/ 后执行 python3 tools/swap_gui_images.py <site> --apply 即可一键替换。
本页怎么用 每个 STEP 都是「目的 → IMG 路径 / 事务码 → 输入值 → 操作手顺 → 自系统中的确认 → 注意 → 练习课题」的固定结构。
① ETO 的标准值环境差最大（戦略グループ、WBS を割り当てられる明細カテゴリ、評価付プロジェクト在庫の扱い）→ 先确认、后自建； ② 练习用对象命名：ZETO-FG01/ZETO-RM01/02（品目）、ZETO-1000（プロジェクト）、ZETO01（プロジェクトプロファイル）、WBS .1/.2/.3、ネットワーク 3000001； ③ 所有改动记入你的カスタマイジング依頼； ④ PS の設定はプロファイルに集約されるので、「どのプロファイルを使っているか」を常に意識する（迷ったら CJ20N のプロファイルから逆引き）。

配置前的准备

PS の設定は SD/PP/MM より「プロファイル」に依存します。着手前に ① PS の権限（CJ20N・CJ30・CJI3・CJ88）② 制御エリア・会社コード・プラントの整合 ③ カスタマイジング依頼 を確認してください。また、既存の標準プロファイル（CJ20N で選択できるもの）を 1 つ選び、それを「正解の見本」として読み解く進め方が最短です。

プロジェクトプロファイルとコーディングマスク

OPSA（IMG）
IMG 路径
Project System > Structures > Operative Structures > Work Breakdown Structure > Create Project Profile（事务码 OPSA）
目的
PS 的「控制面板」：番号範囲、WBS 画面、予算プロファイル、決済パラメータ、ステータスプロファイル、日付/計画の既定値などをひとまとめにする。
  1. OPSA → 既存の標準プロファイル（CJ20N で選べるもの）を 1 つ決め、表示（照会）して主要項目を読み取る：
    ・番号範囲（プロジェクト定義/WBS）　・予算プロファイル　・決済パラメータ/決済ルールの既定　・ステータスプロファイル　・計画要素の既定
  2. （任意）練習用に ZETO01 としてコピー作成し、説明を「ETO 練習用」に。以降の練習はこのプロファイルで行うと差分が追いやすい。
  3. WBS の ID は「コーディングマスク＋番号」で決まる。コーディングマスク（例 ZETO-）を確認し、WBS の採番がどう決まるかを理解する（プロジェクトの特殊文字定義/編集マスク）。
  4. プロジェクトタイプ（WBS 要素のタイプ）：IMG の SM30 ビュー V_TCJ1（WBS 要素のプロジェクトタイプ）で確認する。
确认（自系统） CJ20N で新規作成 → プロファイルを選択 → WBS を 1 件作って ID を見る（ZETO-1000.1 のような形で採番されるか）。採番や階層のルールがここで腹落ちすると、後の練習が速い。
よくある失敗プロファイルを理解せずに WBS を作り、後で「予算が使えない」「決済できない」となる。PS のトラブルはまずプロファイルに戻るのが定石。

C8

予算プロファイルと可用性管理

CJ30 / CJ32 / CJBV / CJ31
目的
WBS 予算を入れて、発注や実績が予算を超えそうなときに警告/エラーを出す（可用性管理）。
  1. C5 のプロジェクトプロファイルで予算プロファイルが割当たっているか確認（未割当なら予算機能が使えない）。
  2. 練習①でプロジェクトを作成後、CJ30（元予算の変更）で WBS に予算を投入（例：WBS .1 に 5,000,000 JPY）。
  3. CJ32（予算の解放）で実行可能にする。予算が解放されないと購買・指図が止まることがある。
  4. CJBV（可用性管理の活性化）を実行し、予算超過時の挙動（警告/エラー）を体験する。CJ31 で予算を照会。
  5. （発展）CJ34 予算振替、CJ37 予算補足、CJ35/CJ38 予算返還。
确认（自系统）CJ31 で元予算・解放額・使用額（実績＋コミット）が見える。CJI5 でコミットメント（発注残）を確認。
C9

評価付プロジェクト在庫（最重要）

CJ20N（プロジェクト定義）
目的
プロジェクト在庫 Q を数量＋金額で持たせる。これが MTO（E）との決定的な違い。
  1. CJ20N → 練習① で作るプロジェクト定義を開く → 「プロジェクト在庫」セクションの 評価付プロジェクト在庫（Valuated project stock） を ON にする。
  2. WBS のフラグを整理：
    ・.1 設計・調達 → 請求要素（請求の宛先）
    ・.2 製造 → 勘定設定要素（指図・発注・在庫の行き先）
    ・.3 据付・試運転 → 勘定設定要素
  3. 品目側の前提（C2）と合わせて 4 点セットが揃っていることを確認する。
确认（自系统） ① CJ20N/CJ03 で評価付フラグが見える ② MM03 MRP4 個別所要量 ③ 戦略グループ→所要量クラスの評価区分 M ④ 受注明細の WBS。
4 点が揃うまで進まないのが、この教材で唯一の「絶対ルール」。
よくある失敗評価付フラグを後から ON にすると、既存在庫の扱いで不整合が起きる。練習ではプロジェクトを作った直後に設定する。
C10

受注明細の WBS 割当（SD × PS 接続点）

VOV7 / VOV4 / VA02
目的
受注明細に WBS を割り当て、需要をプロジェクト（WBS）に帰属させる。ここが ETO の SD-PS 接続点。
  1. まず実測：VA01（または VA02）で明細を作り、明細詳細に「WBS 要素」項目が出るか、入力できるかを確認する。
    ・項目が出ない/入力できない → その明細カテゴリは WBS 割当を許していない。
  2. 明細カテゴリを確認：VOV7 で該当の明細カテゴリを開き、勘定設定・請求関連（請求計画の許可を含む）を読み取る。VOV4 でどのキーで決まるかを確認。
  3. 標準で使える明細カテゴリが無い/要件に合わない場合：コピーして ZETO（例）明細カテゴリを作成し、WBS 割当・請求計画・請求関連を許可する。VOV4 に決定キー（伝票タイプ OR + 品目カテゴリグループ）を追加。
  4. 請求要素（.1）を明細の WBS に指定して保存する。
确认（自系统） VA03 → 明細 → WBS 要素に入力値がある、所要量タイプが Q 系（Cloud は E21）になっている。
参考：SAP Help（Cloud）は「受注の場合、WBS 要素を CBAO（マイルストーン請求計画）などの明細カテゴリの明細に割り当てることができる」と説明している。
ここが ETO 最大の落とし穴「明細に WBS が入らない」→ 明細カテゴリ（VOV7/VOV4）。「請求が WBS に出ない」→ WBS が請求要素でない。「在庫が Q にならない」→ C2/C9 の前提。3 つを切り分けて考える。
C11

請求計画／出来高請求の前提

VA02（請求計画）/ VF01 / VTFL
請求タイプ           : F2（標準）
出荷→請求コピー制御  : VTFL（有効であること）
請求計画            : 受注明細（またはヘッダ）で「請求計画」→ 日付ベース 2 行：
                      ・1 行目：契約締結時 30%（1,500,000 JPY）
                      ・2 行目：完成・検収時 70%（3,500,000 JPY）
出来高請求を使う場合 : 請求計画タイプ（出来高）＋マイルストーン（ネットワーク活動/マイルストーン）と請求の紐付け
  1. VA02 → 明細 → メニュー「明細」→「請求計画」→ 上記 2 行を登録（日付・金額 or パーセント）。
  2. 保存後、VF01（請求タイプ F2、納入日付/請求日付範囲）で請求できれば前提 OK。請求計画に載っていない日付では請求できないのがポイント。
  3. （出来高の場合）ネットワーク活動のマイルストーンと請求計画の紐付けを確認（CN21/CN22 のマイルストーン）。
よくあるエラー 「Item 000010 can not be invoiced according to the billing plan」＝請求計画と請求の条件が噛み合っていない（請求関連の設定/請求計画の日付・金額）。SAP KBA 2763512 が参考になる。
C12

決済の前提（WBS・指図・受注）

CJB1 / CJB2 / CJ88 / CJ8G / KO88 / VA88
WBS の決済ルール    : CJB2（個別）/ CJB1（一括）— 決済受信者（例：会社コードの損益勘定）
指図の決済          : KO88（個別）/ CO88（一括）。MTO/ETO では受注・WBS 側へ
受注の決済          : VA88（得意先受注の決済）
WBS の決済          : CJ88（個別）/ CJ8G（一括）
決済プロファイル     : プロジェクトプロファイル経由で既定が決まる（C5 で確認）
  1. CJB2 で WBS の決済ルールが存在するか確認（無ければ作成）。
  2. 練習⑤ で CJ88（対象：WBS、期間、決済タイプ）を実行し、ログと CJIC（決済明細）を確認する。
  3. 指図は KO88、受注は VA88 であることを整理して覚える（SAP Help「S/4HANA information for Cost Object Controlling」に決済トランザクションの一覧がある）。
确认（自系统）決済を実行すると、WBS に集まった原価・収益が決済受信者へ流れ、CJI3 の残高が整理される。

結果分析と収益認識の前提

KKA2 / KKAJ / KKAX / KKA0P
  1. プロジェクト/WBS に割当てられる結果分析キーと収益認識キー（工事進行基準/出来高/完了基準 など）を確認し、どれが使われているかを記録する。

MD50 / MD51 / MD01N / MD04
