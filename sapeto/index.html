受注設計生産（ETO）实战训练站

姐妹篇：MTO（受注生産） 把库存切到「受注明細」；ETO（受注設計生産） 把库存切到「プロジェクト（WBS）」。 本站跑通一条完整链路：CJ20N 立项（WBS）→ 受注明細に WBS 割当 → MRP → 製造指図（WBS 勘定設定）→ 完成入庫（プロジェクト在庫 Q） → 出荷（Q から PGI）→ 出来高/請求計画で請求 → 予算・実績（CJI3）→ 進捗・結果分析（KKA2/KKAJ）→ 決済（CJ88）。 同样分两层：练习配置（PS 侧プロジェクトプロファイル/ネットワークタイプ/予算/決済 + SD 侧明細カテゴリと WBS 割当）与 练习流程（5 个实操，含输入值、手顺、期待结果、故障对策、验收清单）。主口径 On-Premise，附 Public Cloud（6GD / 戦略グループ E2）对照。

1. 本站教什么

ETO（Engineer-to-Order / 受注設計生産）是「每单都要设计、没有现成库存、按项目核算」的制造形态。 它的机制支点是 プロジェクト（WBS 要素）：需求、库存、成本、收入全部挂到 WBS 上，而不是像 MTO 那样挂到受注明細（E 特在）。 SAP 里这一层用一个专门的特别库存区分实现：Q ＝ プロジェクト在庫（project stock）。

① 练习配置手顺（PS + SD 详细）

C0〜C16：品目マスタ（MRP4 個別所要量・MRP3 戦略グループ）→ プロジェクトプロファイル（OPSA）・プロジェクトタイプ・コーディングマスク → ユーザステータス → ネットワークタイプ/プロファイル → プロジェクト在庫（評価付）→ 受注明細の WBS 割当・請求計画 → 予算（CJ30/CJ32/CJBV）→ 決済（CJ88）→ 結果分析（KKA2）。 每步给出 IMG 路径、事务码、输入值、自系统确认方法。

配置约 180 分

② 练习流程（5 个实操）

①项目与受注（CJ20N + VA01 の WBS 割当）→ ②计划与 MRP（CJ40/CJ42・MD50/MD51・計画手配→製造指図）→ ③执行与入库（261 / CO11N / 101 → プロジェクト在庫 Q）→ ④出荷与请求（VL01N・PGI 601・VF01 請求計画・CJI3 で WBS 実績）→ ⑤发展与故障（予算/可用性管理・進捗・結果分析・決済・故障对照表）。

实操约 300 分

③ 概念与设计

MTS / MTO(E) / ETO(Q) 对照、個別所要量品目と WBS 参照、プロジェクト在庫の成立条件、WBS の「請求要素」、収益認識（POC/出来高/イベントベース）、 相关表（PROJ・PRPS・AUFK・AFPO・MSPR・COEP）与 S/4HANA 变更点。

概念约 75 分

④ 能力测试 + 验收清单

28 题（概念 / 配置 / 流程 / 故障）× 点击判分 + 解说，外加实机验收清单：把 CJI3（WBS 实績）、CJ20N、MD04、MMBE（特在 Q）、伝票フロー 的证据逐条核对。

测试约 30 分
授课用の成果物（3 点セット） ① 讲师版（解答・采分点・必出 Q&A・故障の教え方）／② 学员版ワークシート（挖空・印刷可）／ ③ Excel SD受注設計生産ETO_要件定義・手順書.xlsx（python3 tools/make_eto_xlsx.py で再生成、11 シート）。 MTO 站（../sapmto/）とセットで使うと「按单 vs 按项目」的差异最直观。

7. 关于标准值的立场（务必读）

ETO 是「环境差最大」的场景 与 MTO 相比，ETO 的标准值更容易因版本、解决方案和既有改造而不同：
・ETO 用の戦略グループ（Cloud の 6GD は E2、所要量タイプ E21＝特別在庫 Q）は、スコープアイテム/業務機能の活性状況で有無が変わる（SAP KBA 3623492 が「E2 は 6GD 活性後に利用可能」と明記）。
・WBS を割り当てられる明細カテゴリは限定される（Cloud の例：CBAO＝マイルストーン請求計画）。On-Premise では自システムで実測して決めるしかない。
・評価付プロジェクト在庫の前提は「品目マスタ MRP4 個別所要量＋ MRP3 戦略グループ（評価区分 M を持つ所要量クラス）＋ プロジェクト定義の評価付フラグ」の 3 点セット（SAP Help / SAP Learning）。
だから本站的做法是：把机制写清楚，把每个值都配上「在你系统里怎么确认」的手顺，并让练习用自建对象（ZETO-1000・ZETO01 プロファイル等）完成。
