2品目 ZETO-FG01 の MRP4 個別所要量・MRP3 戦略グループ（Q 系）を整備MM03 で確認済み、または「受講者に実測させる」運営方針を決めておく
3WBS を割り当てられる明細カテゴリを事前調査（On-Premise は環境差が大きい）VA01 の明細に WBS 項目が出る明細カテゴリを 1 つ以上特定（無ければ ZETO 明細カテゴリを用意）
4プロジェクトプロファイル（予算プロファイル・決済パラメータ含む）を用意CJ20N で選択でき、CJ30 で予算投入できる
5練習環境のリセット手順（受注取消・指図削除・在庫戻し・依頼の差戻し）受講者が失敗しても 15 分でやり直せる
6ワークシート印刷＋Excel 配布人数分

3. 板書用：4 点セットと決定链（これ 1 枚で全体が説明できる）

【プロジェクト在庫 Q 成立の 4 点セット】
 ① プロジェクト定義：評価付プロジェクト在庫 = ON      （CJ20N）
 ② 品目マスタ MRP4 ：個別所要量のみ（個別所要量品目）  （MM02）
 ③ 品目マスタ MRP3 ：戦略グループ → 所要量クラス（評価区分 M）  （MM02 / OPPJ / OVZG）
 ④ 受注明細        ：WBS 要素（請求要素）を割当       （VA01/VA02）
        ↓ どれか欠けると「Q にならない／金額が付かない／収益が WBS に出ない」

【決定链】
 プロジェクト(WBS) → 受注明細の WBS → 需要（得意先所要量） → MRP（MD50/MD51/MD01N）
   → 計画手配（勘定設定 = WBS・在庫区分 = Q） → 製造指図（CO40/CO08）
   → 261 部品出庫 / CO11N 実績 → 101 入庫 → プロジェクト在庫 Q（MSPR）
   → 出荷（在庫区分 Q）→ 601 出庫確認 → 請求（請求計画/出来高）
   → WBS へ 収益（請求要素 .1）・原価（勘定設定要素 .2）
   → 進捗（CNE1）→ 結果分析（KKA2）→ WIP（KKAX）→ 決済（CJ88 / 指図 KO88 / 受注 VA88）→ FI
受講者に必ず口頭で言う 3 点 ① ETO は「Q（プロジェクト在庫）」、MTO は「E（受注在庫）」——在庫の帰属先が違う（表も MSPR と MSKA）。
② 収益は請求要素、原価は勘定設定要素。CJI3 に出ないときはこの 2 つを確認。
③ 標準値は環境依存 → 戦略グループ（Q 系か）・WBS を割り当てられる明細カテゴリは必ず実機で確認（Cloud は 6GD の E2/E21）。

6. 必出質問 Q&A（模範回答つき）

#質問模範回答
1ETO でも受注在庫（E）ではだめですか？だめです。E は受注明細、Q は WBS に帰属します。ETO は「案件（プロジェクト）単位で在庫・原価・収益を管理する」ことが目的なので Q を使います（表も MSKA と MSPR）
2受注したらプロジェクトが自動作成されませんか？SAP 標準にはありません。CJ20N で作成し、受注明細に WBS を割り当てます。自動化するなら BAdI や外部連携の実装が必要です
3プロジェクト在庫の金額が入りません4 点セットの ① と ③ を疑ってください。プロジェクト定義の評価付プロジェクト在庫、そして戦略グループが指す所要量クラスの評価区分（M）。会計ビューの評価クラスも確認します
4受注明細に WBS 欄が出ません明細カテゴリが WBS 割当を許していないためです。Cloud は CBAO（マイルストーン請求計画）などの交付済み明細カテゴリから選びます。On-Premise は VOV7 を確認し、必要ならコピーして作成します
5戦略グループの E2 が見つかりませんCloud ではスコープアイテム 6GD の活性後に利用可能になります（KBA 3623492）。On-Premise は環境により値が異なるので、OPPJ/OPPS/OVZG で自システムの ETO 用戦略を特定してください
6ネットワークは必須ですか？必須ではありません。製造は製造指図（CO40/CO08）で回せます。ネットワークは設計・据付・外注を含めた工程管理と工数集計（CN25）、進捗の材料として使います
7予算を入れないと実績は出ませんか？出ます。予算は可用性管理（超過の抑止）と予実比較のためのものです。ただし予算が「解放」されていないと発注・指図が止まることがあります
8請求したのに CJI3 に収益が出ません受注明細が指す WBS が請求要素になっていない可能性が高いです。CJ20N の WBS フラグと VA03 の明細（WBS）を確認してください
9CJI3 に原価が出ません指図・発注の勘定設定が WBS になっていない可能性。計画手配の時点で勘定設定 = WBS だったかを MD04 で遡って確認します（COEP でも確認可）
10決済はどれを実行すればよいですか？対象ごとに違います：製造指図 KO88、得意先受注 VA88、WBS CJ88（一括 CJ8G）。まず決済ルール（CJB2）があるかを確認します
11POC（工事進行基準）で収益を立てたい進捗（CNE1）→ 結果分析（KKA2）で計算されます。収益認識キー・結果分析キー、カットオフ期間の設定が前提です。Cloud はイベントベース収益認識になる場合があります
12Public Cloud で同じ練習はできますか？できません。Cloud は 6GD の Test Script に従います（明細カテゴリの新規作成不可、ネットワークの利用範囲も限定的）。本教材は機制理解と差異把握に使ってください

7. 故障の教え方（4 分层の切り分け）

層問いかけ見る画面 / T-codeここで終わらせる結論
① SD/WBS 層受注明細に WBS が入り、需要が MD04 に出たか？VA03 明細（WBS・所要量タイプ）→ MD04出ない＝明細カテゴリ／戦略グループ／所要量転送
② PS 層手配の勘定設定が WBS、在庫区分が Q か？MD04 計画手配明細 → MM03 MRP4/MRP3 → CJ20N違う＝個別所要量・評価付フラグ・戦略グループ（4 点セット）
③ MM 層Q 在庫ができて動いたか？MMBE／MB52／SE16N: MSPR／MATDOCできない＝指図/発注の勘定設定と入庫先（Q）
④ CO 層原価・収益が WBS に集まり、損益になったか？CJI3/CJ31/CJI5 → KKA2/KKAX → CJ88/CJICならない＝請求要素・決済ルール・結果分析キー
証跡として控えさせる T-code CJ20N・CJ03・VA03・MD04・CO03・MMBE・SE16N（PRPS/PLAF/AUFK/MSPR/COEP/MATDOC）・VL03N・VF03・CJI3・CJ31・FB03。 「症状／根因／証跡（T-code＋画面・表の行）」の 3 点で書かせます。
