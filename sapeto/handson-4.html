4-1 出荷伝票の登録（VL01N）

出荷タイプ   : LF
出荷ポイント : 自動決定（プラント 1000 / 得意先 1000）
出荷先       : 得意先 1000
納入日付範囲 : 今日 ± 30 日（受注の納期を含む範囲）
参照         : 受注 000000xxxx（または VA03 → 明細 → 「出荷」）
数量         : 1 PC（受注残）
  1. （做法 A）VA03 → 受注 → 明細 10 → 「明細」→「出荷」でその明細から出荷伝票を作る。
  2. （做法 B）VL01N → 出荷タイプ LF・出荷ポイント・出荷先 1000・納入日付範囲 → 「納入日程行の選択」で受注 0000… の納期行を选 → 数量 1。
  3. 確認：明細の 在庫区分 = プロジェクト在庫（Q）・WBS ZETO-1000.2・引当数量 1。← ここが「受注在庫 E」ではなく「Q」であることが ETO の証拠。
  4. 「保存」→ 出荷伝票番号を記録（状態 A）。
出荷できない/引当できないとき 引当 0 → プロジェクト在庫が無い（练习③ の 101 が Q に入っていない）。
そもそも納期行が出ない → 受注明細の状態（完了）、納入日付範囲、明細の WBS。
Cloud で PGI が通らない既知事象 → SAP KBA 3623492（戦略グループ E2・6GD の活性状況を確認）。

4-2 ピッキングと出庫確認（VL02N）

  1. VL02N → 出荷伝票 → 明細の「ピッキング数量」に 1 を入力 → Enter（引当済/完全引当）。
  2. 明細で 在庫区分 Q・WBS を再確認 → 「保存」（状態 B）。
  3. メニュー「出荷伝票」→「出庫確認（PGI）」→ 転記。記録：物料伝票番号・会計伝票番号。
  4. 確認：MMBE → 品目 ZETO-FG01 のプロジェクト在庫 Q が 0 になる（納品された）。
  5. 確認：SE16N: MATDOC に移動タイプ 601・特別在庫 Q・WBS 付きの明細。
  6. 確認：FB03 で会計伝票（在庫/売上原価側の動き。評価付プロジェクト在庫なら金額も動く）。
取り消したい場合出庫確認の取消は VL09。請求まで作ってしまったら先に VF11 で請求を取消（逆順厳守）。

4-3 請求（VF01：請求計画/出来高）

請求タイプ   : F2
参照         : 出荷伝票 008000xxxx（出荷ベース）または 請求計画の日付（分割請求）
請求金額     : 出荷ベースなら 5,000,000 JPY（1 式）
              請求計画なら該当行（例：契約時 30% = 1,500,000 JPY）
※ 請求計画の日付に無い請求はエラーになる（KBA 2763512）
  1. VF01 → 請求タイプ F2 → 出荷伝票番号（または納入日付範囲）→ Enter → 請求対象を確認 → 「保存」→ 請求伝票番号を記録。
  2. VF03 → 請求伝票 → 「条件」タブで金額、請求計画のどの行で請求したかを確認。
  3. 会計伝票（VF03 の会計伝票ボタン / FB03）で「売掛金 / 売上」を確認。
  4. （分割請求を練習する場合）VF01 を請求計画の日付順に 2 回実行し、1 回目は 30%、2 回目は 70% になることを確認する。
出来高請求（マイルストーン）を使う場合 マイルストーンをネットワーク活動/WBS に登録し、請求計画タイプ（出来高）と紐付けます。マイルストーン達成（CN25 など）→ 請求可能になる流れを実機で確認してください（练习⑤ の発展）。

4-4 WBS に売上と原価が集まったか（CJI3）——ETO の「答え合わせ」

  1. CJI3（実績原価/収益）→ プロジェクト ZETO-1000 / 対象期間（今日〜+180 日）→ 実行。
  2. 对照下表：
WBS期待される表示意味
.1 設計・調達（請求要素）収益（請求額）が出ている請求が WBS に帰属した証拠。ここが空なら請求要素が正しくない
.2 製造（勘定設定要素）原価（材料費・労務費・外注費）が出ている指図・発注の勘定設定が WBS に乗っている証拠
  1. （ならし）「決済前」の段階では、指図の原価がまだ完全に WBS へ確定していないことがあります。練習⑤ の CJ88（決済）実行後に、もう一度 CJI3 を見て変化を確認してください。これが ETO の「月末処理の意味」です。
  2. CJ31（予算）→ 使用額（実績＋コミット）が 予算内か、可用性管理の警告が出ていないかを確認。
判断口诀 「収益は WBS .1、原価は WBS .2」——この 2 行が出れば、SD・PS・CO 的链路全都通了。 出ない場合は、収益＝請求要素（.1 のフラグと受注明細の WBS）、原価＝勘定設定（指図/発注の WBS）を切り分ける。

4-5 伝票フローで全リンクを確認（VA03 / VBFA）

  1. VA03 → 受注 → メニュー「環境」→「伝票フロー」。
    表示例：受注 → 製造指図 → 入庫（物料伝票）→ 出荷 → 出庫確認（物料伝票）→ 請求
  2. SE16N: VBFA で受注番号を入力し、後続伝票のつながりを表でも確認。
  3. CJ20N/CJ03 でプロジェクトを開き、WBS に「受注」「指図」「在庫」「請求」がぶら下がっているかをプロジェクトのビュー（オブジェクト概要・実績/決済）で確認する。

验收（完成基准）

✓ 练习④验收清单
  • VL01N で受注から出荷伝票を作成し、在庫区分が Q・WBS 付きであることを確認した。
  • VL02N でピッキング 1 を入力し、出庫確認（601）を実行して プロジェクト在庫 Q が 0 になった。
  • VF01 で請求を作成し（出荷ベースまたは請求計画）、VF03 で金額と条件を確認した。
  • FB03 で出庫・請求の会計伝票の借貸方向を説明できる。
  • CJI3 で WBS .1 に収益・.2 に原価が出ていることを確認した。
  • VA03 の伝票フローで 受注→指図→入庫→出荷→出庫確認→請求 が全部つながっている。
発展課題 ① 分割請求：請求計画の 30%（契約時）と 70%（完成時）を別々に請求し、CJI3 の収益が 2 回に分けて立つことを確認。
② 出来高請求：ネットワーク活動にマイルストーンを付け、達成→請求の流れを試す。
③ 部分納入：受注数量を 2 式に変更（VA02）し、1 式だけ先に納入・請求する（残りのプロジェクト在庫と WBS の見え方を確認）。
