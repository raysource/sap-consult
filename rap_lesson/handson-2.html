STEP 2-1 创建根视图 ZR_ZPOHEADER（ADT）

  1. 右键包 Z_WBS_DEV → New → Other ABAP Repository Object → Core Data Services → Data Definition。
  2. 名称 ZR_ZPOHEADER；模板选「Define Root View Entity」。
  3. 粘贴下列 DDL（其中 po_num → PoNum 等为字段改名，便于 Fiori/ABAP 用驼峰名）。
cds · ZR_ZPOHEADER（根视图，含 Composition 与 Association）
@EndUserText.label: '采购订单头 BO Root View'
@AccessControl.authorizationCheck: #NOT_REQUIRED
@Metadata.allowExtensions: true
@AbapCatalog.viewEnhancementCategory: [#NONE]
define root view entity ZR_ZPOHEADER
  as select from z_po_hdr
  composition [0..*] of ZR_ZPOITEM as _Items
  association [0..1] to ZR_VENDOR_TXT as _Vendor
    on $projection.VendorCode = _Vendor.VendorCode
{
  key po_num       as PoNum,
      po_date      as PoDate,
      vendor_code  as VendorCode,
      status       as Status,
      created_by   as CreatedBy,
      zz_memo      as ZzMemo,

      /* 关联：供应商主数据（只读），供 UI/服务导航 */
      _Vendor
}
两个小坑（WBS 实训常见） ① 若报「未知实体 ZR_VENDOR_TXT」→ 先建下一节的供应商视图，再回来激活。② Root View 与普通 View 不同：根上才能挂 Composition；只有 define root view entity 才可以被 BDEF 作为根引用。

STEP 2-2 创建明细视图 ZR_ZPOITEM

  1. 同上建 Data Definition，模板选「Define View Entity」（非 root）。名称 ZR_ZPOITEM。
  2. 粘贴代码。key = po_num + item_num。
cds · ZR_ZPOITEM（明细视图）
@EndUserText.label: '采购订单明细 BO View'
@AccessControl.authorizationCheck: #NOT_REQUIRED
@Metadata.allowExtensions: true
@AbapCatalog.viewEnhancementCategory: [#NONE]
define view entity ZR_ZPOITEM
  as select from z_po_itm
{
  key po_num     as PoNum,
  key item_num   as ItemNum,
      matnr      as Matnr,
      qty        as Qty,
      unit       as Unit,
      net_price  as NetPrice,
      currency   as Currency
}

STEP 2-3 供应商主数据视图 ZR_VENDOR_TXT（VH 用）

cds · ZR_VENDOR_TXT（简单主数据视图）
@EndUserText.label: '供应商主数据视图'
@AccessControl.authorizationCheck: #NOT_REQUIRED
@AbapCatalog.viewEnhancementCategory: [#NONE]
define view entity ZR_VENDOR_TXT
  as select from z_vendor_txt
{
  key vendor_code   as VendorCode,
      vendor_name   as VendorName,
      country       as Country
}

STEP 2-4 激活与数据预览

  1. 激活顺序：ZR_VENDOR_TXT → ZR_ZPOITEM → ZR_ZPOHEADER（Ctrl+F3 逐个激活）。
  2. 右键 ZR_ZPOHEADER → Open With → Data Preview。应显示 2 张订单头。
  3. 测试关联：在 Data Preview 的 SQL Console（或右键 → Open in SQL Console）执行：
    SELECT * FROM ZR_ZPOHEADER;；再 SELECT * FROM ZR_ZPOITEM WHERE PoNum = '4500000001'; 确认明细。
  4. 用 CDS 关联展开测试：建一个临时查询或直接看 _Vendor 是否可导航（Association 在预览中的体现）。若想看到“供应商名称”，最直观是后面在投影/列表注解里把 _Vendor.VendorName 暴露给 UI（手顺④）。
关于 VDM 三层（I/C/P）的取舍 WBS PH1 阶段要求练习 I（Interface）/ C（Consumption）/ P（Private）分层；本站直接以 RAP 的方式建 BO 视图（ZR_）并在后面加消费投影（ZC_），相当于“BO 即 I 层、ZC 即 C 层”，避免重复造 I 层包装视图。想完整练习 VDM 的同学可回原 WBS PH1 3 层示例。

验收（完成基准）

✓ 手顺②验收清单
  1. ZR_ZPOHEADER / ZR_ZPOITEM / ZR_VENDOR_TXT 三个 CDS 均激活无错误；
  2. Data Preview 中 ZR_ZPOHEADER 显示全部订单头；
  3. ZR_ZPOITEM 可按 PoNum 过滤出明细（统合项目 STEP2 期望：关联正确、仕入先名称可显示或可导航）；
  4. 能口述：Composition 与 Association 的区别、本 BO 中谁是 root。
