STEP 3-1 生成 Behavior Definition（managed）

  1. Project Explorer 中右键 ZR_ZPOHEADER → New Behavior Definition。
  2. 默认实现类型选 Managed，勾选 Draft Enabled（弹窗里会出现）。名称默认与实体同名：ZR_ZPOHEADER。
  3. 点 Finish 后 ADT 生成骨架 BDEF（含 root + 子实体 + 草稿表提示）。粘贴/核对以下内容：
abap · BDEF ZR_ZPOHEADER（完整版：CRUD + draft + action + determination + validation）
managed implementation in class zbp_zr_zpoheader unique;
strict ( 2 );
with draft;

define behavior for ZR_ZPOHEADER alias ZpoHeader
persistent table z_po_hdr
lock master
authorization master ( instance )
early numbering
{
  create;
  update;
  delete;

  field ( readonly : update ) CreatedBy;   " 创建人：仅创建时由 Determination 填充，之后只读
  field ( readonly ) PoNum;                 " 主键：仅编号方法可填，客户端始终只读

  mapping for z_po_hdr corresponding
  {
    PoNum      = po_num;
    PoDate     = po_date;
    VendorCode = vendor_code;
    Status     = status;
    CreatedBy  = created_by;
    ZzMemo     = zz_memo;
  }

  /* ---- 默认值 ---- */
  determination setDefaultValues on modify { create; }

  /* ---- 校验 ---- */
  validation validateVendor on save { create; update; }

  /* ---- 动作：確定订单 ---- */
  action ConfirmOrder result [1] self;

  association _Items { create; with draft; }
}

define behavior for ZR_ZPOITEM alias ZpoItem
persistent table z_po_itm
{
  create;
  update;
  delete;

  field ( readonly ) PoNum;
  field ( mandatory ) Matnr, Qty, NetPrice;

  validation validateItemAmount on save { create; update; }

  mapping for z_po_itm corresponding
  {
    PoNum    = po_num;
    ItemNum  = item_num;
    Matnr    = matnr;
    Qty      = qty;
    Unit     = unit;
    NetPrice = net_price;
    Currency = currency;
  }
}
字段控制说明（能力测试必考）
  • field ( readonly ) X：create/update 都不能由客户端改（如系统管理字段）。
  • field ( readonly : update ) PoNum：创建时可提供、更新时只读。
  • field ( mandatory ) ...：客户端必须提供（缺了报错）。
  • 子实体 PoNum 只读：父键由关联/上级带入，UI 不让用户直接改。

STEP 3-2 关于 Draft 的处理（WBS 3.5）

  1. 在 BDEF 头部 strict ( 2 ); 之后加 with draft;（上方代码已含）。
  2. 激活时 ADT 会自动创建草稿表（命名形如 ZR_ZPOHEADER_D / 子表 ZR_ZPOITEM_D）。若提示需手工建，用 Quick Assist（Ctrl+1）→ Create draft table。
  3. Draft 激活后：Fiori/EML 中 Save = 存草稿，Activate 才写正式表；同时提供 Edit 锁、Discard、Resume。
  4. BDEF 中的 draft action（Activate/Edit/Resume/Discard）由 managed 框架自动提供，无需像 unmanaged 那样显式列出——但如需禁用可在行为定义中显式覆盖。
Draft + 编号的关系（WBS 3.7 延伸） Managed BO 若启用 draft，通常用 UUID（raw16, managed numbering） 或 早编号（early numbering） 保证“CREATE 一发生就有主键”（draft 行也需要键）。晚编号（late numbering）是给 unmanaged 的 SAVE 序列用的，不适合 draft。本站用 CHAR 主键 + 早编号 + 番号范围 ZNPO 教学。

STEP 3-3 生成 Behavior Implementation（BIL）

  1. BDEF 中把光标放到方法名上（如 determination setDefaultValues），按 Ctrl+1 → Add implementation（或 Add all missing methods）→ 生成类 zbp_zr_zpoheader。
  2. 会生成两类本地类：LHC（handler） 与 LSC（saver，draft 时出现）。我们只需填 LHC 方法。
  3. 逐一实现下面 4 个方法 + 编号方法。

① earlynumbering_create（编号：Z+10 位番号）

abap · 编号方法（FOR NUMBERING）
" 在 LHC_ZPOHEADER（handler 类）中实现
METHODS earlynumbering_create FOR NUMBERING
  IMPORTING entities FOR CREATE ZR_ZPOHEADER.

METHOD earlynumbering_create.
  DATA: lv_number TYPE n LENGTH 10,
        lv_po_num TYPE z_po_hdr-po_num.

  LOOP AT entities INTO DATA(ls_entity)
       WHERE %is_draft = if_abap_behv=>mk-on.
    " 从番号范围 ZNPO 取号（需先在 SNRO 建好，见 STEP 3-6）
    CALL FUNCTION 'NUMBER_GET_NEXT'
      EXPORTING
        nr_range_nr = '01'
        object      = 'ZNPO'
      IMPORTING
        number      = lv_number.
    CONCATENATE 'Z' lv_number INTO lv_po_num.

    APPEND VALUE #( %cid      = ls_entity-%cid
                    %key      = ls_entity-%key
                    %is_draft = ls_entity-%is_draft
                    PoNum     = lv_po_num )
           TO mapped-zr_zpoheader.
  ENDLOOP.
ENDMETHOD.

② determination setDefaultValues（默认值：日期 / 创建人）

abap · Determination（modify 时触发）
" 在 LHC_ZPOHEADER 中
METHODS setDefaultValues FOR DETERMINE ON MODIFY
  IMPORTING keys FOR ZR_ZPOHEADER.

METHOD setDefaultValues.
  READ ENTITIES OF zr_zpoheader IN LOCAL MODE
    ENTITY zr_zpoheader
    FIELDS ( po_num po_date vendor_code status created_by )
    WITH CORRESPONDING #( keys )
    RESULT DATA(lt_headers).

  " 用系统日期 / 当前用户补默认值
  DATA(lv_date) = cl_abap_context_info=>get_system_date( ).
  DATA(lv_user) = cl_abap_context_info=>get_user_abap_64( ).

  MODIFY ENTITIES OF zr_zpoheader IN LOCAL MODE
    ENTITY zr_zpoheader
    UPDATE FIELDS ( po_date created_by status )
    WITH VALUE #( FOR ls_hdr IN lt_headers (
        %tky      = ls_hdr-%tky
        po_date   = COND #( WHEN ls_hdr-po_date IS INITIAL
                            THEN lv_date ELSE ls_hdr-po_date )
        created_by = COND #( WHEN ls_hdr-created_by IS INITIAL
                             THEN lv_user ELSE ls_hdr-created_by )
        status    = COND #( WHEN ls_hdr-status IS INITIAL
                            THEN 'NEW' ELSE ls_hdr-status ) ) )
    REPORTED DATA(lt_rep)
    FAILED DATA(lt_fail).
ENDMETHOD.

③ validation validateVendor（校验：供应商必须存在）

abap · Validation（save 时触发）
" 在 LHC_ZPOHEADER 中
METHODS validateVendor FOR VALIDATE ON SAVE
  IMPORTING keys FOR ZR_ZPOHEADER.

METHOD validateVendor.
  READ ENTITIES OF zr_zpoheader IN LOCAL MODE
    ENTITY zr_zpoheader
    FIELDS ( vendor_code )
    WITH CORRESPONDING #( keys )
    RESULT DATA(lt_headers).

  DATA: lv_exists TYPE abap_bool.
  LOOP AT lt_headers INTO DATA(ls_hdr).
    CLEAR lv_exists.
    SELECT SINGLE @abap_true FROM z_vendor_txt
      WHERE vendor_code = @ls_hdr-vendor_code INTO @lv_exists.

    IF lv_exists <> abap_true.
      APPEND VALUE #( %tky = ls_hdr-%tky ) TO failed-zr_zpoheader.
      APPEND VALUE #( %tky = ls_hdr-%tky
                      %state_area = 'VALIDATE_VENDOR'
                      %msg = new_message_with_text(
                        severity = if_abap_behv_message=>severity-error
                        text     = |供应商 { ls_hdr-vendor_code } 不存在| ) )
             TO reported-zr_zpoheader.
    ENDIF.
  ENDLOOP.
ENDMETHOD.

④ action ConfirmOrder（確定订单 → CONFIRMED）

abap · Action（实例动作）
" 在 LHC_ZPOHEADER 中
METHODS confirmorder FOR MODIFY
  IMPORTING keys FOR ACTION zr_zpoheader~confirmorder
            RESULT result.

METHOD confirmorder.
  " 只允许状态=NEW 的订单被确定
  READ ENTITIES OF zr_zpoheader IN LOCAL MODE
    ENTITY zr_zpoheader
    FIELDS ( status )
    WITH CORRESPONDING #( keys )
    RESULT DATA(lt_headers).

  DATA: lt_failed  TYPE TABLE FOR FAILED   zr_zpoheader,
        lt_reported TYPE TABLE FOR REPORTED zr_zpoheader.

  LOOP AT lt_headers INTO DATA(ls_hdr)
       WHERE status <> 'NEW'.
    APPEND VALUE #( %tky = ls_hdr-%tky ) TO lt_failed.
    APPEND VALUE #( %tky = ls_hdr-%tky
                    %state_area = 'CONFIRM_ORDER'
                    %msg = new_message_with_text(
                      severity = if_abap_behv_message=>severity-error
                      text     = |只有 NEW 状态的订单可以确定| ) )
           TO lt_reported.
  ENDLOOP.

  " 更新状态
  MODIFY ENTITIES OF zr_zpoheader IN LOCAL MODE
    ENTITY zr_zpoheader
    UPDATE FIELDS ( status )
    WITH VALUE #( FOR ls IN lt_headers WHERE ( status = 'NEW' )
                  ( %tky = ls-%tky status = 'CONFIRMED' ) )
    FAILED DATA(lt_mod_fail)
    REPORTED DATA(lt_mod_rep).

  " 返回更新后的实体（result [1] self）
  READ ENTITIES OF zr_zpoheader IN LOCAL MODE
    ENTITY zr_zpoheader
    ALL FIELDS WITH CORRESPONDING #( keys )
    RESULT DATA(lt_final).

  result = VALUE #( FOR ls_final IN lt_final
                    ( %tky   = ls_final-%tky
                      %param = ls_final ) ).
ENDMETHOD.
Action 的 result [1] self 是什么？ 声明 action ConfirmOrder result [1] self 表示动作执行后把更新后的自身实体返回给调用方（UI 直接刷新该行，不用重新读取）。WBS 3.6 备注「Action後のRefreshはResponse Entityで制御」指的就是它。

STEP 3-4 子实体校验：validateItemAmount（金额 > 0）

abap · 子实体校验（WBS 3.3 的“金额>0”例子）
" 在 LHC_ZPOITEM（子实体的 handler）中
METHODS validateitemamount FOR VALIDATE ON SAVE
  IMPORTING keys FOR ZR_ZPOITEM.

METHOD validateitemamount.
  READ ENTITIES OF zr_zpoheader IN LOCAL MODE
    ENTITY zr_zpoitem
    FIELDS ( net_price qty )
    WITH CORRESPONDING #( keys )
    RESULT DATA(lt_items).

  LOOP AT lt_items INTO DATA(ls_item)
       WHERE net_price <= 0 OR qty <= 0.
    APPEND VALUE #( %tky = ls_item-%tky ) TO failed-zr_zpoitem.
    APPEND VALUE #( %tky = ls_item-%tky
                    %state_area = 'VALIDATE_ITEM_AMOUNT'
                    %msg = new_message_with_text(
                      severity = if_abap_behv_message=>severity-error
                      text     = |行项目金额与数量必须大于 0| ) )
           TO reported-zr_zpoitem.
  ENDLOOP.
ENDMETHOD.

STEP 3-5 激活与快速验证

  1. 保存并激活 BDEF、BIL、CDS（Ctrl+F3 逐个）。激活日志 0 错误。
  2. 若有 draft table 相关的 Quick Assist 提示，按 Ctrl+1 生成。
  3. 用 EML 试跑：新建一个程序（如 ZRAP_EML_DEMO）执行创建→确定→查询，代码见 项目代码页。
  4. 也可以在 ADT 中直接 F8（RAP Preview 需先做手顺④的服务绑定；在此之前用 EML 验证最稳）。

STEP 3-6 番号范围 ZNPO（SNRO）

  1. SE11 建域/数据元素前先确保 po_num 长度 ≥ 11（Z+10 位）。若表已建为 CHAR 10，可把 ZNPO 长度设 10（纯数字）并在编号方法里只取 lv_number（去掉 Z 前缀），或改表字段为 CHAR 12。
  2. 事务码 SNRO → 新建：对象 ZNPO，编号长度 10，间隔 01：0000000001〜9999999999，保存。
  3. （可选）WBS 要求“Z+10桁”：把表字段 po_num 设为 CHAR 11，然后在 CONCATENATE 'Z' lv_number ... 时直接用 11 位。
番号范围与 draft 的小陷阱 号码在 create（草稿保存）时就被消耗；若用户放弃草稿，号码会跳号（gap）。这是 early numbering 的正常行为，生产上若需“无跳号请用 late numbering（仅 unmanaged）”。

STEP 3-7 权限（Authorization，WBS 3.8）

  1. BDEF 中已写 authorization master ( instance )，意味着实例级权限检查。
  2. 实现：在 LHC 中写 get_instance_authorizations（FOR INSTANCE AUTHORIZATION）+ 在 save 校验里用 cl_abap_authorization 或 AUTHORITY-CHECK 检查授权对象（如自建 ZPURCHASE_AUTH：activity + 购买组织）。
  3. 授权对象在 SU21 建，角色 PFCG 分配；开发期可先用 SAP_ALL 或 DCL #NOT_REQUIRED 跳过（本站示例默认 #NOT_REQUIRED，DCL 示例见 代码页）。
本页范围说明 为了控制篇幅，本页把 WBS 3.2〜3.8 的“可运行核心”讲完；实例权限 get_instance_authorizations 的完整代码见项目代码页。Draft 深度讲解（draft action、discard/resume 行为）在 quiz 有对应考题。

验收（完成基准，对应 WBS 3.x 的完了基準）

✓ 手顺③验收清单
  1. BDEF/BIL 激活成功，managed + draft 生效（创建草稿表无报错）；
  2. EML 创建订单头 → 自动带出 po_date / created_by / status=NEW（determination 生效）；
  3. 输入不存在的供应商 → 保存时报错（validation 生效）；
  4. 明细金额 ≤0 → 报错「金额必须大于 0」；
  5. 对 NEW 订单执行 ConfirmOrder → status 变 CONFIRMED 且返回实体；
  6. 对已 CONFIRMED 订单执行 → 报错（状态机校验）；
  7. 创建后 po_num 自动带出编号（编号方法/番号范围生效）；
  8. （若启用实例权限）无权限用户 → Forbidden 错误（WBS 3.8）。
