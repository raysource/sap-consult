STEP 4-1 创建投影视图 ZC_ZPOHEADER

  1. 右键包 → New → Data Definition → 模板选「Define Projection View」，名称 ZC_ZPOHEADER，来源实体 ZR_ZPOHEADER。
  2. 投影视图 = 只读的“裁剪层”：只能投影 BO 视图已有字段/关联，不能新算字段。UI 注解写在这里（或 Metadata Extension）。
cds · ZC_ZPOHEADER（消费投影 + 基础 UI 注解）
@EndUserText.label: '采购订单消费投影'
@AccessControl.authorizationCheck: #NOT_REQUIRED
@Metadata.ignorePropagatedAnnotations: true
@UI: {
  headerInfo: {
    typeName: '采购订单',
    typeNamePlural: '采购订单',
    title: { type: #FOR_KEY, value: 'PoNum' }
  },
  presentationVariant: [ { sortOrder: [ { by: 'PoDate', direction: #DESC } ] } ]
}
@Search.searchable: true
define root view entity ZC_ZPOHEADER
  provider contract transactional_query
  as projection on ZR_ZPOHEADER
{
  @UI: {
    lineItem:       [ { position: 10, label: '订单号' } ],
    selectionField: [ { position: 10 } ],
    identification: [ { position: 10 } ]
  }
  @Search.defaultSearchElement: true
  key PoNum,

  @UI: {
    lineItem:       [ { position: 20, label: '采购日期' } ],
    selectionField: [ { position: 20 } ],
    identification: [ { position: 20 } ]
  }
  PoDate,

  @UI: {
    lineItem:       [ { position: 30, label: '供应商' } ],
    selectionField: [ { position: 30 } ],
    identification: [ { position: 30 } ]
  }
  @Consumption.valueHelpDefinition: [ { entity: { name: 'ZR_VENDOR_TXT', element: 'VendorCode' } } ]
  VendorCode,

  @UI: {
    lineItem:       [ { position: 40, label: '状态' } ],
    selectionField: [ { position: 40 } ],
    identification: [ { position: 40 } ]
  }
  Status,

  @UI: { lineItem: [ { position: 50, label: '备注' } ] }
  ZzMemo,

  @UI.hidden: true
  CreatedBy
}
为什么 headerInfo 不显示供应商名称？ 投影视图（projection on ...）只能投影下层 BO 视图已有的字段；VendorName 在 ZR_ZPOHEADER 中并不存在（只有 VendorCode + _Vendor 关联）。要在标题/列表显示名称，需在 BO 层把名称做成字段或用关联展开（Fiori 课程范围）。本站用 供应商 F4 值帮助 让用户看到名称即可。

STEP 4-2 明细投影视图 ZC_ZPOITEM

cds · ZC_ZPOITEM（明细消费投影）
@EndUserText.label: '采购订单明细消费投影'
@AccessControl.authorizationCheck: #NOT_REQUIRED
@Metadata.ignorePropagatedAnnotations: true
@UI: {
  headerInfo: { typeName: '采购订单明细', typeNamePlural: '采购订单明细' }
}
define view entity ZC_ZPOITEM
  provider contract transactional_query
  as projection on ZR_ZPOITEM
{
  @UI: { lineItem: [ { position: 10 } ], identification: [ { position: 10 } ] }
  key ItemNum,

  @UI: { lineItem: [ { position: 20, label: '物料' } ], identification: [ { position: 20 } ] }
  Matnr,

  @UI: { lineItem: [ { position: 30, label: '数量' } ], identification: [ { position: 30 } ] }
  Qty,

  @UI: { lineItem: [ { position: 40, label: '单位' } ], identification: [ { position: 40 } ] }
  Unit,

  @UI: { lineItem: [ { position: 50, label: '单价' } ], identification: [ { position: 50 } ] }
  NetPrice,

  @UI: { lineItem: [ { position: 60, label: '币种' } ], identification: [ { position: 60 } ] }
  Currency,

  @UI.hidden: true
  PoNum
}
供应商 F4 值帮助的目标实体 ZC_ZPOHEADER 的 VendorCode 注解指向 ZR_VENDOR_TXT（值帮助视图）。要让 Fiori 能调它，需把它也放进服务定义（下一步的 expose ZR_VENDOR_TXT as VendorTxt）。值帮助视图本身只读即可，不需要投影包装。

STEP 4-3 Service Definition 与 Binding

  1. 右键包 → New → Other ABAP Repository Object → Cloud/Service 相关 → Service Definition：名称 ZSD_ZPURCHASEORDER，暴露上面三个投影。
  2. 再右键 → New → Service Binding：名称 ZUI_ZPURCHASEORDER_O4，绑定类型 OData V4 (UI)，引用 ZSD_ZPURCHASEORDER。
  3. 激活后，双击 Binding 里的实体 → 点「预览 / Preview」打开 Fiori Elements 列表页。
cds · Service Definition ZSD_ZPURCHASEORDER
@EndUserText.label: '采购订单 RAP 服务'
define service ZSD_ZPURCHASEORDER {
  expose ZC_ZPOHEADER as ZpoHeader;
  expose ZC_ZPOITEM   as ZpoItem;
  expose ZR_VENDOR_TXT as VendorTxt;
}
为什么服务里要有 VendorTxt？ VendorCode 字段的值帮助（valueHelpDefinition）指向 ZR_VENDOR_TXT，OData 服务需要能访问它（F4 下拉从同一服务取数）。ZpoHeader / ZpoItem 是可读写 BO 投影；VendorTxt 是只读值帮助实体，三者同属一个服务。

STEP 4-4 在 Preview 中验收（统合项目 STEP6 期望动作）

  1. 列表页（List Report）出现：订单号 / 采购日期 / 供应商 / 状态 等列，顶部可按订单号/状态筛选；
  2. 点「Create」→ 输入供应商、日期 → 明细表加 2 行（物料/数量/单价）→ Save（Draft）→ Activate；
  3. 点某行 → Object Page 显示抬头 + 明细 Facet（由 ZC_ZPOITEM 的 lineItem 注解自动成表）；
  4. 对状态 NEW 的行执行 「ConfirmOrder」按钮（若想按钮出现在列表，需在注解里加 @UI.lineItem: [{ type: #FOR_ACTION, dataAction: 'ConfirmOrder', position: 60 }] 或把它加为 identification 区域按钮）；
  5. 保存后返回列表 → 状态变为 CONFIRMED；
  6. 再对 CONFIRMED 行执行 ConfirmOrder → 报错（后台校验拦截）。
按钮显示注解（WBS 4.4 Custom Column / Action 列） 要让 Action 出现在列表行内，需在投影字段（或 entity 级注解）里加 dataAction 引用；示例：
@UI.lineItem: [ { type: #FOR_ACTION, dataAction: 'ConfirmOrder', position: 99, label: '确定' } ]
（本站在代码页给出完整版；UI 深度定制属 Fiori 课程范围。）

STEP 4-5 检查 OData V4（可选）

  1. 在 Service Binding 里复制服务 URL，浏览器打开 …/sap/opu/odata4/sap/zui_zpurchaseorder_o4/…/$metadata，应看到 ZpoHeader / ZpoItem 实体与 ConfirmOrder 动作。
  2. 用 GW_CLIENT（/IWFND/GW_CLIENT）或 Postman 测试 GET / POST / PATCH 与 $expand。

验收（完成基准）

✓ 手顺④验收清单（= 统合项目 STEP5/6 + STEP10 前 4 步）
  1. Service Binding 激活，Preview 能打开 Fiori Elements 列表；
  2. 列表显示 ≥5 列、可按订单号/状态搜索过滤；
  3. 新建订单（抬头 + 2 行明细）→ Draft → Activate 成功；
  4. 对象页（Object Page）显示抬头 + 明细；
  5. ConfirmOrder 动作可用、状态机正确；
  6. 供应商名（VendorName）在抬头/标题中可见（若保留了关联投影）。
