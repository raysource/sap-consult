RAP 概念与架构

2. 什么是 Business Object（BO）

在 RAP 中，BO 是“数据模型 + 行为”的打包单元：

  • Root Entity：一棵树的根（如采购订单头）。可 create/update/delete。
  • Child Entity：通过 Composition 挂在根下（如订单明细），随根同生共死（级联操作）。
  • Association：与其他实体的关联（如订单头 → 供应商主数据），只读导航或跨 BO 引用。
Composition vs Association（能力测试必考） Composition = 包含关系（整体-部分，子不能脱离父独立存在，父删除子级联删除）；Association = 引用关系（两个独立对象互相引用，可 to-one / to-many）。WBS 1.2 例子：Z_PO 头 → 明细用 Composition，头 → 供应商用 Association。

4. Draft（草稿）机制

  • BDEF 中启用 draft 后，保存 = 存草稿，点击 Activate 才写入正式表；框架自动创建草稿表（ZR_ZPOHEADER_D 等）。
  • Draft 提供：编辑锁（Edit → 独占锁）、多会话草稿、draft action（Edit/Activate/Discard/Resume）。
  • WBS 3.5：draft enabled 一行即可；草稿表由 ADT 自动生成（ZDRAFT…或实体名_D）。
为什么用 Draft？ Fiori 端用户期望“输入到一半可以离开、下次继续”，并且校验失败不丢数据。RAP 的 draft 与 OData V4 的 draft 语义自动打通，UI 无需额外编码。

  CREATE FIELDS ( po_num po_date vendor_code status )

                  net_price = '100.00' currency = 'JPY' ) )

  FAILED DATA(failed)
