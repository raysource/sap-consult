讲师版 —— 指導案・解答・採点基準

この頁は講師用です（受講者は読まないでください） 受講者に渡す前に 学员版（記入用） と 能力测试（28 題） を印刷してください。本頁には発展課題の解答例・症例判別の答え・必出 Q&A が載っています。

1. 全体設計（この站で到達させたい 2 点）

動画（SAP Education Unit 14: Sales Order Processing）の到達目標は 2 つだけです。 本站はその 2 点を、自分の環境で再現できる形に分解しました。

動画の目標本站での分解到達判定（受講者の言動）
① 伝票データの出所を言える（material master・customer master・Customizing）概念 1〜6 節 ＋ 练习①の「値の出所表」＋ 练习⑤の故障切り分け 4 画面受注の任意の項目について「値・出所テーブル・決まった理由」を 3 つセットで言える
② ツールとヘルプを使える（tools and help）练习⑤ の SU3／F1／与力分析／VA05／V.02／SE16N初見の異常に対して、自力で 3 つ以上の画面を開いて切り分けを進められる

3. 板書用の図（そのまま写す）

黒板／ホワイトボードに書く図は 2 枚だけに絞ります。これ以上書くと受講者が写しきれません。

板書 1：受注伝票の決定链

受注タイプ OR ─┐
品目カテゴリグループ ─┼→ 明細カテゴリ TAN ─┬→（与力関連）→ 価格決定手順 → 条件 PR00 → Net value
品目使用目的 ─┘                          └→ 納入日程行カテゴリ → 所要量タイプ → 在庫確認(ATP)

得意先 1000 → 販売エリア 1000/10/00 → パートナー SP/SH/BP/PY ─┬→ 支払条件 ZB01（Payer）
                                                          └→ インコタームズ FOB

出荷プラント ← ① 客先品目情報(VD51) ＞ ② 得意先マスタ出荷先(XD02) ＞ ③ 品目マスタ販売組織1(MM02)
             └→ 出荷ポイント → 出荷タイプ（VL01N）

板書 2：データの出所 4 分類（異常時の探索順）

① 主データ（得意先/品目/条件）  → XD03 / MM03 / VK13
② 既存伝票（先行受注・参照コピー） → VA03 / 伝票フロー
③ Customizing（伝票タイプ・決定テーブル） → VOV8 / VOV4 / VOV5 / OVA2
④ ハードコード（ABAP/拡張）        → ①②③が正しいときだけ疑う

≪切り分けの順序≫ ①受注を見る → ②主データを見る → ③設定を見る → ④拡張を疑う

4. 発展課題の解答例（练习⑤）

課題解答の要点よくある誤答
発展① 伝票タイプにブロックを仕込むVOV8 の ZOR1 に納入ブロックを設定 → そのタイプで作る受注は最初からブロック付き。設定を戻しても既存受注はブロックのまま（伝票に焼き付く）「設定を戻せば既存受注も解除される」→ ✗（新規受注のみに効く）
発展② 出荷プラントの優先順位MM02（販売組織1）→ XD02（出荷先）→ VD51（客先品目情報）の順に値を入れ、後から入れた上位が勝つ。上位を空にすると下位に戻る「品目マスタを直せば必ず反映される」→ ✗（上位があると負ける）
発展③ Sales Summary のビュー自作① でビュー Z01 を定義 → ② で情報ブロックを 3〜5 個割当 → ③ で自分を Z01 に割当 → VC/2 の View に出る①だけ作って②を忘れる → ビューは出るが中身が空
発展④ 不完全性の必須項目追加OVA2 で手順に項目追加 → VUA2 で警告にすると保存はでき、V.02 に載る。項目を埋めると一覧から消える「エラーにしないと意味がない」→ ✗（業務では警告＋一覧管理が一般的）

5. 症例判別（8 問）—— 症状だけを見せて答えさせる

受講者に症状だけを読み上げ、① 根因 ② 証拠の取り方 ③ 処置 を答えさせます。答えを先に言わないこと。

#症状答え（根因／証拠／処置）
1受注の Net value が 0.00 EUR条件レコードが無い or 有効期間外 or 与力日付ずれ → VA03 条件画面＋VK13 → VK11 で正しいキー・期間で登録
2明細の出荷プラントが空3 か所すべてに値が無い → VD53／XD03／MM03 → どこに入れるか決めて保守
3品目マスタを直したのに出荷プラントが変わらない上位（客先品目情報 or 得意先マスタ）に値がある → KNMT／KNVV／VBAP-WERKS を並べる → 上位を修正
4明細カテゴリが TAN にならない決定テーブル（VOV4）の 4 キー不一致／品目カテゴリグループ違い → MM03（販売組織2）＋VOV4 → 行を整備
5保存時に「PO Number を入力してください」不完全性手順の必須項目（動画の環境で発生）→ OVA2／V.02 → 埋める or 警告に変更
6受注は保存できたが出荷できない納入／請求／与信ブロックのどれか → VA03 ヘッダ 3 ブロック＋与信ステータス → 由来を特定して解除
7得意先を変えたのに価格が古い再決定されない項目 or 手動条件 or 後続伝票ありで無変更 → 条件画面（手動表示）＋伝票フロー → 入れ直す／後続伝票を処理
8VC/2 に情報ビューが出ない「Report Views for a User」に未割当 or ビュー未定義 → VC/2 の View＋SPRO → C5 の ①③ を整備

6. 必出 Q&A（12 問）

質問答え
伝票データの源泉 4 つは？主データ／既存伝票／Customizing／ハードコード（ABAP）
販売エリアは何から導出される？得意先マスタ（販売エリアビュー）。複数あれば選択ダイアログ「Sales area for customer」
出荷プラントの優先順位は？① 客先品目情報（VD51）→ ② 得意先マスタの出荷先（XD02 出荷タブ）→ ③ 品目マスタ 販売組織1（MM02）
明細カテゴリの 4 つのキーは？販売伝票タイプ × 品目カテゴリグループ × 品目使用目的 × 高レベル明細カテゴリ
TAN は在庫を持つ？持たない（所要量タイプが空＝所要量を作らない）。受注在庫 E とは別（戦略グループ・所要量クラスの設計）
支払条件と与信を決めるパートナーは？Payer。納入先住所と出荷プラントは Ship-to 側
得意先変更で再決定されるものは？得意先マスタ・客先品目情報・テキスト・無償品・与力価格・出力・出荷プラントと出荷ポイント
得意先変更で変わらないものは？販売エリア・販売事務所／販売グループ・可用性／製品割当・バッチ
後続伝票がある受注で得意先を変えると？何も変更されない（ステータス関連の先行／後続伝票がある場合の仕様）
ブロックの 3 階層は？ヘッダ（納入／請求）・明細（請求）・納入日程行（納入）。由来は ①手動 ②Customizing ③チェック（与信）
Sales Summary の画面はどこで決まる？SIS の Customizing 4 画面（Report Views／Views for an Evaluation／Report Views for a User／Last Documents for a Customer）
不完全性の設定と一覧は？定義 OVA2（挙動 VUA2、適用 VUP2／VUE2）、一覧 V.02／V.00

7. 採点基準と合否

項目配点合格ライン見方
能力测试（28 題）10075%（21 問）以上概念 10／設定 7／実務 6／故障 5 の配分。故障問題を落とした場合は該当節を再実習
练习①〜④ の验收清单必須全項目 ✓特に「値の出所表」と「変更前後比較表」は実物の画面で確認させる
练习⑤ の故障対照表必須2 件以上の再現記録「症状 → 根因 → 証拠 → 処置 → 再発防止」が書けているか。証拠が画面名・T-code で具体的か
発展課題 4 本加点2 本以上①〜④ のうち 2 本できれば実務即応レベル
指導上の禁止事項 ① 標準の OR／TAN を直接書き換えさせない（Z コピーで練習させる）。
② 後続伝票がある受注で変更練習をさせない（意図しない差異や実データ汚染の原因）。
③ PGI を実施させたら必ず記録させる（取消には専用処理が必要）。
④ 故障問題で答えを先に言わない（症状 → 自力で証拠、の順を守らせる）。
